# 工程方法

## 任务与完成定义

先读取 [文档导航](README.md)、[架构](architecture.md) 和 [项目状态](project-status.md)，在队列中选择一个任务，保持唯一进行中项。确定可观察验收，再按契约、实现、失败/取消/回滚验证、记录的顺序完成最小纵向切片。

实现、自动测试、原生人工验证和正式发行资格分别记录。失败应记录原因及修复后的实际复测；模拟测试不得冒充真实内核或系统写入验证。构建/测试入口见 [开发指南](development/build.md)。

## UI 先审视、先设计、后修改

1. 从完整用户任务出发，核对页面职责、操作频率、信息层级和预期；遵守 [当前交互契约](ui-interactions.md)，不只美化单个控件。
2. 修改代码前，将采用方案、布局/主次动作、浏览与写入边界、状态转换及验收点记录到所属设计章节。小改动可简短记录，大改动应说明完整操作链。
3. 设计同时覆盖空态、加载、失败、取消、草稿/候选/运行版、鼠标/键盘、窄窗/DPI/主题，以及隐藏和轻量重建。
4. 按设计实现并复核；冲突先修订设计。只有实际后果需要决策时才增加确认。测试/截图不能替代事前设计，也不能将计划自动标为通过。

## 目录与模块

| 目录 | 归属 |
|---|---|
| src/app | Controller、状态、串行命令及业务协调 |
| src/core | 内核 API、进程、服务会话与就绪 |
| src/profile | YAML、下载、Provider、不可变版本与配置合成 |
| src/platform/windows | Windows 原生 API、权限、恢复及进程观测 |
| src/storage / src/diagnostics | 持久化、机密与有界日志 |
| src/ui | Widgets、按需主窗口、页面与托盘；只调用 Controller 命令 |
| resources / licenses | 运行资源、品牌与第三方许可署名 |
| docs | 当前契约、ADR、状态、验证与明确标注的归档 |
| scripts / tests | 构建验证工具与隔离测试 |
| build / dist / cores | 可丢弃构建缓存、发行暂存、固定内核；二进制不提交 |

用户数据不写回程序或源码目录。订阅路径使用随机 UUID，名称不参与路径；版本不可变，索引原子提交。原生函数不得绕过平台层进入 UI。

## 协作与 Git

并发协作前明确每个文件/模块的唯一写入者，接口变化先更新契约。集成者负责构建、测试和状态，不允许 UI 绕过 Controller 修补业务。委派必须有明确授权。

任务分支使用 feature/ 或 fix/ 前缀，提交采用简洁 Conventional Commit。提交包含相关契约与真实验证结果；构建输出、二进制、真实配置、订阅、令牌、日志和恢复记录不提交。

## 文档职责与优先级

原始规格作为需求基线保留；接受的偏差由编号 ADR 说明。当前架构/API/交互契约按职责维护实现，状态只记录进度，验证只记录实际结果。历史报告移入 archive 并显式标识，不作为当前缺口或验收结论。

每项事实有唯一归属；新增/移动文档必须同步导航和相对链接，执行文档与隐私检查。不得记录个人工作站路径、真实订阅、私人使用经过或会话附件标识。第三方许可署名及必要的公开项目 URL 保留。

ADR 按编号保留决策意图，后续决策可替代早期取舍，不抹除原意。当前文档重组规则见 [ADR 0041](adr/0041-public-documentation-baseline.md)。

## 资源与发行

Qt 动态链接，yaml-cpp 等依赖按锁定提交获取，编译器 ABI 不混用。品牌源为 `resources/mlash.svg`；generate-brand.py 派生 PNG/ICO/托盘资源，generate-service-icons.py 维护服务图标。派生资源入库，Python/Pillow 不进入运行包。

正式发行的证据和授权材料按 [发布门禁](release-readiness.md) 管理。默认测试不改系统代理；真实写入仅在受控 VM 显式启用，失败保留恢复意图。
