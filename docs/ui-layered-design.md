# U06 界面分层设计

2026-10-29 · 设计文档，未实施。本文按五个层次依次定义 Mlash 的界面：整体架构、原则、UI 分类、容器布局、Widget 详细设计。视觉与配色作为第六层在最后统一套用，前五层只定义结构与中性占位样式。决策意图见 [ADR 0045](adr/0045-ui-system-rebuild.md)，问题证据见 [U05 评审](ui-system-review.md)。

> 本文取代 U05 中「目标信息架构」与「实施阶段」两节的结构提案；U05 的问题清单与证据继续有效。

## 设计约束

用户明确的原则：

1. **架构从简**：能不分区就不分区，能合并就合并；但主要任务必须单页完成的，保持单页。
2. **分层推进**：严格按 1→5 顺序设计，视觉风格最后统一套用，避免容器假设与配色互相矛盾。
3. **允许推翻**：不局限于现有八页结构。
4. **三目标并重**：功能完整（对标 Clash Verge）、简洁直观（对标 Shadowrocket）、最终呈现极简。三者通过「默认界面 / 收纳入口 / 视觉克制」分工实现，详见 [P0 原则](#p0-三者兼得的分工)。

工程约束（不可推翻）：Controller 命令与持久化 schema 不变；候选/运行版本分离；写前恢复与串行化；默认测试不碰系统代理。

## 第 1 层：整体架构

### 判断标准

一个「页面」只承载一类任务，且该任务的主要动作能在一个屏幕内完成。满足则单页；不满足则拆。反过来，两个页面若共享同一对象与同一动作链，则合并。

### 现状评估

八页中，有三组存在真实的重叠：

| 组 | 重叠事实 | 结论 |
|---|---|---|
| 首页 / 节点 | 首页有节点快捷切换与策略组浏览，节点页是同一对象的主界面 | 首页的节点能力是**捷径**，不是独立任务；合并后由节点页承担 |
| 首页 / 网站测试 | 首页只提供进入入口与摘要 | 网站测试是独立任务且需要整屏卡片，保持单页 |
| 订阅 / 规则 | 规则按订阅保存，两者共享订阅选择上下文 | 任务不同（来源维护 vs 分流维护），保持分页但共享上下文条 |
| 连接 / 日志 | 都是观测，但读取边界与操作不同 | 任务不同，保持分页 |
| 设置 / 备份 | 备份是长流程任务，不是偏好 | 拆出为独立页面 |

### 采用的结构

**两级导航。** 侧栏保留四个分区；页面**不设标题**，分区页签是内容区顶部第一行，与内容左缘对齐。页面级动作放在该行右侧，与页签同排。

| 分区 | 页签（可寻址视图） | 数量 | 说明 |
|---|---|---|---|
| 首页 | 状态(0)、节点(2) | 2 | 保留原名「首页」；状态页只保留「当前成员 + 切换」一行 |
| 配置 | 订阅(1)、规则(3) | 2 | 共享订阅上下文条 |
| 数据 | 网站测试(7)、连接(4)、日志(5) | 3 | 保留原名「数据」，不更名 |
| 设置 | 常规(6a)、网络与内核(6b)、备份与工具(6c) | 3 | 三个分类**均为可寻址视图**，见下方路由模型 |

**计数口径统一**：8 个 `QStackedWidget` 视图（ID 0–7）+ 设置内 3 个分类视图（6a/6b/6c，共享 `pages_` 索引 6），共 **11 个可寻址叶子视图**。全文不再使用「九个页面」这类模糊计数。

### 路由模型

所有导航表面（侧栏、页签、托盘、启动页、设置搜索、`GuiHost`）从同一张表取值，禁止页号算术。

| 视图 | ID | 分区 | 页签顺序 | 显示名 | 可寻址 | 默认页 |
|---|---|---|---|---|---|---|
| 状态 | 0 | 首页 | 1 | 状态 | 是 | **是** |
| 订阅 | 1 | 配置 | 1 | 订阅 | 是 | 否 |
| 节点 | 2 | 首页 | 2 | 节点 | 是 | 否 |
| 规则 | 3 | 配置 | 2 | 规则 | 是 | 否 |
| 连接 | 4 | 数据 | 2 | 连接 | 是 | 否 |
| 日志 | 5 | 数据 | 3 | 日志 | 是 | 否 |
| 设置 | 6 | 设置 | — | 设置 | 是（含分类） | 否 |
| 设置 › 常规 | 6a | 设置 | 1 | 常规 | 是 | 否 |
| 设置 › 网络与内核 | 6b | 设置 | 2 | 网络与内核 | 是 | 否 |
| 设置 › 备份与工具 | 6c | 设置 | 3 | 备份与工具 | 是 | 否 |
| 网站测试 | 7 | 数据 | 1 | 网站测试 | 是 | 否 |

**路由键**：`viewId`（0–7）或 `viewId + category`（仅设置）。`startupPage` 与托盘跳转沿用整数 0–7，不迁移数据；设置分类另存会话内状态（不持久化），由搜索/托盘以 `6 + category` 复合键直达。

**扩展面**（这是相对 ADR「命令与 schema 不变」的偏差，需在 ADR 0046 记录）：

- `GuiHost::show()` 的 `page < 8` 硬编码改为「路由模型条目数」校验（`GuiHost.cpp:10`）。
- `TrayController` 的页号跳转改为路由键；设置分类要支持 `(6, category)`。
- 启动页下拉改用路由模型标签，数值 0–7 不变。
- 设置搜索 `pageRequested(int)` 扩展为路由键。

### 页签层级分离

一级分区页签与页内分段是**两种控件**，不得同形同位置：

| 控件 | 位置 | 行为 | 记忆 |
|---|---|---|---|
| 分区页签 | 内容区顶部第一行，与内容左缘对齐 | 切换视图，改变路由；响应 Ctrl+Tab | 分区最后视图（会话内） |
| 页内分段 | 工具条内 | 只切换当前页视图（活动/已结束、列表/文本），不改变路由 | 页内记忆 |

规则页与连接页现有的 `QTabWidget`/`QTabBar` 降为页内分段；同页不得出现第二行页签。

| — | — | 设置 › 网络与内核 | 索引 6 + 分类 1 |

### 全局表面

| 表面 | 职责 | 事实边界 | 持久化 |
|---|---|---|---|
| 侧栏状态条 | 一句状态结论（核心 / 代理归属 / TUN / 当前订阅） | 只做摘要，完整状态在状态页 | 否 |
| 全局状态栏 | 跨页操作结果 + 当前告警两段 | 不承载页面级错误 | 否 |
| 托盘 | 第二导航面，与路由模型同源 | 单击/菜单动作复用同一命令与确认 | 否 |
| 设置搜索 | 跨页定位 | 结果可直达 `(viewId, category)` | 否 |

## 第 2 层：UI/UX 原则

原则层不做视觉决定，只做**行为承诺**。每条原则都必须能在后续层级被验证。

### P0 三者兼得的分工

Mlash 同时追求三件事：Clash Verge 级的功能完整、Shadowrocket 级的简洁直观、极简的最终呈现。三者不可能靠「减少功能」或「简化界面」同时满足，因此用**分工**而不是折中：

| 目标 | 承担者 | 具体机制 |
|---|---|---|
| 功能完整 | 设置与工具窗口 | 29 项设置、TUN/DNS/备份/Provider 全部保留，不删功能 |
| 简洁直观 | 默认界面 | 默认只呈现当前状态、当前对象、下一步动作；其余进入抽屉、菜单、工具窗口 |
| 极简呈现 | 视觉层 | 不靠边框、不靠装饰、不靠颜色堆叠；一屏之内信息密度由层级决定 |

**推论一：功能不删，位置重排。** 任何「删掉某个功能」的提案都违反本条；正确做法是把低频功能移入抽屉/菜单/工具窗口，而非删除。
**推论二：默认界面只回答三件事。** 状态、当前对象、下一步。超出这三件事的信息默认折叠。
**推论三：复杂度必须可见地收纳。** 折叠不等于隐藏——被折叠的能力要有可发现的入口（「更多」「全部设置」「高级」），而不是只能靠记忆或搜索找到。

**可验证**：状态页首屏的可交互元素不超过 3 个（一个主动作 + 至多两个选择）；其余页面首屏控件数不超过 12 个；被折叠的功能都有可见入口；功能清单相对当前版本不减少。

**依据与例外**：3 个的硬指标来自 Shadowrocket 状态页的实测结构——大号状态区 + 主开关 + 两组分段，见 [U07 截图观察](ui-benchmark-research.md#三张实机截图的结构观察2026-10-29-用户提供)。这不是「尽量少」，而是「状态页只回答一个问题」的直接后果。设置页与订阅页不适用控件上限，以「单分类 / 单列表一屏」为准，但必须有常驻的搜索或分类入口。例外只此三处，其余页面不得援引。

### P1 状态先于导航

全局状态由侧栏状态条常驻展示（核心 / 代理归属 / TUN / 当前订阅）；每个页面首屏还必须展示该页的**当前对象或范围**（当前订阅、当前策略组、测试节点）。不得出现只有空表格与「前往首页」的页面。

**可验证**：840×560、100% 文字下逐页检查「状态条存在」与「当前对象可见」两项，任一缺失即不通过。

### P2 一个事实只有一个权威来源

每个事实只有一个权威来源；摘要与详情必须由同一来源派生，不得各自缓存或计算。每个事实在路由模型中登记「常驻位置」与「详情位置」各一个。

**可验证**：按下表逐项在代码中找唯一赋值点，并确认界面没有第二处独立计算。

| 事实 | 权威来源 | 常驻位置 | 详情位置 |
|---|---|---|---|
| 内核状态/版本 | `AppState.core`、`coreVersion` | 侧栏状态条 | 状态页状态块 |
| 系统代理归属 | `AppState.proxy` | 侧栏状态条 | 状态页状态块 |
| TUN 意图 | `Settings.tunEnabled` | 状态页开关 | 设置 › 网络与内核 |
| TUN 观测 | `AppState.tunObserved` | 侧栏状态条 | 状态页状态块 |
| 当前订阅 | `Settings.activeProfile` | 侧栏状态条 + 节点页上下文条 | 订阅页 |
| 当前成员 | `proxies[group].now` | 节点页上下文条 | 状态页 |

### P3 意图与观测分离

用户要求开某状态（意图）与系统实际生效（观测）必须分别表达。未知显示「—」并给出原因入口，不填 0、不沿用旧值、不回落为关闭。

**结构与文案**（三类状态统一）：

| 状态 | 意图控件 | 观测指示 | 文案 |
|---|---|---|---|
| 系统代理 | 开关（受 readOnly/busy 约束） | 状态点 + 归属 | 「已接管」/「外部管理」/「未启用」/「— 未确认」 |
| TUN | 开关（受权限前提约束） | 状态点 + 就绪 | 「已启用」/「启用中」/「未生效」/「— 未确认」 |
| 内核 | 启动/停止按钮 | 状态点 + 版本 | 「运行中 · vX」/「启动中」/「已停止」/「失败」 |

主窗口、状态页、托盘 tooltip 三处文案同源，由同一函数生成。

**可验证**：未安装 TUN 服务时，开关保持用户意图，观测显示「— 未确认」且不回落为关闭；托盘与主窗口对同一状态给出相同句子。

### P4 写操作明确、就近反馈

浏览、搜索、排序、预选不写；只有明确动作才提交。失败在对象附近显示并保留输入。

**明确动作的例外定义**（避免与即时提交矛盾）：

| 动作 | 是否写入 | 说明 |
|---|---|---|
| 偏好控件变化 | 是 | 偏好类设置变化即提交，视为明确动作 |
| 重启类设置变化 | 否（标记待应用） | 需显式「应用网络设置」 |
| 文本输入 | 失焦 / Enter / 离页 / 关窗时提交 | 关窗时必须先提交或提示保留草稿 |
| 节点卡片双击 / Enter | 是 | 提交节点选择 |
| 节点单击 / 方向键 | 否 | 仅预选 |

**可验证**：节点预选零写入；失败后草稿仍在；未失焦的文本改动在关窗时被提交或提示，不静默丢失。

### P4.1 反馈路由

现有 `operationFinished(bool ok, QString message)` 不带操作标识（`AppController.h:183`），无法区分页面级与跨页级。**决定：扩展信号加操作标识**（需 ADR 0046 记录偏差）。

| 反馈类型 | 承载位置 | 生命周期 | 触发源 |
|---|---|---|---|
| 对象内结果 | 对象所在行/卡片 | 直到状态改变 | 延迟测试、面板选中 |
| 页面内提示 | 页面提示区 | 直到状态改变 | 规则草稿、设置应用结果、页面级失败 |
| 全局操作结果 | 状态栏「最近操作」段 | 成功 5 秒后消失，失败保留 | 跨页操作（导入、批量更新） |
| 持久告警 | 状态栏「当前告警」段 + 侧栏状态条 | 直到条件解除 | `state.lastError`、只读保护 |
| 聚合结果 | 页面内提示，含「n 成功 / m 失败」+ 详情入口 | 直到关闭 | 批量更新、批量测试 |
| 进行中 | 触发控件旁 + 状态栏 | 直到完成或取消 | `operationStarted`、`delayProgress` |

**映射要求**：`operationStarted`、`delayProgress`（现同时写页面与状态栏，`MainWindow.cpp:146`）、`settingsFeedback_`、`rulesHint_`、托盘失败气泡（`TrayController.cpp:62-64`）逐条归入上表某一类，不得留在状态栏兜底。

### P5 高频路径最短

| 高频动作 | 唯一主入口 | 允许的次入口 |
|---|---|---|
| 启动/停止内核 | 状态页状态块 | 侧栏状态条点击、托盘菜单 |
| 切换节点 | 节点页列表提交 | 托盘策略组子菜单、最近选择菜单 |
| 看延迟 | 节点页列表内联 | 托盘组菜单停留测试 |
| 更新订阅 | 订阅页提交条 | 托盘「订阅管理」 |
| 切换系统代理 | 状态页开关 | 托盘菜单、快捷键 |

**可验证**：每个高频动作在 840×560 首屏一次点击可达。

### P6 结构一致，而非外观一致

同一类对象在不同页面遵循相同的层级与交互规则，外观由统一 token 决定。

**执行机制**：色值、字号、间距只允许出现在 `UiTheme`、`UiIcons`、`WidgetStyle`、`NodePresentation` 四个文件；页面代码与自绘委托只读 token。构建检查脚本禁止清单外出现 `setStyleSheet`、`QColor` 字面量、`setPixelSize`、`setPointSize`。

**可验证**：检查脚本零命中；同一控件类型只有一处样式定义。

### P7 尊重平台与可访问性

使用系统字体栈与原生窗口装饰；文字放大时几何同步缩放；状态不能只靠颜色；键盘可达全部动作。

**可验证**：840×560 下 90/100/110/120% 四档逐页检查固定尺寸控件与 `ElidedLabel`，列出所有 `setFixedSize`/`setMinimumHeight` 并改为 token；卡片视图支持方向键/Enter/Space；焦点环由单一绘制器绘制。

### P8 不显示无来源的承诺

界面不展示未经 Controller 字段支撑的指标；未知一律「—」+ 原因；截断与上限必须可见说明（如「仅显示前 2000 条」）。

**可验证**：不出现无字段来源的数值；所有截断处有可见说明。正例参考 `WebsiteTestsPage.cpp:78`「HTTP 状态：未知（核心 delay 接口未提供）」。

### P9 有界与可取消

所有持续操作有上限与取消路径：日志 2000 行、连接/规则/订阅显示上限、刷新频率固定、批量操作可中止、长任务有进度。

**可验证**：任一长操作用户都能取消；内存与条目数有明确上限。

### P10 版本与写入安全

候选/运行/上次良好三分展示，不互相冒充；系统代理只在完整快照匹配时恢复；日志先脱敏后显示与导出；备份密码不可找回。

**可验证**：订阅页同时可见三个版本标识；恢复只在快照匹配时执行；导出内容不含令牌与原始配置。

### P11 繁忙与只读

写操作进行中全局可见且禁止并发写；只读保护时所有写入口禁用并说明原因。

**可验证**：busy 时提交按钮禁用且有说明；readOnly 时写入口不可用。

### P12 两跳上限

从用户所见页面到完成任何修改，**不超过两层**：页面行/列表项 → 工具窗口或内联展开。禁止第三层钻取，禁止「行 → 菜单 → 子菜单 → 对话框」。

设置行、列表项必须**行内显示当前值**（端口显示端口号、内核显示版本、备份显示上次时间），不能只显示名称要求用户点进去才知道。

**来源**：Clash Verge Rev 2.5.9 实证——设置页 4 卡 35 行 + 11 个子对话框，所有复杂项都是「一行标题 + 当前值 → 对话框」，这是它在 100+ 可调项下仍不失控的唯一机制（见 [U07 调研](ui-benchmark-research.md)）。

**可验证**：统计每个设置项到完成修改的层级数，全部 ≤ 2；每个控件型设置行都显示当前值。

### P13 简洁的定义

本项目的「简洁」采用以下定义，用于裁决所有争议：

> 简洁不是功能少，也不是界面元素少。简洁是**每一屏只回答一个问题**，且**任何能力最多两跳可达**。首屏裁剪决定观感，两跳上限决定可发现性，两者缺一不可。

**可验证**：每页首屏只有一个任务焦点；任意能力 ≤ 2 跳；两者同时满足才算简洁。

## 第 2.5 层：三目标冲突的逐页审视

P0 给出分工原则后，用实际数据检查每个页面是否满足首屏指标：状态页 ≤ 3 个可交互元素，其余页 ≤ 12 个控件。统计来自当前实现，目标为设计值。

| 页面 | 当前控件数 | 首屏应保留 | 收纳去向 | 结论 |
|---|---|---|---|---|
| 状态（原首页） | 21 + 6 卡 + 4 指标 + 2 面板 | **状态结论、主开关、至多两个选择** | 导航卡删除；指标、探测、摘要全部进「更多运行信息」抽屉；首页摘要设置项移入设置 | Shadowrocket 实测为 3 个可交互元素，据此硬性裁剪 |
| 节点 | 19 | 搜索、排序、视图、列表、当前成员、切换 | 筛选、恢复自动、测速全部、最近选择进工具条溢出菜单；订阅切换进上下文条 | 底部七项合并为「选中对象提交条」 |
| 设置 | 29 | 分类页签 + 当前分类的分组行 | 不减少行数，但**每分类独立滚动**，不在同一屏堆叠；搜索常驻 | 29 项全部保留（P0 推论一），靠分类与搜索收纳 |
| 订阅 | — | 列表、添加、更新、使用 | 管理菜单（重命名/回滚/删除/兼容性）、编辑配置菜单 | 现有分层基本符合 |
| 规则 | — | 规则列表、添加、保存 | 高级文本、完整编辑、规则源进工具窗口 | 符合 |
| 网站测试 | — | 测试节点、开始/停止、结果卡片 | 目标编辑、出口诊断进页签行右侧动作区 | 符合 |
| 连接 | — | 搜索、表格、断开选中 | 列设置、断开全部进溢出 | 页签（活动/已结束）保留 |
| 日志 | — | 搜索、级别、日志、跟随 | 导出、清空、换行进工具带溢出 | 符合 |

### 三条具体裁决

**1. 首页六卡改为「默认收起、可选添加」。** 它们用 `i+1` 当页号（`MainWindowHome.cpp:45-47`），本质是侧栏的第二份拷贝，默认全开是「功能完整」与「极简」冲突最明显的例子。

调研校正（[U07](ui-benchmark-research.md)）：Clash Verge 的做法是**9 张卡任选、默认开 8 张**，且自己修过 840 宽下的卡片截断缺陷——说明「可配置首页」的价值被验证，但「默认全开」是它的问题。因此不采纳「删除」，改为：

- 默认只显示 3 张：**状态、当前订阅、当前节点**。
- 其余三张（规则摘要、连接摘要、日志摘要）进入「添加卡片」入口，用户自选。
- 卡片本身从「导航卡」改为「摘要卡」——点击跳转保留，但卡面必须显示真实摘要而非仅标题。

这既保留 Clash Verge 「用户自己决定首屏噪声」的优点，又避免它的默认全开缺陷。

**2. 设置 29 项全部保留，但不同时呈现。** 当前三分类已经存在（`settingsCategories`），问题是分类切换后仍是一长列。方案：每个分类独立滚动 + 搜索常驻 + 组内折叠低频组（如「高级内核」默认收起）。这是 Shadowrocket 的做法——设置项一个不少，但一屏只看到当前分类。

**3. 节点页底部的七项动作合并。** 当前底部同时有当前成员、进度、取消、计数、定位、进入、切换（`MainWindowProxy.cpp:82-86`）。方案：进度与取消只在测速时出现；定位与进入组合并为组标题旁的图标按钮；切换作为唯一主按钮。

### 新增原则的可验证边界

P0 已声明设置页与订阅页是「首屏 ≤ 12 控件」的例外；其余页面按该上限执行。

## 第 3 层：UI 分类

### 页面类型

页面类型只描述**主视图**；一个页面可包含多个页内视图（分段切换）。

| 类型 | 定义 | 页面 | 主视图 | 提交条 |
|---|---|---|---|---|
| **状态页** | 回答「我在哪、下一步做什么」 | 状态 | 状态块 + 指标 | 无（动作在状态块内） |
| **对象列表页** | 浏览并操作同一类对象 | 订阅、节点、连接 | 列表 | 有选中对象时才有 |
| **流视图页** | 只读、不可选择、持续追加 | 日志 | 文本流 + 过滤 | 无 |
| **编辑页** | 维护配置，多步骤 | 规则 | 编辑区（列表/文本分段） | 固定保存栏 |
| **任务页** | 执行一次可观察的任务 | 网站测试 | 结果网格 | 无（结果摘要条代替） |
| **设置页** | 调整偏好 | 设置（三分类） | 分组行 | 仅重启类改动时出现 |

### 页内视图类型

| 类型 | 说明 | 实例 |
|---|---|---|
| 列表 | 可选择、可排序 | 规则优先列表、连接活动/已结束 |
| 编辑 | 可写、有草稿 | 规则文本编辑 |
| 只读 | 只读快照 | 内核实际规则 |
| 流 | 追加、不可选择 | 日志 |

页内视图用**页内分段控件**切换，不改变路由（见第 1 层「页签层级分离」）。

### 容器类型

| 类型 | 用途 | 实例 |
|---|---|---|
| 分组 | 同类别行的容器 | 设置分类内各组、「备份与工具」内各任务组 |
| 卡片网格 | 等宽卡片流式排列 | 网站测试目标、节点卡片 |
| 工具窗口 | 单对象配置 | 见窗口类型 |

「备份与工具」是**设置页的第三个分类**，其内部用「分组 + 任务行」容器，不是独立页面类型。

### 窗口类型

| 类型 | 用途 | 规则 | 实例 |
|---|---|---|---|
| **工具窗口** | 配置单个对象 | 非模态，按（工具, 对象）复用，关闭即取消未提交编辑 | TUN、DNS、快捷键、节点定义、Provider、代理链 |
| **模态管理窗口** | 复杂内容，需明确完成/取消 | 模态，阻塞主窗口，有未提交改动时确认 | 备份/恢复预览、兼容性报告、批量更新 |
| **确认对话框** | 有不可逆后果 | 模态，说明后果与范围 | 删除订阅、断开全部、覆盖 |
| **预览/详情窗口** | 只读快照 | 打开时快照，不跟随刷新 | 配置预览、网站结果详情、出口证据 |
| **浮层/通知** | 轻量、瞬态 | 不承载必要信息 | 设置搜索、筛选面板、托盘气泡 |

### 反馈类型

见第 2 层 [P4.1 反馈路由](#p41-反馈路由)：六类反馈已给出承载位置、生命周期与触发源，并附逐条映射要求。

### 控件分类

| 类别 | 成员 | 规则 |
|---|---|---|
| 主导航 | 侧栏项、分区页签 | 选中实心，改变路由 |
| 页内分段 | 活动/已结束、列表/文本 | 只切换页内视图，不改变路由 |
| 上下文 | 订阅选择、策略组、筛选 | 改变浏览范围；**必须在提交条或动作文案中回显目标** |
| 工具 | 搜索、排序、视图切换、重测 | 只影响呈现 |
| 提交 | 使用、应用、保存、启动 | 唯一写入口，明确文案 |
| 工具带 | 详情、复制、断开、导出 | 作用于选中对象 |

**危险**不是独立类别，而是可叠加在提交与工具带上的修饰角色（红色 + 确认）。

### 收纳层级

P0 的三目标分工需要一套统一的收纳机制，否则每页各自决定「什么收起」，最终又回到混乱。**任何功能必须且只能位于以下四级之一**：

| 级别 | 可见性 | 适用 | 入口 | 现有例子 |
|---|---|---|---|---|
| **L0 常驻** | 首屏直接可见 | 状态结论、当前对象、下一步动作、主提交 | 无 | 启动/停止、当前成员、节点切换 |
| **L1 工具条** | 首屏可见，与内容同排 | 高频但不主打的动作（搜索、排序、视图） | 无 | 搜索框、排序下拉、表格/卡片切换 |
| **L2 抽屉/溢出菜单** | 同页内一次点击展开 | 中频动作、多选、次要设置 | 「更多」「筛选」「管理」按钮 | 筛选面板、订阅管理菜单、更多运行信息 |
| **L3 工具窗口/设置分类** | 跨页或窗口 | 低频、长流程、需要预览或确认 | 设置行、工具窗口、菜单项 | TUN 管理、备份恢复、Provider 编辑 |

判定规则：

- 每日使用的动作 → L0 或 L1，**禁止**下沉到 L2 以下。
- 每次启动才用一次的动作（备份、内核切换）→ L3。
- 同一对象超过 4 个动作时，保留 1 个主要 + 其余进 L2。
- L2 与 L3 的入口必须**始终可见**，不得只在特定状态下出现；入口本身可以标注数量（「筛选 2」）。

**违反检测**：若某功能既不在四级的任何一级、又没有被删除，说明它的位置是随机的。当前「首页六卡」（纯重复导航）与「计算后隐藏的标签」都属于此类。

## 第 4 层：容器布局

### 统一页面骨架

所有页面共用同一垂直骨架，顺序固定：

```
┌──────────────────────────────────────────┐
│ 页签行：分区页签（左）＋页面级动作（右）  │  ← 固定，内容区第一行
├──────────────────────────────────────────┤
│ 上下文条（可选）：当前对象/范围           │  ← 固定
├──────────────────────────────────────────┤
│ 工具条（可选）：搜索、排序、视图、页内分段 │  ← 固定，可换行
├──────────────────────────────────────────┤
│ 主内容区（列表/编辑/卡片/状态块）         │  ← 占据剩余，可滚动
├──────────────────────────────────────────┤
│ 结果摘要条（可选）：进度、统计、提示      │  ← 固定
├──────────────────────────────────────────┤
│ 提交条（可选）：目标回显 + 主/次动作      │  ← 固定
└──────────────────────────────────────────┘
```

约束：

- **不设页面标题**：分区名由侧栏选中态表达，视图名由页签选中态表达，二者都不再重复成文字标题。页面级动作与页签同排右对齐。

**关于不设标题的取舍**：去掉标题减少了顶部两行文字与一处层级竞争，但也让「我在哪」只能依赖侧栏与页签的选中态。为避免识别性下降，要求：

1. 页签必须始终可见（即使分区只有一个视图也保留页签，以承载视图名）。
2. 侧栏选中态用实心填充，不得退化为仅换文字颜色。
3. 窗口标题栏显示「Mlash · 当前视图名」，供任务栏与 Alt+Tab 识别。
4. 设置页的视图名由三分类页签承载，不再额外渲染「设置」二字。
- 页签行、上下文条、工具条、提交条与主内容**同宽同左缘**；只有主内容区可滚动。设置页的 760 单列改为列容器宽度 token，与其它行落在同一列内。
- 同一页面**同屏只有一个滚动主体**：列表/文本框自身的滚动不算页面滚动，但同屏不得出现两个。
- 提交条固定底部，滚动内容不改变其位置；提交条必须回显当前目标（如「使用并启动 · 订阅 A」）。
- 关闭窗口或离开页面时，未失焦的编辑先提交或提示保留草稿。

### 各类型页面骨架

| 类型 | 页签行 | 上下文条 | 工具条 | 主内容 | 结果摘要条 | 提交条 |
|---|---|---|---|---|---|---|
| 状态页 | 有 | 无 | 无 | 状态块 + 指标 + 折叠摘要 | 无 | 无（动作在状态块内） |
| 对象列表页 | 有 | 有（对象范围） | 有 | 列表（表格或卡片） | 无 | 有选中对象时 |
| 流视图页 | 有 | 无 | 有（级别/搜索/跟随） | 文本流 | 有（采样时间、暂停状态） | 无 |
| 编辑页 | 有 | 有 | 有（页内分段：列表/文本） | 编辑区 | 有（草稿状态/校验） | 有（固定保存） |
| 任务页 | 有 | 有（测试对象） | 有（开始/停止） | 结果网格 | 有（进度、上次结果、下一步） | 无 |
| 设置页 | 有（三分类） | 无 | 有（搜索） | 分组行 | 有（应用结果） | 仅重启类改动时出现 |

补充规则：

- 日志页的导出与目录合并在工具条内一处，不重复出现。
- 日志的「回到最新」使用浮层位置，不占骨架行。
- 订阅页的对象动作条迁到提交条，与节点/连接一致。
- 网站测试的「前往首页」改为直接执行下一步（启动内核或添加订阅），文案写动作而非目的地。

### 列表容器规则

- 表格与卡片视图共享同一数据、选择、滚动语义；切换视图不丢失选择。
- 行高由密度 token 决定（数据 32 / 表单 48），不在页面里硬编码；卡片最小高另由 `card-min` token 决定。
- 空态占据列表区域，文案说明原因与下一步，不显示空表格。
- 每个列表登记选择模型：节点（单选 + 双击/Enter 提交）、订阅（单选 + 提交条）、连接（多选 + 提交条）、日志（无选择）、规则（单选 + 编辑）。

### 分组容器规则

- 分组用**留白与次级表面**区分，不依赖边框。
- 组内行之间用 hairline 分隔；组与组之间只用间距。
- 可交互容器（可点击卡片、输入框）才使用边框。

### 收纳级别的容器形态

| 级别 | 形态 | 布局约束 | 关闭/返回 |
|---|---|---|---|
| L1 工具条 | 单行，可换行 | 与页签行同高，不与主内容争宽 | 无（常驻） |
| L2 抽屉 | 页面内展开区 | 展开时推动主内容，不覆盖；展开状态在切分类时保留 | 再次点击收起的按钮 |
| L2 溢出菜单 | 弹出菜单 | 分组 + 分隔；超屏可滚动 | 点击外部或 Esc |
| L2 侧面板 | 右侧滑入面板 | 最多占内容宽 40%；不遮页签行 | 关闭按钮或 Esc |
| L3 工具窗口 | 独立窗口 | 见下方骨架 | 关闭 = 取消未提交编辑 |

**L2 的三种形态如何选**：需要并列查看主内容 → 侧面板；纯动作列表 → 溢出菜单；需要多选或多字段 → 抽屉。

### 默认密度

三目标中的「极简呈现」由密度保证，而不是由减少功能保证：

- 默认一行只表达一件事，不把状态、说明、动作塞进同一行。
- 次要说明默认省略，保留在提示与无障碍描述中。
- 空态只显示一句原因 + 一个动作，不显示空表与空卡片。
- 页面内不使用装饰性图标；图标只用于识别对象或指示可展开。

### 工具窗口骨架

```
标题 | 说明（可选）
─────────────────────
内容（可滚动）
─────────────────────
反馈文本
[取消] [主要动作]
```

**生命周期契约**：

| 事项 | 规则 |
|---|---|
| 复用键 | （工具, 对象 ID）；同一键再次打开时 raise 已有实例 |
| 对象消失 | 订阅/节点被删除或切换数据源时自动关闭 |
| 页面切换 | 非模态工具窗口保留并 raise；预览/详情窗口关闭 |
| busy / readOnly | 写入口禁用并说明原因，浏览仍可用 |
| 关闭时未提交编辑 | 用 `DialogDraftGuard` 询问，不静默丢弃 |
| 破坏性流程 | 升级为模态管理窗口或确认对话框 |

### 页面生命周期契约

现有 `setPage` 带页号副作用开关轮询（`MainWindow.cpp:489-506`）。改为统一导航后必须显式定义：

| 时机 | 页面 | 行为 |
|---|---|---|
| 进入 | 状态、节点 | 刷新运行状态，启动 8 秒轮询 |
| 进入 | 连接 | 开始连接采样 |
| 进入 | 日志 | 订阅诊断输出，滚动到最新 |
| 进入 | 规则（内核实际规则） | 刷新内核规则 |
| 离开 | 全部 | 停止本页轮询，取消本页测试，关闭详情窗口 |
| 轻量重建 | 全部 | 只恢复页面号与页内记忆，不恢复轮询 |

### 反馈位置

- 反馈文本固定在动作区上方，不随滚动移动。
- 字段错误显示在字段下方，不汇总到顶部。

## 第 5 层：Widget 详细设计

这一层只定义**结构、语义与交互**，不定义颜色与字号（第 6 层统一套用）。

### 5.1 导航

| Widget | 结构 | 交互 | 状态 |
|---|---|---|---|

### 5.9 托盘

托盘的定位经调研校正：**它不是「第二套导航」，而是「把高频动作从窗口里拿走」**。这是 Shadowrocket 桌面版唯一的界面级机制——官方更新日志明确 macOS 增加「菜单栏路由控制 + 快捷服务器配置」（[U07](ui-benchmark-research.md)），窗口退化为纯配置界面。

因此托盘菜单以**动作**为主，导航为辅：

| 项 | 结构 | 约束 |
|---|---|---|
| 状态标题 | 一行结论（核心 / 代理 / TUN） | 与侧栏状态条同源，不单独计算 |
| 启停内核 | 单项动作 | 与状态页同一命令 |
| 路由模式 | 规则/全局/直连 三项 | 与状态页同一命令 |
| 策略组子菜单 | 组 + 成员 + 「测试延迟」 | 停留后按需测试，复用缓存；内嵌测速是 Clash Verge 实证的有效小改动 |
| 代理切换 | 与状态页开关同一命令 | 必须复用同一确认逻辑，不得绕过 |
| 页面入口 | 精简至常访问的 3–4 个 | 不是完整导航镜像；完整导航仍在窗口 |
| 失败气泡 | 与状态栏同源 | 同一失败不同时出现在两处 |
| 单击动作 | 可配置（显示窗口/切换代理） | 切换代理需确认 |

**设计约束**：托盘菜单总项数 ≤ 12；超过时收纳进「更多」子菜单，不新增一级项。

### 6.3 应用规则

1. **层级靠表面抬升，不靠边框**。elevation-0 → 1 → 2；边框只给可交互容器与浮层。
2. **交互状态用叠色阶梯**。悬停、按下、选中各占一档；选中另加 2px `selectionBar`。
3. **高对比是第三套平行 token**。不只加深边框，选中、控件填充、轨道、焦点同时增强。
4. **字号七档、间距 8pt、圆角四级**。页面代码禁止字面量。
5. **几何随文字比例缩放**，覆盖 90–120%；给出最小字号 9pt 与最小行高 16px 下限，低于下限不再缩放。
6. **状态多通道**。形状 + 颜色 + 文本，不只靠色相。
7. **硬编码清零**，迁移清单：`WidgetStyle.cpp:118`（滚动条）、`WebsiteTestsPage.cpp:130`（内联样式）、`MainWindow.cpp:338`（状态点）、`NodePresentation.cpp:98-99`（徽标）、`OutboundDialog.cpp:22`（17pt 硬编码）、`HomeMetricsView.cpp:30`（被覆盖的死代码）；配合 P6 的构建检查脚本。

### 6.4 第 5 层的尺寸声明

第 5 层的控件尺寸直接引用 token，不写死值。以下现有硬编码将被替换，需计入迁移成本：`ProxySwitch` 38×20 → `switch-track` 42×24；图标按钮 26 → `icon-hit` 28；网站卡最小高 108 → `card-min`；组面板固定 110 → 内容驱动。

## 持久化与接口边界

| 项 | 本期决定 | 影响 |
|---|---|---|
| `startupPage` | 仍为整数 0–7 | 无需数据迁移；标签随路由模型变化 |
| 设置分类 | 会话内状态，不持久化 | 轻量重建后回到「常规」 |
| 分区最后视图 | 会话内状态，不持久化 | 现有行为保留 |
| 表格列宽/列序 | **不新增持久化** | 会话内记忆；如后续需要另立 schema 决策 |
| `GuiHost` 恢复 | 只恢复视图 ID（0–7） | 设置分类不参与恢复 |
| `operationFinished` | 扩展为带操作标识 | **接口变更**，需 ADR 0046；85 处 emit、119 处 connect 需同步 |
| Controller 命令 | 不变 | 不新增、不删除命令 |
| Controller 状态字段 | 不变 | 新 UI 只消费现有字段 |

## 需记录的 ADR 偏差

本文相对 ADR 0045 与 U05 目标信息架构有以下偏差，须新增 ADR 0046 记录：

1. **备份不独立成页**，保留为设置第三分类（ADR 0045 写的是移出为「维护」页）。
2. **设置三分类为可寻址视图**，路由扩展为 `(viewId, category)`（ADR 0045 未定义设置分类的寻址方式）。
3. **`operationFinished` 增加操作标识**，偏离「命令与接口不变」的边界。
4. **分区名保持首页/配置/数据/设置**，不改「运行/观测」。
