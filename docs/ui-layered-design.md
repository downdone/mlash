# U06 界面分层设计

2026-10-29 · 设计文档，未实施。本文按六个层次依次定义 Mlash 的界面：整体架构、原则、UI 分类、容器布局、Widget 详细设计、视觉与配色。前五层只定义结构与中性占位样式，第六层最后统一套用。决策意图见 [ADR 0045](adr/0045-ui-system-rebuild.md)，问题证据见 [U05 评审](ui-system-review.md)。

> 本文取代 U05 中「目标信息架构」与「实施阶段」两节的结构提案；U05 的问题清单与证据继续有效。

## 设计约束

用户明确的原则：

1. **架构从简**：能不分区就不分区，能合并就合并；但主要任务必须单页完成的，保持单页。
2. **分层推进**：严格按 1→5 顺序设计，视觉风格最后统一套用，避免容器假设与配色互相矛盾。
3. **允许推翻**：不局限于现有八页结构。
4. **三目标并重**：功能完整（对标 Clash Verge）、简洁直观（对标 Shadowrocket）、最终呈现极简。三者通过「默认界面 / 收纳入口 / 视觉克制」分工实现，详见 [P0 原则](#p0-三者兼得的分工)。

工程约束（不可推翻）：候选/运行版本分离；写前恢复与串行化；默认测试不碰系统代理。Controller 命令与持久化 schema 的**唯一例外**是新增 `setProxyEnabled(bool)`——UI 层无法把「启内核 → 接管 → TUN」编排成可回滚事务（见「契约影响清单」与 ADR 0048）。

## 第 1 层：整体架构

### 判断标准

一个「页面」只承载一类任务，且该任务的主要动作能在一个屏幕内完成。满足则单页；不满足则拆。反过来，两个页面若共享同一对象与同一动作链，则合并。

### 现状评估

八页中，有三组存在真实的重叠：

| 组 | 重叠事实 | 结论 |
|---|---|---|
| 首页 / 节点 | 首页有节点快捷切换与策略组浏览，节点页是同一对象的主界面 | 同一对象、同一动作链；合并为一个首页（见 [ADR 0048](adr/0048-home-merged-proxy-switch.md)） |
| 首页 / 网站测试 | 首页只提供进入入口与摘要 | 网站测试是独立任务且需要整屏卡片，保持单页 |
| 订阅 / 规则 | 规则按订阅保存，两者共享订阅选择上下文 | 任务不同（来源维护 vs 分流维护），保持分页但共享上下文条 |
| 连接 / 日志 | 都是观测，但读取边界与操作不同 | 任务不同，保持分页 |
| 设置 / 备份 | 备份是长流程任务，不是偏好 | 保留为设置第三分类（用户决定，不拆独立页） |

### 采用的结构

**两级导航。** 侧栏保留四个分区。K 版（U08 第二版）改为：内容区首行是固定 72px 的**顶栏**（页面标题 + 副标题 + 状态胶囊 + 主题/更多图标钮），分区页签不再是首行容器；只有「数据」与「配置」保留各自的页签，其余分区没有页签行。页面级动作放在顶栏下方该屏自己的标题行右侧。

| 分区 | 页签（可寻址视图） | 数量 | 说明 |
|---|---|---|---|
| 首页 | **无页签**（状态(0) 与节点(2) 合并为同一滚动视图） | 0 | 控制区在上、节点列表在下，见[ADR 0048](adr/0048-home-merged-proxy-switch.md) |
| 配置 | 订阅(1)、规则(2) | 2 | 两张行列表，每行 76px，各自带标题行 |
| 数据 | 流量(3/0)、连接(3/1)、测试(3/2)、日志(3/3) | 4 | 一个视图 + 四个页签，见下「数据页」 |
| 设置 | **无页签**：通用 / 网络 / 内核与维护三组平铺 | 0 | 分类只用于深链定位，不是可寻址视图 |

**首页是唯一无页签的视图。** 状态与节点合并在同一滚动视图内（[ADR 0048](adr/0048-home-merged-proxy-switch.md)）：三行控制区在上，节点与策略组列表在下。索引 0 与 2 都路由到首页；索引 2 额外滚动到节点列表首行。首页的窗口标题仍为「Mlash · 首页」。

**计数口径统一**：`QStackedWidget` 有 **5** 个视图（K1 起），视图 ID 为 首页 0 / 配置 1 / 规则 2 / 数据 3 / 设置 4。数据页的四个页签不是视图，是数据视图内的页签；设置的三组分类也不是视图。旧编号 0–7 只作为持久化与快捷键的兼容入口存在（启动页、托盘、`GuiHost`、订阅链接），由 `ViewIds::fromLegacy()` 一处映射。

### 路由模型

所有导航表面（侧栏、页签、托盘、启动页、设置搜索、`GuiHost`）从同一张表取值，禁止页号算术。

| 视图 | ID | 分区 | 页内位置 | 显示名 | 可寻址 | 默认页 |
|---|---|---|---|---|---|---|
| 首页（控制区 + 节点列表） | 0 | 首页 | — | 首页 | 是（旧入口 0/2） | **是** |
| 配置 › 订阅 | 1 | 配置 | 列表 1 | 订阅 | 是 | 否 |
| 规则 | 2 | 配置 | — | 规则 | 是（旧入口 3） | 否 |
| 数据 | 3 | 数据 | 页签 0–3 | 数据 | 是（旧入口 4/5/7） | 否 |
| 设置 | 4 | 设置 | 分组 0–2 | 设置 | 是（旧入口 6） | 否 |

**旧编号（0–7）与视图 ID 不是同一套数字。** `3` 在旧编号里是规则、在新编号里是数据；`4` 在旧编号里是数据·连接、在新编号里是设置。因此旧的整数入口（`startupPage`、托盘、`GuiHost::show(int)`、订阅链接）必须先经 `fromLegacyPage()` 归一化，**任何代码都不得对视图 ID 再做页号算术或历史猜测**。

**路由别名**：旧编号 0 与 2 指向**同一个首页视图**，区别只在锚点：`fromLegacyPage(0)` 落控制区，`fromLegacyPage(2)` 落节点列表首行（`HomeAnchor::Nodes`）。托盘、启动页、搜索取显示名「首页」，不出现「状态」「节点」作为页面名。

**路由键**：`viewId`（0–4）+ `tab`（仅数据页，`-1` 表示沿用当前页签）+ `category`（仅设置页，`kNoCategory = -1` 表示沿用当前分类，`fromLegacyPage(6)` 给 `category = 0`）+ `anchor`（仅首页）。非数据页的 `tab` 恒为 `-1`——否则同一条路由各字段不等，`toLegacyPage()` 往返还会把它变成数据页的编号。`startupPage` 与托盘跳转沿用旧整数 0–7，不迁移数据。

**扩展面**（这是相对 ADR「命令与 schema 不变」的偏差，需在 ADR 0046 记录）：

- `GuiHost::show()` 的 `page < 8` 硬编码改为「路由模型条目数」校验（`GuiHost.cpp:10`）。
- `TrayController` 的页号跳转改为路由键；设置分类要支持 `(6, category)`。
- 启动页下拉改用路由模型标签，数值 0–7 不变。
- 设置搜索 `pageRequested(int)` 扩展为路由键。

### 页签层级分离

一级分区页签与页内分段是**两种控件**，不得同形同位置：

| 控件 | 位置 | 行为 | 记忆 |
|---|---|---|---|
| 分区页签 | 内容区顶部第一行，与内容左缘对齐 | 切换视图，改变路由；响应 Ctrl+Tab | 分区最后视图（会话内） |
| 页内分段 | 工具条内 | 只切换当前页视图（活动/已结束、列表/文本），不改变路由 | 页内记忆 |

规则页与连接页现有的 `QTabWidget`/`QTabBar` 降为页内分段；同页不得出现第二行页签。

### 结构裁决表

本文多处描述同一页面时曾出现互斥版本。**下表是唯一权威**；其余章节凡与此表冲突，以本表为准，并在修订时同步改正。

| 视图 | 首屏结构（唯一版本） | 主控件 | 分段 | 明确不做 |
|---|---|---|---|---|
| **首页** | 控制区（当前代理/路由方式/连通性三行）→ 节点标题行 → 节点行列表 → 一行 inline-stat → 提示 | **代理总开关**（行尾开关，开启代理/关闭代理，不是内核启停） | 无 | 不设页签（[ADR 0048](adr/0048-home-merged-proxy-switch.md)）；不设 IPv4/IPv6 分段；不设手动节点的提交条；自动策略组不提供切换；**不设「更多运行信息」抽屉**（K 版删除：内核、会话速率、运行版本在「数据 › 流量」，接管明细在「设置 › 网络」） |
| **订阅** | 标题行（添加订阅 / 导入文件 / 更新全部）→ 远程订阅列表 → 本地配置列表 | 「设为当前配置」抽屉动作；行尾 › 打开详情 | 无 | — |
| **规则** | 上下文条 → 页内分段 → 列表 → 提交条 | 「保存」 | 优先规则 / 内核实际规则 | — |
| **数据 › 流量** | 三块统计（下载/上传/活动连接）→ 近 60 秒曲线 → 一行出口摘要 | 无 | 无 | — |
| **数据 › 连接** | 页内分段 → 工具条 → 表格 → 提交条 | 「断开选中」 | 活动 / 已结束 | 不改单选模型（Controller 只有 `closeConnection(id)`） |
| **数据 › 测试** | 上下文条（测试节点）→ 工具条 → 卡片网格 → 结果摘要 | 「开始 / 停止」 | 无 | — |
| **数据 › 日志** | 工具条 → 文本流 → 结果摘要 | 无 | 无 | 不设提交条 |
| **设置（三组平铺）** | 通用 → 网络 → 内核与维护，组内 52px 行，行尾「值 + ›」 | 组末「应用网络设置 / 放弃修改」（仅需重启内核的改动出现） | 无（不设分类页签） | — |

**六条裁决说明**：

1. **首页主控件是代理总开关，不是内核启停。** 用户的心智是「开代理 / 关代理」，不是「启内核 / 停内核」；把内核启停当主按钮，等于把「内核在跑但没接管」这一状态留给用户自己从状态句推断。点开启时若内核未运行，内部先启动内核再按设置恢复接管；点关闭时按开启步骤的逆序撤销接管（系统代理 → TUN），**不停止内核**（失败回滚见 [ADR 0048](adr/0048-home-merged-proxy-switch.md)）。**内核单独启停不是首页控件**，它移到托盘菜单。**设置里没有单独的「允许接管」偏好开关**（现状只有「启动时恢复代理开关」`restoreProxy` 与表示上次结果的 `desiredProxy`）。首页总开关本身就是接管意图：关闭它即撤销接管，不改 `restoreProxy`；下次启动是否恢复由设置里的那一项决定。因此不存在「偏好关、总开关开」的组合。
2. **TUN 开关不放首页**。TUN 依赖权限服务安装这一前置条件，放在首页会让未安装用户看到一个必然失败的开关。它归「设置 › 网络与内核」。首页状态句只报告 TUN 的观测结果。
3. **IPv4/IPv6 分段删除**。这是评审指出的新功能而非现有控件重排，且 Controller 无对应字段；如将来要做，另立 ADR。
4. **状态与节点合并，首页无页签。** 截图证明两件事可以在一屏完成；分置两个页签会把最高频任务（换节点）的路径加长一跳。索引 0 与 2 保留为两个入口，指向同一视图。
5. **收纳入口不计入首屏控件数。** 只展开不执行的按钮（如「其余操作」「全部设置」「高级」）不是任务动作：展开前不改变用户可做的事，展开后内容进入的是同一页面而非新任务。但**必须可见**，不得退化为只有快捷键或隐藏按钮。**本版首页没有抽屉**：K 版按 GPT 原型删除了「更多运行信息」，流量与出口摘要在「数据 › 流量」，内核启停在托盘，接管明细在「设置 › 网络」的状态行；原抽屉的五项不设替代抽屉。
6. **首页只保留控制区与节点列表，不做仪表盘。** 流量曲线、连接数、规则命中、内核路径都不上首页；它们在「数据」与设置里。首页底部一行轻量速率摘要是允许的上限，且可关闭。

## 第 2 层：UI/UX 原则

原则层不做视觉决定，只做**行为承诺**。每条原则都必须能在后续层级被验证。

### P0 三者兼得的分工

Mlash 同时追求三件事：Clash Verge 级的功能完整、Shadowrocket 级的简洁直观、极简的最终呈现。三者不可能靠「减少功能」或「简化界面」同时满足，因此用**分工**而不是折中：

| 目标 | 承担者 | 具体机制 |
|---|---|---|
| 功能完整 | 设置与工具窗口 | 29 项设置、TUN/DNS/备份/Provider 全部保留，不删功能 |
| 简洁直观 | 默认界面 | 默认只呈现当前状态、当前对象、下一步动作；其余进入抽屉、菜单、工具窗口 |
| 极简呈现 | 视觉层 | 不靠边框、不靠装饰、不靠颜色堆叠；一屏之内信息密度由层级决定 |

**推论一：功能不删，位置重排。** 任何「删掉某个功能」的提案都违反本条；正确做法是把低频功能移入抽屉/菜单/工具窗口，而非删除。
**推论二：默认界面只回答三件事。** 状态、当前对象、下一步。超出这三件事的信息默认折叠。
**推论三：复杂度必须可见地收纳。** 折叠不等于隐藏——被折叠的能力要有可发现的入口（如「其余操作」「全部设置」「高级」），而不是只能靠记忆或搜索找到。

> 命名边界：收纳入口按屏命名（「其余操作」「全部设置」「高级」）；作为**菜单分组名**时禁用具体控件名（见 P14），统一用「其余操作」。

**可验证**：首页控制区的交互控件不超过 6 个，节点列表不计入；其余页面首屏控件数不超过 12 个；被折叠的功能都有可见入口；功能清单相对当前版本不减少。

**计数规则**（避免不同人算出不同数）：开关、分段、按钮、下拉各计 1——一个分段控件不论含几个按键都计 1；只读文本与状态区不计；位于抽屉内、未展开时不计；**收纳入口（「其余操作」「全部设置」这类只展开不执行的按钮）不计**，但必须保持可见；**首页的节点列表（含其搜索、排序工具）不计入控制区预算**。**可导航的主要值**（如「当前代理」行点击进入节点区）计 1——它有命中区域与动作，不是只读文本。**控制区边界以第 4 层「逐页布局实例」首页行为准**：订阅选择器属于**节点区的上下文**，不在控制区三行内。


**「当前控件数」列的算法**（否则无法复核）：按本节首段的 P0 计数规则计——开关/分段/按钮/下拉各计 1，只读文本与状态区不计，抽屉内未展开不计。首页在 K 版实测为 **4**：路由方式行 1 + 系统代理开关 1 + 连通性测试 1 + 节点标题行的测速与排序各 1（原型把它们做成两个图标钮；搜索框属节点区上下文，不计入）；「其余操作」是收纳入口，不计；首页已无抽屉，「更多运行信息」的计数项随之作废。节点页的 19–22 区间量级已随 H3 行列表作废（`nodeToolsButton` 是收纳入口，其内动作不计）。
**证据等级与例外**：首页「控制区 3 行、节点列表在下方同屏」来自 Shadowrocket 三张实机截图的结构观察（iPad 版，中置信度，非 Windows 实测）。该结构是 ADR 0048 与 R3 的验收前提，**按阻塞验收执行**（R3 必须有 840×560 下「控制区之后可见 ≥3 行节点」的自动断言）。设置页与订阅页不适用控件上限，以「单分类 / 单列表一屏」为准，但必须有常驻的搜索或分类入口。例外只此两处，其余页面不得援引。

### P1 状态先于导航

全局状态由侧栏状态条常驻展示（核心 / 代理归属 / TUN / 当前订阅）；每个页面首屏还必须展示该页的**当前对象或范围**（当前订阅、当前策略组、测试节点）。不得出现只有空表格与「前往首页」的页面。

**可验证**：840×560、100% 文字下逐页检查「状态条存在」与「当前对象可见」两项，任一缺失即不通过。

### P2 一个事实只有一个权威来源

每个事实只有一个权威来源；摘要与详情必须由同一来源派生，不得各自缓存或计算。每个事实在路由模型中登记「常驻位置」与「详情位置」各一个。

**可验证**：按下表逐项在代码中找唯一赋值点，并确认界面没有第二处独立计算。

| 事实 | 权威来源 | 常驻位置 | 详情位置 |
|---|---|---|---|
| 内核状态/版本 | `AppState.core`、`coreVersion` | 侧栏状态条 | 首页控制区状态句 + 托盘菜单（K 版：首页抽屉已删除） |
| 系统代理归属 | `AppState.proxy` | 侧栏状态条 | 首页控制区状态句 |
| TUN 意图 | `Settings.tunEnabled` | 设置 › 网络 › TUN 开关 | 设置 › 网络 › TUN 管理窗 |
| TUN 观测 | `AppState.tunObserved`（**现状是意图的影子**：`AppControllerTransaction.cpp:84` 直接赋值 `settings.tunEnabled`） | 侧栏状态条 | 首页控制区状态句 |
| 代理总开关意图 | 由内核+系统代理+TUN 三者观测派生，不单独存储 | 首页控制区开关 | 首页控制区状态句 |
| 当前订阅 | `Settings.activeProfile` | 侧栏状态条 + 首页节点列表的订阅选择器 | 订阅页 |
| 当前成员 | `proxies[group].now` | 首页控制区「当前代理」行 + 节点列表行内标记 | 首页节点列表 |

**代理总开关没有独立状态字段。** 它是派生视图：内核未运行 → 关闭；内核运行且（系统代理或 TUN）已接管 → 开启；内核运行但都没接管 → 关闭且状态句说明「内核运行中，未接管流量」。任何新增的布尔字段都会与三者产生第二权威来源（违反 P2）。

**关闭代理不停止内核。** 关闭只撤销系统代理与 TUN；内核继续运行以支持测速、配置管理与快速重开。理由是内核生命周期是技术动作而非用户意图（[ADR 0048](adr/0048-home-merged-proxy-switch.md)），且停止后在托盘「策略组」子菜单里测延迟会必然失败。需要停止内核时走托盘「启动内核 / 停止内核」（K 版删掉了首页「更多运行信息」抽屉，首页不再有内核启停）。

### P3 意图与观测分离

用户要求开某状态（意图）与系统实际生效（观测）必须分别表达。未知显示「—」并给出原因入口，不填 0、不沿用旧值、不回落为关闭。

**结构与文案**（三类状态统一）：

| 状态 | 意图控件 | 观测指示 | 文案 |
|---|---|---|---|
| 代理总开关（首页） | 开关/按钮（受 readOnly/busy 约束） | 由内核与接管状态派生 | 「已接管」/「内核运行中 · 未接管」/「已关闭」/「开启中…」/「关闭中…」/「失败：<原因>」 |
| 系统代理（设置） | 开关（受 readOnly/busy 约束） | 状态点 + 归属 | 「已接管」/「外部管理」/「未启用」/「— 未确认」 |
| TUN（设置） | 开关（受权限前提约束） | 状态点（观测待补，见下） | 「已启用」/「启用中」/「未生效」（「— 未确认」待观测字段补齐后启用） |
| 内核（托盘） | 启动/停止按钮 | 状态点 + 版本 | 「运行中 · vX」/「启动中」/「已停止」/「失败」 |

主窗口、首页、托盘 tooltip 三处文案同源，由同一函数生成。

**三个维度不得互相冒充**：内核运行 ≠ 流量已接管 ≠ 目标可达。「已连接」只在「内核运行且至少一种接管方式生效」时出现；目标可达性单独报告，不能反过来推断代理状态。

**三个维度各有唯一观测来源**：内核 = `AppState.core` + `CoreState`；接管 = `AppState.proxy`（系统代理）+ TUN 的实际接口状态；目标可达 = 网站测试执行器的一次结果 + 时间戳。**「失败：<原因>」的来源是 `setProxyEnabled` 返回的失败步骤枚举**（`CoreStarting` / `ProxyApplying` / `TunApplying` / `Rollback`），不是状态栏的通用错误文本——后者无操作标识，无法区分是哪一步。

**可验证**：托盘与主窗口对同一状态给出相同句子。**TUN 的意图/观测分离属待补能力**：现状 `tunObserved` 由 `settings.tunEnabled` 直接赋值（`AppControllerTransaction.cpp:84,154`）、内核非运行即清零（`AppController.cpp:53`），并非真实观测；`core_.tunObservation()` 存在但未写回。R3 不依赖该分离，补齐 TUN 观测另立切片与 ADR；在此之前 P3 的 TUN 行只用「已启用 / 未启用」，不显示「— 未确认」。

### P4 写操作明确、就近反馈

浏览、搜索、排序不写；只有明确动作才提交。失败在对象附近显示并保留输入。首页节点列表的单击**就是**明确动作（手动组），不设预选态——这是 [ADR 0048](adr/0048-home-merged-proxy-switch.md) 对「单击=预选、双击=提交」的唯一例外。

**明确动作的例外定义**（避免与即时提交矛盾）：

| 动作 | 是否写入 | 说明 |
|---|---|---|
| 偏好控件变化 | 是 | 偏好类设置变化即提交，视为明确动作 |
| 重启类设置变化 | 否（标记待应用） | 需显式「应用网络设置」 |
| 文本输入（即时类：测试地址） | 失焦 / Enter / 离页 / 关窗时提交 | 关窗时必须先提交或提示保留草稿 |
| 文本输入（重启类：内核路径） | **不即时提交**，标记待应用 | 走「应用网络设置」，与端口/日志等级一致 |
| 首页节点行单击（手动策略组） | 是 | 立即 `selectMember`；失败回滚为原成员（[ADR 0048](adr/0048-home-merged-proxy-switch.md)） |
| 首页节点行单击（自动策略组） | 否 | 只读展示当前选路结果，不提供切换 |
| 方向键 | 否 | 仅移动高亮，不写入；Enter 等同单击 |

**可验证**：方向键移动零写入；手动组单击写入且失败回滚；自动组无论单击或 Enter 都不写入；失败后草稿仍在；未失焦的文本改动在关窗时被提交或提示，不静默丢失。

### P4.1 反馈路由

现有 `operationFinished(bool ok, QString message)` 不带操作标识（`AppController.h:183`），无法区分页面级与跨页级。**决定：扩展信号加操作标识**（需 ADR 0046 记录偏差）。

| 反馈类型 | 承载位置 | 生命周期 | 触发源 |
|---|---|---|---|
| 对象内结果 | 对象所在行/卡片 | 直到状态改变 | 延迟测试、面板选中 |
| 页面内提示 | 页面提示区 | 直到状态改变 | 规则草稿、设置应用结果、页面级失败 |
| 全局操作结果 | 状态栏「最近操作」段 | 成功 5 秒后消失，失败保留 | 跨页操作（导入、批量更新） |
| 持久告警 | 状态栏「当前告警」段 + 侧栏状态条 | 直到条件解除 | `state.lastError`、只读保护 |
| 聚合结果 | 页面内提示，含「n 成功 / m 失败」+ 详情入口 | 直到关闭 | 批量更新、批量测试 |
| 进行中 | 触发控件旁 + 状态栏 | 直到完成或取消 | `operationStarted`、`delayProgress` |

**映射要求**：`operationStarted`、`delayProgress`（现同时写页面与状态栏，`MainWindow.cpp:146`）、`settingsFeedback_`、`rulesHint_`、托盘失败气泡（`TrayController.cpp:62-64`）逐条归入上表某一类，不得留在状态栏兜底。

### P5 高频路径最短

| 高频动作 | 唯一主入口 | 允许的次入口 |
|---|---|---|
| 开/关代理 | 首页控制区代理总开关 | 托盘菜单、侧栏状态条点击 |
| 切换节点 | 首页节点列表（单击即生效，自动组不提供切换） | 托盘策略组子菜单 |
| 切换路由方式 | 首页控制区「路由方式」行 | 托盘菜单 |
| 目标可达性测试 | 首页控制区「连通性」行 | 数据 › 网站测试 |
| 看延迟 | 首页节点列表内联 | 网站测试页 |
| 更新订阅 | 配置 › 订阅提交条 | 托盘「订阅管理」 |
| 启动/停止内核（单独） | 托盘 | 设置 › 内核与维护 › 内核更新管理窗 |

**可验证**：每个高频动作在 840×560 首屏一次点击可达。

### P6 结构一致，而非外观一致

同一类对象在不同页面遵循相同的层级与交互规则，外观由统一 token 决定。

**执行机制**：色值、字号、间距只允许出现在 `UiTheme`、`UiIcons`、`WidgetStyle`、`NodePresentation` 四个文件；页面代码与自绘委托只读 token。构建检查脚本禁止清单外出现 `setStyleSheet`、`QColor` 字面量、`setPixelSize`、`setPointSize`。

**可验证**：检查脚本零命中；同一控件类型只有一处样式定义。

### P7 尊重平台与可访问性

使用系统字体栈与原生窗口装饰；文字放大时几何同步缩放；状态不能只靠颜色；键盘可达全部动作。

**可验证**：840×560 下 90/100/110/120% 四档逐页检查固定尺寸控件与 `ElidedLabel`，列出所有 `setFixedSize`/`setMinimumHeight` 并改为 token；卡片视图支持方向键/Enter/Space；焦点环由单一绘制器绘制。

### P8 不显示无来源的承诺

界面不展示未经 Controller 字段支撑的指标；未知一律「—」+ 原因；截断与上限必须可见说明（如「仅显示前 2000 条」）。

**可验证**：不出现无字段来源的数值；所有截断处有可见说明。正例参考 `WebsiteTestsPage.cpp:78`「HTTP 状态：未知（核心 delay 接口未提供）」。

### P9 有界与可取消

所有持续操作有上限与取消路径：日志 2000 行、连接/规则/订阅显示上限、刷新频率固定、批量操作可中止、长任务有进度。

**可验证**：任一长操作用户都能取消；内存与条目数有明确上限。

### P10 版本与写入安全

候选/运行/上次良好三分展示，不互相冒充；系统代理只在完整快照匹配时恢复；日志先脱敏后显示与导出；备份密码不可找回。

**可验证**：订阅页同时可见三个版本标识；恢复只在快照匹配时执行；导出内容不含令牌与原始配置。

### P11 繁忙与只读

写操作进行中全局可见且禁止并发写；只读保护时所有写入口禁用并说明原因。

**可验证**：busy 时提交按钮禁用且有说明；readOnly 时写入口不可用。

### P12 两跳上限

从用户所见页面到完成任何修改，**不超过两层**：页面行/列表项 → 工具窗口或内联展开。禁止第三层钻取，禁止「行 → 菜单 → 子菜单 → 对话框」。

设置行、列表项必须**行内显示当前值**（端口显示端口号、内核显示版本、备份显示上次时间），不能只显示名称要求用户点进去才知道。

**来源**：Clash Verge Rev 2.5.9 实证——设置页 4 卡 35 行 + 11 个子对话框，所有复杂项都是「一行标题 + 当前值 → 对话框」，这是它在 100+ 可调项下仍不失控的唯一机制（见 [U07 调研](ui-benchmark-research.md)）。

**可验证**：统计每个设置项到完成修改的层级数，全部 ≤ 2；每个控件型设置行都显示当前值。

### P13 简洁的定义

本项目的「简洁」采用以下定义，用于裁决所有争议：

> 简洁不是功能少，也不是界面元素少。简洁是**每一屏只回答一个问题**，且**任何能力最多两跳可达**。首屏裁剪决定观感，两跳上限决定可发现性，两者缺一不可。

**可验证**：每页首屏只有一个任务焦点；任意能力 ≤ 2 跳；两者同时满足才算简洁。

### P14 收纳处必须比首屏更有序

把功能移进菜单、抽屉或工具窗口，只是把复杂度从「看得见」变成「找得到」。**收纳不是终点，组织的质量决定简洁是否成立。**

规则：

1. **分组必有语义**：每组只做一类事，组间有分隔；无内容的组省略，不留空分隔。
2. **命名即说明书**：菜单项与分组名必须让人不点开就知道做什么、影响什么。动词开头，会弹窗才加省略号，不带未经解释的缩写。
3. **危险项永远单独在最后**，与上一组强制分隔，且宾语明确（「删除订阅…」而非「删除」）。
4. **同一动作在所有入口同名同位置**；菜单内不得出现两个同名项。**约束的是动作身份，不是文案**——随状态变化的标签视为同一动作。
5. **收纳不得成为隐藏**：入口在页面或菜单里必须可见，不能只在特定状态下出现。

**适用范围**：直接动作 ≥ 8 项的菜单才强制五组分组与 ≤15 上限；少于 8 项按自然顺序排列。托盘等跨对象菜单使用自己的分组（见 5.9），不受对象五组约束。溢出兜底名统一为「其余操作」，不得使用「更多」。

**依据**：Shadowrocket 的菜单之所以不显乱，不在于项少，而在于每组只做一类事、名字说清后果、危险项隔离（[U07](ui-benchmark-research.md)）。Mlash 当前订阅菜单 15 个动作只有 3 处分隔、托盘 14 项仅 2 处分隔，属于「功能收纳了但没组织」。

**可验证**：任一菜单按五组顺序排列、每组 ≤ 5 项、整单 ≤ 15 项；菜单内无同名项；危险项在最后且与上组分隔；分组名与项名符合[命名规则](#命名规则)。

## 第 2.5 层：三目标冲突的逐页审视

P0 给出分工原则后，用实际数据检查每个页面是否满足首屏指标：首页控制区 ≤ 6 个控件（列表不计），其余页 ≤ 12 个控件。统计来自当前实现，目标为设计值。**本表按现有八页审视**（设置尚未拆分分类，首页与节点按合并后的目标统计），与第 4 层「逐页布局实例」的目标叶子不是同一层，行数不同属正常。

| 页面 | 当前控件数 | 首屏应保留 | 收纳去向 | 结论 |
|---|---|---|---|---|

### 三条具体裁决

**1. 首页六卡删除，不再保留可配置卡片。** 它们用 `i+1` 当页号（`MainWindowHome.cpp` 六卡循环体内 `setProperty("page", i+1)`，`:47/49/52/54/62`），本质是侧栏的第二份拷贝。

上一轮曾据 Clash Verge「9 卡任选」提出「默认 3 张 + 3 个复选项」。**该方案作废**：Clash Verge 的卡片是**它**的首页唯一内容，而我们的首页现在有控制区 + 节点列表（ADR 0048），再叠加卡片会与两者争夺首屏。卡片承担的「状态 / 当前订阅 / 当前节点」已由控制区三行原生表达，复选卡只是二份。流量、连接、规则命中的摘要归「数据」页，不进首页。

**2. 设置 29 项全部保留，但不同时呈现。** 当前三分类已经存在（`settingsCategories`），问题是分类切换后仍是一长列。方案：每个分类独立滚动 + 搜索常驻 + 组内折叠低频组（如「高级内核」默认收起）。这是 Shadowrocket 的做法——设置项一个不少，但一屏只看到当前分类。

**3. 节点列表的工具带与提交条重定义。** 原节点页底部同时有当前成员、进度、取消、计数、定位、进入、切换（`MainWindowProxy.cpp:82-86`）。合并进首页后：

- **取消提交条**：单击成员即生效（手动组），没有「切换」按钮。
- **保留工具带**：搜索、排序、测速、筛选 —— 与列表同排，可换行。
- **进度与取消**只在测速时出现。
- **定位与进入**（组标题旁）在分组视图里保留为图标按钮。
- **底部**只留一行轻量摘要（已选 N 个 · 当前成员 · 上次测速时间），不设动作。

## 第 3 层：UI 分类

### 页面类型

页面类型只描述**主视图**；一个页面可包含多个页内视图（分段切换）。

| 类型 | 定义 | 页面 | 主视图 | 提交条 |
|---|---|---|---|---|
| **控制+列表页（首页）** | 回答「我现在是否在被代理，下一步做什么」并直接换节点 | 首页（无页签） | 控制区三行 + 节点标题行 + 节点行列表 + inline-stat | 无（单击即生效；主控件在控制区） |
| **对象列表页** | 浏览并操作同一类对象 | 订阅、连接 | 列表 | 有选中对象时才有 |
| **流视图页** | 只读、不可选择、持续追加 | 日志 | 文本流 + 过滤 | 无 |
| **编辑页** | 维护配置，多步骤 | 规则 | 编辑区（列表/文本分段） | 固定保存栏 |
| **任务页** | 执行一次可观察的任务 | 网站测试 | 结果网格 | 无（结果摘要条代替） |
| **设置页** | 调整偏好 | 设置（三分类） | 分组行 | 仅重启类改动时出现 |

首页节点区**不是**一个「对象列表页」：它没有提交条，单击即生效（手动组），规则见第 2 层 P4 例外表与 [ADR 0048](adr/0048-home-merged-proxy-switch.md)。「对象列表页」的「有选中对象时才出现提交条」不适用于首页。

### 页内视图类型

| 类型 | 说明 | 实例 |
|---|---|---|
| 列表 | 可选择、可排序 | 规则优先列表、连接活动/已结束 |
| 编辑 | 可写、有草稿 | 规则文本编辑 |
| 只读 | 只读快照 | 内核实际规则 |
| 流 | 追加、不可选择 | 日志 |

页内视图用**页内分段控件**切换，不改变路由（见第 1 层「页签层级分离」）。

### 容器类型

| 类型 | 用途 | 实例 |
|---|---|---|
| 分组 | 同类别行的容器 | 设置分类内各组、「备份与工具」内各任务组 |
| 卡片网格 | 等宽卡片流式排列 | 网站测试目标、节点卡片 |
| 工具窗口 | 单对象配置 | 见窗口类型 |

「备份与工具」是**设置页的第三个分类**，其内部用「分组 + 任务行」容器，不是独立页面类型。

### 窗口类型

| 类型 | 用途 | 规则 | 实例 |
|---|---|---|---|
| **工具窗口** | 配置单个对象 | 非模态，按（工具, 对象）复用，关闭即取消未提交编辑 | TUN、DNS、快捷键、节点定义、Provider、代理链 |
| **模态管理窗口** | 长流程且必须在主窗口内完成的操作 | 模态，阻塞主窗口，有未提交改动时确认；内部可多步 | 批量更新的失败明细、备份恢复的预览与选填项 |
| **确认对话框** | 有不可逆后果的单步确认 | 模态，说明后果与范围，只有「取消 / 确认」 | 删除订阅、断开全部、覆盖式恢复 |
| **预览/详情窗口** | 只读快照 | 打开时快照，不跟随刷新 | 配置预览、网站结果详情、出口证据 |
| **浮层/通知** | 轻量、瞬态 | 不承载必要信息 | 设置搜索、筛选面板、托盘气泡 |

### 反馈类型

见第 2 层 [P4.1 反馈路由](#p41-反馈路由)：六类反馈已给出承载位置、生命周期与触发源，并附逐条映射要求。

### 控件分类

| 类别 | 成员 | 规则 |
|---|---|---|
| 主导航 | 侧栏项、分区页签 | 选中实心，改变路由 |
| 页内分段 | 活动/已结束、列表/文本 | 只切换页内视图，不改变路由 |
| 上下文 | 订阅选择、策略组、筛选 | 改变浏览范围；**必须在提交条或动作文案中回显目标** |
| 工具 | 搜索、排序、视图切换、重测 | 只影响呈现 |
| 提交 | 使用、应用、保存、启动 | 唯一写入口，明确文案 |
| 工具带 | 详情、复制、断开、导出 | 作用于选中对象 |

**危险**不是独立类别，而是可叠加在提交与工具带上的修饰角色（红色 + 确认）。判定门槛是**不可逆**：执行后无法从界面回到执行前状态（删除、重置）。可逆的切换类动作（回滚运行版本、断开连接、清除筛选）不叠加危险，即使它们改变当前运行状态。

**但「批量」是独立的第二条门槛**：一次作用到多个对象的动作即使用户可以重连，也必须先确认——断开单条连接是即时动作，断开全部必须弹确认；断开全部因此不染红色（连接会重建，不是删除），但**必须确认**，且不以行内按钮直接执行。

### 收纳层级

P0 的三目标分工需要一套统一的收纳机制，否则每页各自决定「什么收起」，最终又回到混乱。**任何功能必须且只能位于以下四级之一**：

| 级别 | 可见性 | 适用 | 入口 | 现有例子 |
|---|---|---|---|---|
| **L0 常驻** | 首屏直接可见 | 状态结论、当前对象、下一步动作、主提交 | 无 | 代理总开关、当前成员、节点切换 |
| **L1 工具条** | 首屏可见，与内容同排 | 高频但不主打的动作（搜索、排序、视图） | 无 | 搜索框、排序下拉、表格/卡片切换 |
| **L2 抽屉/溢出菜单** | 同页内一次点击展开 | 中频动作、多选、次要设置 | 「更多」「筛选」「管理」按钮 | 筛选面板、订阅管理菜单、其余操作、节点/订阅详情抽屉 |
| **L3 工具窗口/设置分类** | 跨页或窗口 | 低频、长流程、需要预览或确认 | 设置行、工具窗口、菜单项 | TUN 管理、备份恢复、Provider 编辑 |

判定规则：

- 每日使用的动作 → L0 或 L1，**禁止**下沉到 L2 以下。
- 每次启动才用一次的动作（备份、内核切换）→ L3。
- 同一对象超过 4 个动作时，保留 1 个主要 + 其余进 L2。
- L2 与 L3 的入口必须**始终可见**，不得只在特定状态下出现；入口本身可以标注数量（「筛选 2」）。

**违反检测**：若某功能既不在四级的任何一级、又没有被删除，说明它的位置是随机的。当前「首页六卡」（纯重复导航）与「计算后隐藏的标签」都属于此类。

## 第 4 层：容器布局

### 统一页面骨架

所有页面共用同一垂直骨架，顺序固定：

```
┌──────────────────────────────────────────┐
│ 页签行：分区页签（左）＋页面级动作（右）  │  ← 固定，内容区第一行（首页无此行）
├──────────────────────────────────────────┤
│ 上下文条（可选）：当前对象/范围           │  ← 固定
├──────────────────────────────────────────┤
│ 工具条（可选）：搜索、排序、视图、页内分段 │  ← 固定，可换行
├──────────────────────────────────────────┤
│ 主内容区（列表/编辑/卡片/状态块）         │  ← 占据剩余，可滚动
├──────────────────────────────────────────┤
│ 结果摘要条（可选）：进度、统计、提示      │  ← 固定
├──────────────────────────────────────────┤
│ 提交条（可选）：目标回显 + 主/次动作      │  ← 固定
└──────────────────────────────────────────┘
```

约束：

- **不设页面标题**：分区名由侧栏选中态表达，视图名由页签选中态表达，二者都不再重复成文字标题。页面级动作与页签同排右对齐。
- **首页没有页签行**（[ADR 0048](adr/0048-home-merged-proxy-switch.md)）：它的骨架从控制区直接开始，页面级动作并入控制区第三行右侧。这是唯一例外。
- 页签行、上下文条、工具条、提交条与主内容**同宽同左缘**；只有主内容区可滚动。设置页的 760 单列改为列容器宽度 token，与其它行落在同一列内。
- 同一页面**同屏只有一个滚动主体**：列表/文本框自身的滚动不算页面滚动，但同屏不得出现两个。首页的控制区与节点列表**共用一个页面滚动**（控制区滚出视野后列表继续），不是两个独立滚动区。
- 提交条固定底部，滚动内容不改变其位置；提交条必须回显当前目标（如「使用并启动 · 订阅 A」）。
- 关闭窗口或离开页面时，未失焦的编辑先提交或提示保留草稿。

**关于不设标题的取舍**：去掉标题减少了顶部两行文字与一处层级竞争，但也让「我在哪」只能依赖侧栏与页签的选中态。为避免识别性下降，要求：

1. 页签必须始终可见（即使分区只有一个视图也保留页签，以承载视图名）——首页除外，它由控制区第一行的状态句承担识别。
2. 侧栏选中态用实心填充，不得退化为仅换文字颜色。
3. 窗口标题栏显示「Mlash · 当前视图名」，供任务栏与 Alt+Tab 识别。
4. 设置页的视图名由三分类页签承载，不再额外渲染「设置」二字。

### 各类型页面骨架

| 类型 | 页签行 | 上下文条 | 工具条 | 主内容 | 结果摘要条 | 提交条 |
|---|---|---|---|---|---|---|
| 控制+列表页（首页） | **无** | 并入控制区（当前代理行） | 并入列表区（搜索、排序、测速、筛选） | 控制区三行 → 节点与策略组列表 | 仅测速进行中显示进度，不常驻 | 无（单击即生效） |
| 对象列表页 | 有 | 有（对象范围） | 有 | 列表（表格或卡片） | 无 | 有选中对象时 |
| 流视图页 | 有 | 无 | 有（级别/搜索/跟随） | 文本流 | 有（采样时间、暂停状态） | 无 |
| 编辑页 | 有 | 有 | 有（页内分段：列表/文本） | 编辑区 | 有（草稿状态/校验） | 有（固定保存） |
| 任务页 | 有 | 有（测试对象） | 有（开始/停止） | 结果网格 | 有（进度、上次结果、下一步） | 无 |
| 设置页 | 有（三分类） | 无 | 有（搜索） | 分组行 | 有（应用结果） | 仅重启类改动时出现 |

补充规则：

- 日志页的导出与目录合并在工具条内一处，不重复出现。
- 日志的「回到最新」使用浮层位置，不占骨架行。
- 订阅页的对象动作条迁到提交条，与节点/连接一致。
- 网站测试的「前往首页」改为直接执行下一步（启动内核或添加订阅），文案写动作而非目的地。**现状仍 `emit pageRequested(0)`，属 R4 的改动项。**

### 逐页布局实例

骨架只规定顺序，不规定每页放什么。以下是**5 个视图**的具体分配（首页一行；配置两行——订阅与规则；数据一行含四个页签；设置一行含三组），实施时不得自行增减行；结构冲突时以[结构裁决表](#结构裁决表)为准。K 版起分区页签行由固定顶栏（标题 + 副标题 + 状态胶囊 + 主题/更多）取代，下表「页签行右」一列读作「该屏标题行右侧」。

| 页面 | 页签行右 | 上下文条 | 工具条 | 主内容 | 结果摘要 | 提交条 | 收纳入口 |
|---|---|---|---|---|---|---|---|
| **首页** | 无（顶栏只有主题与更多） | 节点标题行内的订阅 chip | 搜索 · 测速 · 排序 · 「其余操作」 | 控制区三行（当前代理/路由方式/连通性）→ 节点行列表 → inline-stat | 仅测速进行中显示进度，不常驻 | 无（单击即生效） | 「其余操作」：恢复自动、最近选择、节点选项、筛选 |
| **订阅** | 添加订阅 · 导入文件 · 更新全部 | 无 | 搜索 · 更新所选（多选时启用） | 远程订阅列表 + 本地配置列表（一行一条，76px） | 批量结果 | 抽屉内「设为当前配置」 | 行尾 › / 双击打开详情抽屉；对象动作并入「更多操作」 |
| **规则** | 完整规则编辑 | 订阅选择 | 页内分段（优先规则 / 内核实际规则）· 搜索 | 规则列表 | 草稿状态 / 校验错误 | 保存 | 规则源 |
| **数据** | 复制诊断摘要 | 无 | 页签「流量」：无；「连接」：页内分段 + 搜索 + 列与视图 + 暂停；「测试」：开始/停止；「日志」：级别 + 搜索 + 跟随 | 四个页签各自的内容 | 各页签自带 | 仅「连接」有「断开选中」 | 各页签原有的列面板、日志选项等 |
| **设置** | 无（顶栏只有主题与更多） | 无 | 无 | 通用 / 网络 / 内核与维护三张卡片，组内 52px 行 | 应用结果 | 组末「应用网络设置 / 放弃修改」，仅重启类改动时出现 | 无（三组同屏平铺） |

**首页是唯一无页签的页面**：控制区三行 + 节点列表共用一次页面滚动；控制区之后仍须能看到若干节点行（840×560、100% 文字下至少 3 行）。指标、探测间隔与内核路径都不在首页——K 版把「更多运行信息」抽屉删除后，流量与出口摘要在「数据 › 流量」，内核与接管明细在设置与托盘。这是 Shadowrocket 实测结构与 GPT 原型共同给出的结论：不得因为「指标很重要」而放回首屏。

**日志页不设提交条**：它没有可选中对象，导出与清空属于工具条动作。

### 列表容器规则

- 表格与卡片视图共享同一数据、选择、滚动语义；切换视图不丢失选择。
- 行高由密度 token 决定（数据 32 / 表单 48），不在页面里硬编码；卡片最小高另由 `card-min` token 决定。
- 空态占据列表区域，文案说明原因与下一步，不显示空表格。
- 每个列表登记选择模型，且必须与 Controller 命令一致：节点（单选 + 单击即生效，仅手动组）、订阅（**多选** + 批量更新，`updateProfilesBatch`）、连接（**单选** + 提交条，Controller 只有 `closeConnection(id)`）、日志（无选择）、规则（单选 + 编辑）。

### 分组容器规则

- 分组用**留白与次级表面**区分，不依赖边框。
- 组内行之间用 hairline 分隔；组与组之间只用间距。
- 可交互容器（可点击卡片、输入框）才使用边框。

| 级别 | 形态 | 布局约束 | 关闭/返回 |

### 状态呈现规格

每个数据区域（列表、卡片网格、详情、状态块）必须能表达下列**十种**状态，且**同一状态在所有页面用同一套结构与文案模式**。缺一种就会让用户看到空白或旧数据而不自知。后三种（暂停/冻结、进行中、外部管理/未确认）容易被忽略，但分别对应「冻结快照」「写操作在跑」「被别的程序接管」三种真实情形。

| 状态 | 结构 | 文案模式 | 必须包含 | 禁止 |
|---|---|---|---|---|
| **空（无对象）** | 居中图标 + 一句原因 + 一个动作 | 「还没有 X」+ 动作 | 原因、下一步动作 | 空表格、空卡片、仅「暂无数据」 |
| **空（有对象但无匹配）** | 同上，动作改为「清除筛选」 | 「没有匹配的 X」 | 当前筛选条件 | 建议新增对象（应引导清筛选） |
| **加载中** | 骨架行或「读取中…」+ 可选取消 | 「正在读取 X…」 | 已知进度或可取消 | 转圈遮住整个页面 |
| **成功无内容** | 同「空（无对象）」 | 「X 已就绪，暂无 Y」 | 区分「已就绪」与「未就绪」 | 把就绪当成有内容 |
| **失败** | 就地错误行 + 原因 + 重试/查看日志 | 「读取 X 失败：<原因>」 | 原因、重试入口 | 只写「失败」、把错误塞进状态栏 |
| **过期/未刷新** | 数据显示 + 时间戳 + 「已过期」标记 | 「<时间> 的数据 · 可能已过期」 | 采样时间 | 用旧值冒充当前值 |
| **未就绪** | 说明缺什么 + 下一步动作 | 「内核未就绪」/「请先选择订阅」 | 具体缺项 | 空表格 + 「前往首页」 |
| **暂停/冻结** | 数据保持 + 暂停标记 + 时间戳 | 「已暂停 · <时间> 的快照」 | 恢复入口 | 暂停后继续刷新 |
| **进行中（写/测）** | 触发控件旁进度 + 可取消 | 「正在保存…」/「测试中 3/12」 | 取消入口 | 禁用整个页面 |
| **外部管理/未确认** | 状态句 + 原因 + 前往处理 | 「外部程序管理」/「— 未确认」 | 处理入口 | 显示为「已关闭」 |

**通用约束**：

- 未知一律显示「—」，不填 0、不沿用旧成功值。
- 状态之间可共存：列表已加载但刷新失败 → 显示旧数据 + 过期标记 + 错误行，**不要清空列表**。
- 空态与失败态必须有可聚焦的动作按钮，供键盘用户使用。**现有 `emptyState()` 只创建带 `WA_TransparentForMouseEvents` 的 `QLabel`（`MainWindowParts.h:136-139`），必须重写为「图标 + 原因 + 动作按钮」组件**（见 R7）。
- **区域豁免**：状态块、纯文本流、短列表（<3 行）只需「正常/加载/失败/未就绪」四态，不强制十态。
- 同一页面内多个区域的状态不得互相冒充（如「内核就绪」不等于「连接有数据」）。
- **首页控制区的「当前代理」行同时是一处状态区域**：它用一行状态句表达内核、接管、节点三件事各自的结果，不得合并成单一「已连接」（[ADR 0048](adr/0048-home-merged-proxy-switch.md)）。

**验收**：逐页检查十种状态是否都有实现与截图；用隔离平台注入失败/空/过期数据验证。

### 默认密度

三目标中的「极简呈现」由密度保证，而不是由减少功能保证：

- 默认一行只表达一件事，不把状态、说明、动作塞进同一行。
- 次要说明默认省略，保留在提示与无障碍描述中。
- 空态只显示一句原因 + 一个动作，不显示空表与空卡片。
- 页面内不使用装饰性图标；图标只用于识别对象或指示可展开。

### 工具窗口骨架

```
标题 | 说明（可选）
─────────────────────
内容（可滚动）
─────────────────────
反馈文本
[取消] [主要动作]
```

**生命周期契约**：

| 事项 | 规则 |
|---|---|
| 复用键 | （工具, 对象 ID）；同一键再次打开时 raise 已有实例 |
| 对象消失 | 订阅/节点被删除或切换数据源时自动关闭 |
| 页面切换 | 非模态工具窗口保留并 raise；预览/详情窗口关闭 |

| 关闭时未提交编辑 | 窗口「关闭」= 放弃未提交编辑并直接关闭，**不询问**；「取消」= 有改动时先询问。二者不得同时出现在同一窗口（见下方统一要求） |
| 破坏性流程 | 升级为模态管理窗口或确认对话框 |

| **详情/预检**（非模态） | CoreUpdateDialog、ProfileChangesDialog、ConnectionDetailsDialog、OutboundDialog | 「<对象> · 预检」/「· 详情」/「· 快照」 | 预检窗口：主「应用」（未通过时禁用）；详情窗口：只读或无破坏性动作 | 直接关闭；有写动作时须确认 |
| **导入**（模态，一次性） | ImportDialog | 随入口变化（「添加订阅」/「确认链接订阅」） | 主：导入；次：取消 | 有输入时询问 |

**内联窗口**（约 10 个，不在独立类中）：批量更新、节点源/规则源、订阅来源与维护、分享订阅、配置兼容性、节点选项、配置预览、节点链接导入/移除影响/新增定义、状态详情消息框。这些窗口必须遵守同一套「关闭语义与有未提交改动时询问」规则，不因未独立成类而豁免。

**统一要求**：

- 标题不得重复窗口内已有的大标题；标题只表达「对象 + 意图」。
- 「取消」在有改动时先询问，「关闭」不询问；同一窗口不得同时出现「关闭」和「取消」。**现状偏差**：`DialogDraftGuard` 在 `QEvent::Close` 时无条件询问，与本节相反；R6 需把 `DialogDraftGuard` 的挂接点从 `Close` 改到「取消/Esc」，窗口级 `closeEvent` 直接丢弃草稿。
- 预检类窗口必须有明确的「应用」按钮且默认禁用，直到预检通过。CoreUpdateDialog 的**目标行为**如此，实施前需逐路径核对 `updateActions()` 的禁用条件是否完整。
- 长流程窗口的**关闭按钮始终可用**（只隐藏窗口，不中止任务）；「取消/停止后续」才中止。二者语义不同，不得混用。

### 页面生命周期契约

现有 `setPage` 带页号副作用开关轮询（`MainWindow.cpp:489-506`）。改为统一导航后必须显式定义：

| 时机 | 页面 | 行为 |
|---|---|---|
| 进入 | 状态、节点 | 刷新运行状态，启动 8 秒轮询 |

| 轻量重建 | 全部 | 只恢复页面号与页内记忆，不恢复轮询 |

### 5.6b 菜单

菜单是 Mlash 收纳功能的主要容器。现有实现的问题是**分组不足与命名不稳**，不是「项太多」：

| 位置 | 直接动作数 | 分隔线 | 观察 |
|---|---|---|---|
| 订阅管理菜单 | 15（`MainWindowProfiles.cpp:33-69`） | 3 | 编辑类与危险类混排；「删除」与「回滚」相邻 |
| 托盘顶层 | 14（含 4 个子菜单，`TrayController.cpp:110-171`） | 2 | 运行控制、对象操作、页面入口平铺 |
| 设置页工具菜单 | 3 | 0 | 无分组 |

Shadowrocket 的菜单之所以不显乱，不在于项少，而在于**每组只做一类事**、**名字说清后果**、**危险项隔离**（[U07](ui-benchmark-research.md)）。

#### 分组规则

**适用范围**：直接动作 ≥ 8 项的菜单才强制分组；少于 8 项按自然顺序排列，不强行凑满五组。

对象菜单（订阅、节点等）按固定顺序分组，组间必须有分隔线；某组无内容时整组省略，不留空分隔。

| 序 | 组 | 内容 | 为什么在这 |
|---|---|---|---|
| 1 | 当前对象 | 名称、状态、来源等**只读信息** | 先让人确认在对哪个对象操作 |
| 2 | 常用动作 | 该对象最高频的 2–4 个动作 | 与工具带一致 |
| 3 | 编辑与配置 | 打开子编辑器（节点、DNS、来源…） | 低频但需要入口 |
| 4 | 文件与目录 | 打开所在目录、导出、复制路径 | 与系统交互，语义独立 |
| 5 | 危险动作 | 不可逆的动作（删除、重置） | **永远最后，且与上一组强制分隔** |

**规模上限**：单组 ≤ 5 项；整单 ≤ 15 项。超出时把第 3 组收为子菜单，**不新增一级项**。

**跨对象菜单**（托盘）不适用对象五组，按「窗口 / 代理与 TUN / 运行控制 / 订阅 / 页面 / 退出」六组排列，规则见 5.9。

#### 命名规则

| 规则 | 正例 | 反例 | 说明 |
|---|---|---|---|
| 动词开头 | 「更新订阅」「打开目录」 | 「订阅更新」 | 菜单项是一个动作，不是名词 |
| 会弹窗才加省略号 | 「重命名…」「DNS 设置…」 | 「更新订阅…」 | 省略号 = 还需要输入；直接执行则不加 |
| 不带技术缩写 | 「节点来源」 | 「节点源（Provider）…」 | 括号注英文是补丁，不是命名 |
| 危险项含宾语 | 「删除订阅…」 | 「删除」 | 单独看也要知道删的是什么 |
| 同名项加限定 | 「更新当前订阅」 vs 「更新全部订阅」 | 两个都叫「更新」 | 菜单内不得有同名项 |
| 不使用「更多」作分组名 | 「其余操作」 | 「更多页面」 | 无信息量的分组名等于没分组；「其余操作」是唯一的兜底名 |

**动态标签例外**：「同名同位置」约束的是**动作身份**，不是文案。像「使用并启动 / 应用更新」「恢复自动选择 / 自动选择中」这类随状态变化的项，视为同一动作，位置固定、文案可变。

**P12 与本节的边界**：子菜单只用于**同类枚举**（打开子编辑器、选择订阅），不得用于「两层菜单再进对话框」的连续钻取。第 3 组的「编辑配置 ▸」成员是对话框，属 P12 允许的「行 → 子菜单 → 对话框」两跳，不构成第三层。

当前 15 个直接动作（`MainWindowProfiles.cpp:33-69`）。按规则重排为**五组、一级项 13 个**（只读头不计）：

```
<订阅名> · <运行状态>                    ← 只读头，禁用态
─────────
更新当前订阅
重新加载当前版本
回滚上次运行版本
─────────
编辑配置 ▸
    编辑节点与策略组…
    节点来源…
    DNS 设置…
    上游代理链…
─────────

来源与更新…
配置兼容性…
─────────
分享订阅二维码…
上移
下移
更换文件…
打开数据目录
─────────

```

| 组 | 项数 | 说明 |
|---|---|---|
| 只读头 | 0（不计） | 让用户确认对象 |
| 常用动作 | 3 | 更新、重载、回滚到上次良好版本 |

| 对象维护 | 3 | 改名、来源、兼容性 |
| 文件与目录 | 5 | 分享、排序、换文件、打开目录 |
| 危险动作 | 1 | 删除 |

一级项 13 个、六段（含只读头）、每组 ≤5、整单 ≤15，符合规则。「使用并启动 / 应用更新」是页面提交条按钮，不进菜单（避免与页面主按钮重复）。「查看变化」是页面工具条按钮，不进菜单。

**「回滚上次运行版本」不在危险组。** 它调用 `activateProfile(id, lastGood=true)`（`AppController.cpp:233-241`），语义是**切换**到上次良好版本，不删除任何数据，且可再次切回（`activateProfile(id, false)` 激活候选版本）。危险组要求「不可逆 + 需确认」，回滚两条都不满足；把它染红会让真正的危险项（删除）失去区分度。因此该项归入「常用动作」组，位于「重新加载当前版本」之后；文案保留宾语「回滚上次运行版本」，并在菜单项提示中说明「切换运行版本，不删除数据」。

### 5.9 托盘

托盘的定位经调研校正：**它不是「第二套导航」，而是「把高频动作从窗口里拿走」**——Shadowrocket 桌面版的唯一界面级机制（官方更新日志：菜单栏路由控制 + 快捷服务器配置，见 [U07](ui-benchmark-research.md)）。

现有托盘顶层 14 项、含 4 个子菜单（`TrayController.cpp:110-171`），页面入口分散在「节点/连接/更多页面/设置」。按跨对象分组重排：

```
显示主窗口
─────────
开启代理 / 关闭代理
系统代理  ✔
TUN 模式  ✔
─────────
路由模式 ▸        规则 / 全局 / 直连
策略组 ▸          <组> → 成员 + 测试延迟
─────────
订阅 ▸            <订阅> → 更新当前订阅 / 打开订阅页
─────────
连接页…
设置…
─────────
退出 Mlash
```

| 组 | 项数 | 说明 |
|---|---|---|
| 窗口 | 1 | |
| 代理 | 3 | 总开关（与首页同一命令与确认）+ 系统代理 + TUN |
| 运行控制 | 2 个子菜单 + 1 项 | 路由模式、策略组、**启动内核 / 停止内核**（K5 后这是内核单独启停的唯一常驻入口；受 busy/readOnly/无活动订阅约束，按状态只显示其一） |
| 订阅 | 1 个子菜单 | |
| 页面 | 2 | **从 7 个降为 2 个**：连接、设置；首页即「显示主窗口」，订阅从子菜单进 |
| 退出 | 1 | |

托盘按跨对象六组排列，**不受 P14「直接动作 ≥8 项才强制分组」的下限约束**——该门槛是下限，不是「少于 8 项不得分组」。顶层 11 项、6 组，符合 ≤15。**「更多页面」删除**——它是无信息量的分组名。其原有内容去向：订阅管理 → 订阅子菜单；**网站测试、规则、日志只保留侧栏入口，不在托盘重复**（托盘是「把动作拿走」，不是第二套导航）。**节点不再单独占一个托盘入口**：策略组子菜单已经承担「不打开窗口换节点」，这是它应有的位置。

**约束**：

- 托盘只承载**动作与状态**，不镜像完整页面列表。
- 切换系统代理必须复用主窗口的同一确认路径（含外部代理接管确认），不得绕过——现有单击路径（`TrayController.cpp:52`）直接 `setSystemProxy`，需改。
- 失败气泡：仅当主窗口不可见时弹出，避免与状态栏重复。

### 6.3 应用规则

1. **层级靠表面抬升，不靠边框**。三级表面：`canvas` → `surface` → `popupSurface`，深色逐级变亮;边框只给可交互容器与浮层。
2. **交互状态用「色相分离 + 结构信号」，不用亮度阶梯**。经实算，同一色相的叠色在合理 alpha 范围内无法产生可辨的亮度差（accent 叠 30% 时浅色仅 1.58、深色 1.31），继续加深会让表面发脏。因此改为：

   本节**重新定义** `hoverFill` 与 `selectionFill` 的取值，U05 表中对应行的旧值作废：

   | token | 浅色 | 深色 | 说明 |
   |---|---|---|---|
   | `hoverFill` | `#EAEAEF` | `#36363B` | 中性灰，只表达「指针在此」 |
   | `selectionFill` | `#D6E4F7` | `#1E3350` | accent 调，配合竖条 |
   | `selectionBar` | `#0057B8` | `#7DB4FF` | 2px，对选中底 5.33 / 5.99 |
   | `pressedFill` | `#DFDFE6` | `#45454B` | 对各自的悬停底：浅 1.11 / 深 1.26（深色对新 `hoverFill #36363B` 实算 1.2622；旧值 1.09 对应旧 `hoverFill`，作废） |

   - 选中与悬停的亮度比只有 1.07，但**色相不同**，配合竖条形成双重通道——这是 macOS 列表的做法。
   - **禁止**用单一背景亮度区分选中与悬停。
   - **浮层例外**：`popupSurface` 深色为 `#36363B`，与 `hoverFill` 深色相同，会导致菜单悬停不可见。浮层内改用 `popupHover` 深色 `#4A4A50`（对浮层底 1.37），浅色 `#EFEFF3`（对浮层底 1.15）。
3. **高对比是第四套平行 token**（浅/深 × 普通/高对比，与 `applyAppearance(scheme, highContrast)` 的二维参数一致）。不只加深边框，选中、控件填充、轨道、焦点同时增强。注意 HC 已知弱于普通模式（见 6.3b），必须单独验证。**本层只规定存在与验证要求，不给 HC 取值**：U05 的 HC 列中 `canvas` 与 `surface` 同值（浅 `#FFFFFF`、深 `#000000`），规则 1 的「逐级变亮」在 HC 下不成立，必须先在 R9 内单独补四级表面取值与逐对复算，再写 `ThemeTokens` 的四实例。该项**不阻断 R1–R8**。
4. **字号七档、间距 8pt、圆角三级 + pill**（`sm` 6 / `md` 8 / `lg` 12，`pill` 只用于开关轨道、滚动条手柄与进度条）。页面代码禁止字面量。
5. **几何随文字比例缩放**，覆盖 90–120%；给出最小字号 9pt 与最小行高 16px 下限，低于下限不再缩放。
6. **状态多通道**。形状 + 颜色 + 文本，不只靠色相。
7. **硬编码清零**。经逐处核对，真正的字面色值与内联样式共 8 处（`QColor(UiTheme::X)` 属正确用法，不在此列）：

### 6.4 第 5 层的尺寸声明

第 5 层的控件尺寸直接引用 token，不写死值。以下现有硬编码将被替换，需计入迁移成本：`ProxySwitch` 38×20 → `switch-track` 42×24；图标按钮 26 → `icon-hit` 28；网站卡最小高 108 → `card-min`；组面板固定 110 → 内容驱动。

**技术路径**（先于数值）：

1. token 以 `struct ThemeTokens { int controlMd; int rowForm; …; QColor canvas; … }` 持有，**四个实例**：`light` / `dark` / `hcLight` / `hcDark`。
2. `styleSheet()` 从 token 生成，不做字符串替换——现有 `@Token` 替换存在前缀冲突风险（`@Control` 是 `@ControlFill` 的前缀），扩大 token 数量后必然出错。
3. C++ 侧固定尺寸（`setFixedWidth(SidebarWidth)`、`ProxySwitch::sizeHint`、卡片网格 220/54）改为读 token，不保留常量。
4. `QPalette` 从同一 token 派生，`QPalette::PlaceholderText` 当前错误映射到 `Secondary`（`UiTheme.cpp:62`），迁移时改 `textPlaceholder`。

**缩放公式与取整规则**：

```
value = qRound(base * textScale / 100.0)   // 四舍五入，不额外取偶
```

| token | 90% | 100% | 110% | 120% |
|---|---|---|---|---|
| `control-sm` | 22 | 24 | 26 | 29 |
| `control-md` | 27 | 30 | 33 | 36 |
| `control-lg` | 32 | 36 | 40 | 43 |
| `row-data` | 29 | 32 | 35 | 38 |
| `row-form` | 43 | 48 | 53 | 58 |
| `icon-hit` | 25 | 28 | 31 | 34 |
| `statusbar` | 31 | 34 | 37 | 41 |
| `switch-track` | 38×22 | 42×24 | 46×26 | 50×29 |
| `row-menu` | 25 | 28 | 31 | 34 |

以上四档全部由公式算出，可直接验算。

**不缩放的两项**：

- **侧栏宽度 172**：120% 下四个两字分区名加图标约需 81px，侧栏内宽 148px，余量充足。侧栏**项的 padding 与图标随比例缩放**，总宽由内边距吸收。
- **图标尺寸**取最近档（16/20/24），不连续缩放；描边随档位调整（16px 用 1.25、24px 用 1.5），避免小图标描边过粗。

侧栏宽度不缩放——分区名短，缩放会挤压内容区。图标尺寸随比例取最近档（16/20/24），不做连续缩放。

**接口签名**（R1 前置）：

```cpp
enum class HomeAnchor { Control = 0, Nodes = 1 };
struct Route { int view; int category = -1; HomeAnchor anchor = HomeAnchor::Control; };
Route fromLegacyPage(int page);   // 0 → {0, kNoCategory, Control}；2 → {0, kNoCategory, Nodes}；
                                  // 6 → {6, 0}（启动页/托盘选「设置」固定落常规，不恢复上次分类）；其余 → {page, kNoCategory, Control}
bool isRoutableView(const Route& route);  // 合法视图集合，GuiHost 与 navigate 共用
int toLegacyPage(const Route& route);     // 回显用入口 ID：首页 Nodes → 2，否则 view
void navigate(Route route);       // 唯一切换入口；category < 0 表示沿用当前设置分类
Route currentRoute() const;
```

**锚点与「页内定位」是两件事**：`Route.anchor` 是路由级锚点（只有首页的节点首行），`SettingsSearch::anchorRequested(QWidget*)` 是设置页内的控件定位，R1 只改前者，不动后者。

`GuiHost` 保存 `Route` 而非 `int`；`startupPage` 仍为 0–7，读取时经 `fromLegacyPage` 转换，不迁移数据。

**0/2 归一化（R1 写死的三条语义）**：

1. **索引 2 的控件实例保留到 R3 才删除**。ADR 0048 与本文此前一版曾写「R1 删除索引 2」，实施勘查后**改为 R3**：节点区（`proxyGroups`/`nodesTable`/`nodeCards`/`nodeContent`）由 `proxyPage()` 创建，R1 就删掉它会让「换节点」这一最高频任务在两片之间完全不可用，并把 `QualificationRun` 的节点测量一起打断——这不是「一片可独立运行、可回滚」。R1 只做路由归一化，R3 合并首页时连同索引 2 的控件一起删除。
2. **`navigate({home, anchor})`：R1 落到索引 2（同一视图的节点入口），R3 起一律落到索引 0 并滚动到节点列表首行**（仅在控件已布局后执行，用 `QTimer::singleShot(0)`）。R1 里 `applyHomeAnchor` 的可见效果是定位到节点区当前成员行。
3. **`MainWindow::page()` 返回入口 ID 供侧栏与页签回显**：实现为 `toLegacyPage(route_)`——从启动页 2 或托盘「节点」进入返回 2，从侧栏「首页」进入返回 0；`currentRoute()` 才是权威。轻量重建由 `GuiHost` 保存的 `Route` 恢复，`anchor` 一并恢复，因此「启动页 2 重建后仍落在节点入口」成立。

**`GuiHost` 与路由校验**：`page < 8` 的硬编码改为 `Route` 合法性校验（`view ∈ {0,1,3,4,5,6,7}` 或 `view == 0 && anchor ∈ {Control, Nodes}`），**不是**「路由模型条目数」——条目数 10 仍会放行 0–7 之外的非法组合。
