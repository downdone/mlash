# ADR 0044：设置即时生效、内核历史与设置页标题统一

2026-10-29 · 接受。替代 ADR 0042 中“设置固定草稿/还原/应用栏”的交互决定与 ADR 0033 中“只保留上一次内核”的回退边界；分组布局、平台排版、内核预检/独立副本和写前恢复继续有效。

## 原因

设置页审视与用户反馈发现四处与预期不一致：

1. 设置页保留独立“设置”大标题，而首页/配置/数据分区把标题位替换为常驻页签行，搜索框因此落在标题右侧另一条基线上，内容起点与其它页不一致。
2. 设置修改必须点击“应用设置”，并保留“还原修改”；用户明确要求修改后立即生效。
3. 设置分组内的下拉框与数字框在未聚焦时被滚轮误改，滚动页面会意外改变偏好。
4. 内核管理只有“上次内核”一档回退，`core-updates/` 实际最多保留 8 个副本，却没有历史列表可切换。

## 决定

**即时生效，分两类提交。** 纯偏好（登录启动、启动时隐藏窗口、启动内核、恢复代理开关、轻量关闭、启动页面、托盘单击、外观、文字大小、节点延迟测试地址）在用户改变控件时立即提交 `AppController::updateSettings`，失败时用户可见原因并把控件回滚到实际已保存值。需要内核安全重启的项（本地端口、日志等级、内核对文件、IPv6、统一延迟）保留显式“应用网络设置”动作，因为每次键入路径就重启内核不可接受；该按钮只在确有此类改动时出现。移除“还原修改”：即时提交后不存在可还原的全局草稿，未提交的重启类改动可用“放弃网络设置修改”回到已保存值。

**提交串行化。** 即时提交沿用 Controller 的 `begin()`/`busy` 串行约束；控件在操作期间保持可见但不可写，读者看到的永远是“已保存值或正在保存”。连续快速切换不排队覆盖：新提交在上一提交完成后按“当前控件值对比实际设置”重新计算差异，已合并的改动只提交一次。失败时再次刷新控件为实际值。

**设置页标题统一。** 设置分区与其它分区一致：页面标题位由分类页签行（常规 / 网络与内核 / 备份与工具）承载，搜索框与该行同排右对齐；不再渲染第二个“设置”标题。分区切换、页签数据与内容左缘和其他页面同一 `ContentInset`。

**内核历史。** 新增有界历史（`Settings::coreHistory`，最多 8 条，与 `core-updates/` 副本上限一致），每条记录 sha256、版本、字节数、路径、记录时间和来源（local / official / rollback / bundled）。应用内核、回退和官方下载应用时追加历史；同一 sha256 只保留最新一条。存储校验限制条数、字段类型、sha256 形态和路径长度；备份恢复沿用“当前版本保留、历史随设置迁移”的既有原则。清理未使用副本时，保留当前、上次以及全部历史在册副本，删除的副本同步从历史移除。内核管理窗口列出历史并支持“预检此版本 → 应用”，切换仍走预检、校验、事务和写前恢复，不直接改路径。

**滚轮防误触。** `CompactComboBox` 在未获得焦点且弹出层未展开时忽略滚轮事件并把它交还父级滚动区域；设置分组内的 `mixedPort` 数字框同样处理。获得焦点或已展开时滚轮与键盘照常工作。该规则统一由共用控件实现，避免各页重复。

## 验证边界

即时提交、控件回滚、重启类显式应用、标题行几何、历史列表切换与清理、滚轮防误触由隔离平台和本地夹具测试覆盖；窄窗、90–120% 文字、浅深色与高对比由 UI 复核测试覆盖。Windows 实机、人工读屏与正式发行资格未因此 ADR 获得验证。
