# 0027 按指定节点测试常见目标

2026-10-15 · 接受 · 补充原规格，不修改历史导航 ID。

用户希望在独立测速页对当前节点测试 YouTube、ChatGPT、Google、GitHub 等目标，以卡片呈现。页面关注指定出口到目标的响应延迟，不复用原有节点测速结果，不模拟服务解锁、速率或历史曲线。

## 决定

- 主导航/托盘新增“测速”，显示顺序为首页、订阅、代理、测速、规则、连接、日志、设置。旧页面内部 ID 0–6 与已保存启动页含义保持，测速追加为 7；启动页允许 0–7，仍用 itemData 持久化，不使用显示行号。
- 默认解析代理页所浏览组的 `now`，最多16层、去环，只解析 Selector/URLTest/Fallback，冻结为具体叶子。LoadBalance/Relay 等无法确定单出口时要求手选；不悄悄改用 DIRECT。用户可选择其他具体节点，DIRECT 显式标为直连；拒绝/Pass 不作为目标出口。
- AppController 拥有 WebsiteTests，会话最多24个目标、3个客户端在途请求，当前内置12个公开 HTTPS 地址。UI 通过命令执行整组/单卡测试、取消、清空；无自动周期采样、自定义目标或磁盘历史。
- 使用锁定 mihomo v1.19.32 的 `/proxies/{具体节点}/delay?url=…&timeout=5000`，客户端6秒截止；不调用组 delay、选择 PUT 或解除固定 DELETE。默认测试节点只影响本页，结果按节点和目标归属，不发 nodeDelay，不污染代理页/托盘的应用层缓存。
- 离页或隐藏取消未完成请求，保留已经完成的会话结果；关闭轻量 GUI 时清空，重建不自动测速。Controller 写操作、内核停止/切换、退出取消并清空；取消只 abort 自有 reply，代次和 QPointer 保护回调。
- 紧凑白色圆角卡片、自适应1–4列、每项测试/重测直达，真实状态为未测试/排队/测试中/已响应/超时或未响应/已取消。服务使用本地字母标记，无运行时图标下载、假曲线或虚构可用率；完成时间/脱敏原因在提示中。

## API 语义与限制

已核对锁定内核源码 `hub/route/proxies.go` 与 `adapter/adapter.go` 并用本地夹具验证。URLTest 对指定代理发 HEAD，遵循 TLS 校验、不跟随跳转；统一延迟可能发第二次 HEAD。接口只有 delay，没有目标 HTTP 状态；403/429 等也可能返回延迟，expected 参数不能可靠转成服务可用判定。因此页面只声称“已响应”，0ms 可以是有效测量，绝不显示“已解锁”或凭此判定账号/地区可用。

URLTest 会更新内核自身的该代理健康/延迟历史，自动组仍由内核策略处理；这里的“不主动切换”是没有选择写入，不保证禁止内核自动策略。取消客户端不代表已经开始的内核探测立即终止，最多继续至该次5秒上限。切换节点后旧代次不写回本页。

## 验证责任

独立 website_tests 覆盖有界调度、无效响应、0ms、单卡重测、跨节点清空、取消/销毁/迟到回调；真实内核+本地隧道验证指定出口、目标路径、403仍已响应和原组成员/PID保持。UI 覆盖导航映射、旧/新启动页、默认当前叶子、隐藏/离页/写优先取消、轻量释放，以及尺寸/DPI渲染。实际运行结果由 verification-report 唯一维护，不把夹具误写成公共站点可用或系统代理验收。
