# ADR 0021：节点优先布局与卡片延迟操作

2026-10-14，接受。用户指出策略组切换频率低，而节点区占比不足；要求借鉴 Clash 的展开组/节点卡片，以及延迟悬停和点击重测。

借鉴当前组展开的阅读顺序，保留紧凑订阅行和当前组标题，完整组列表默认折叠，点击“切换策略组”或 Ctrl+G 才展开。点击组或键盘回车确认后收起并将焦点返回节点；方向键在组列表中移动时不提前关闭。相比逐个常驻所有折叠组标题，该方案减少低频控件持续占用的空间和页面滚动，节点面板取得剩余高度。不增加整页与节点双重滚动。

表格/卡片仍共用原模型、排序/搜索、选择与命令。卡片行高收为 54px，仅保留位置图标、名称和延迟；类型、完整名称及错误继续在提示中，当前成员以粗体/边界和底部实际状态标明。

延迟拥有独立命中区域。空闲且内核就绪时悬停显示浅蓝背景/手形，点击调用 Controller.testNodes({name})；未测和失败也能重试，卡片 F5 保留选中成员测速入口。延迟按下/释放不进入列表选择或双击使用流程，忙碌时不发第二个请求。使用持久索引确认释放仍命中同一节点；排序、过滤、模型重置使目标改变时取消这次点击，不能测到另一张卡片。

继续异步、单写命令、手动测量；不添加自动测速、节点定位请求、逐卡片 QWidget 或持久化字段。单节点结果及取消沿用既有契约。原始规格不变；本决策调整 ADR 0019/0020 的常驻组区和卡片展示细节。
