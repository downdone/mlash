# ADR 0023：托盘具体策略组按需测速

2026-10-14，接受。用户提出展开托盘具体策略组时自动测速，以便直接在托盘选择节点。

直接复用 GUI 批量命令会占 busy 并阻止成员切换，不符合托盘快速操作的预期。采用低优先级、独立 Controller 只读队列：具体组展开后停留 300ms 才触发，最多 500 个去重成员、三个客户端请求；排除内置直连/拒绝/Pass，只用单成员延迟接口，不解除自动组固定，不自动选择最低延迟节点。

菜单原地显示名称图标/未知/进行中/结果，错误仅就近呈现。使用单调时钟 60 秒和操作代次的有界内存缓存，复用 GUI 手测；本次启动可关闭自动触发，保留绕过缓存的重测入口，重测不关闭菜单，进行中拒绝追加。

关闭菜单/切组/主写命令/内核停止/退出，撤销客户端队列并仅 abort 自有请求句柄。旧回调不能更新新菜单或缓存；不能用 cancelAll 破坏成员选择/日志/其他 API。内核单节点测试使用后台 context，客户端取消不保证立即终止，已启动探测由 5 秒预算约束。自动测试不写持久化索引、不占 busy、不生成操作失败气泡，也不创建主窗口或周期性后台测速。

这是对既有仅手动测速原则的受限扩展：明确展开具体组属于按需观察，仍保留轻量、异步、写优先和实际状态分离。原始规格不修改；API 句柄与缓存契约进入 api-contracts/architecture，操作进入 ui-interactions，实际结果进入 verification-report。
