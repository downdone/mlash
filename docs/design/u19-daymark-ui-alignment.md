# U19：参照 Daymark 的界面精修

## 原则评审与边界

首页仍以“看清实际代理状态、选择节点、必要时测速”为主；配置承载订阅与候选，数据承载观察，设置承载偏好。保持四分区、AppController 唯一写入者、浏览与应用分离、节点名称与延迟独立命中。Daymark 是组件与视觉秩序参考，不移植任务产品的信息架构，也不引入 QML。

当前问题是有语义 token，却缺少贯穿导航、页面、行列表、菜单的组件几何和状态规则。首页节点标题及数量虽创建并更新，却被隐藏，操作工具孤立在列表之上；导航用整块主色，行列表每行永久显示同等权重的图标、次级信息及详情入口；组搜索将完整表单嵌入命令菜单。单独调整颜色或字号无法解决这些层级问题。

## 逐项对照与设计

| 项 | 采用规则 | 验收 |
|---|---|---|
| 导航 | 固定图标/标题列；柔和选中底与当前文字，主色仅用于选中图标和必要操作；悬停、键盘焦点分别表达，不改变尺寸。 | 四分区切换无文字/图标跳位，明暗与高对比可辨识。 |
| 首页框架 | 控制面、节点区、状态栏依次排列。节点区以“节点”作标题，浏览组是带文字的独立选择按钮，数量紧邻；搜索、测速、更多操作靠右。 | 840×560 仍可见控制区和至少三行节点，标题与列表不脱节，空态保持可见。 |
| 节点列表 | 名称是主要信息，协议/分组为次级信息；国旗仅标位置；延迟为独立动作。当前成员、悬停、高亮、键盘焦点四种状态不能混用，详情图标仅在悬停/高亮/当前行突出。分隔线从文字列起，滚动条有固定留白。 | 单击名称仅按组契约切换，延迟点击仅测速，详情点击仅打开详情；长名称、缩放和不同状态均不重叠。 |
| 菜单与浮层 | 命令菜单只放命令；含搜索和列表的组选择采用有锚点、限高的专用浮层。菜单统一行高、勾选列、文字列、快捷键/箭头列及分组间距；开合时圆角、尺寸稳定。 | 鼠标、键盘与屏幕边缘下可操作；显示/隐藏及筛选不出现跳位或方角闪烁。 |
| 设置目录 | 第一组有左侧分组名，搜索入口对齐在该行右侧且用次级色；其余分组保持连续行。 | 搜索入口不再悬在整页右上角，Ctrl+F 与点击仍打开同一搜索任务。 |
| 空状态 | 说明和相关操作共用一个居中的内容簇，避免说明独占视口而把操作推到底部。 | 连接、规则、配置和节点的空态按钮紧随说明；窗口缩放时保持居中且不遮挡列表。 |
| 视觉系统 | 颜色、字阶、线条、圆角与密度仍由设计 token 和 Qt 适配层给值。强调色限于有效主操作；一物理像素分隔线；图标在实际 DPR 检查。 | 100/125/150% DPR，100/120% 文字，明暗/高对比截图无明显裁切、双线或状态歧义。 |

## 实施与复核顺序

1. 导航和首页标题/列表结构，先恢复信息层级；不改业务命令。
2. 行列表的绘制与命中状态，保留卡片视图及现有排序/过滤。
3. 组选择浮层和通用菜单状态，复核跨页菜单。
4. 配置、数据、设置逐页对照相同规则；只消除不一致，不增设功能。
5. 定向构建/回归、窄窗与主题样片、文档和隐私检查；人工观感单独注明。

实施状态与真实验证由项目状态和验证报告记录。未运行的设备、系统代理/TUN、Windows 10、长期稳定性不据此宣称通过。

## 实施后逐项复核

导航改为浅选中面与强调色图标；首页节点区恢复标题、分组名称和数量。节点行把当前、悬停、选中分别表达，详情入口仅在相关状态突出，命中区域仍固定。可搜索组选择从命令菜单拆为有锚点的专用浮层，首次绘制前确定边界、圆角和位置。设置目录把搜索放入“常用”标题行。共用空状态将说明与按钮作为居中的内容簇，连接页的原本贴底动作已移至说明下方。

没有迁移 Daymark 的 QML 或任务语义，也没有修改代理命令、配置格式和系统写入。原生 Windows 1.5 DPR 明暗样片与窗口尺寸样片已复核；几何与交互的自动化结果见[验证报告](../verification-report.md)。人工读屏、不同显卡和 Windows 10 的视觉验收仍需独立进行。
