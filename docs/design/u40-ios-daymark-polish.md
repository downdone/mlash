# U40 Mlash 全界面重新设计与验收标准

状态为设计方案。基线是 1.22.0 工作区的 U39 界面，现有一级分区、页面容器和控件组合均可重做。以 Apple HIG 的信息层级、可恢复操作、反馈和适应性为目标，借鉴 Daymark 已验证的固定操作位置、就近详情和大字重排。设计按功能盘点、功能大纲、UI 布局、UI 功能、UI/UX 精修依次展开。

原生复审后，以现有 Widgets 布局作为精修底稿。下文的五区是导航候选，是否调整现有入口由 T13 的任务发现结果决定。优先级和对原生组件的要求见[复审结论](u40-visual-interaction-design.md#当前-widgets-实现复审)。

## 目标与决策

- 用户沿「导入配置 → 使用配置 → 开启代理 → 确认接管」完成首次连接，每步都能看见对象、实际状态和下一步。
- 使用 Qt Widgets，遵循 Windows 原生窗口交互与桌面输入习惯。业务状态继续由 Controller 串行写入，沿用状态回读、独立候选与回滚机制。内容区采用实色层级，材质效果在功能和无障碍验收后评估。
- Mlash 保留炭黑 M 路径。Daymark 用于参考图标小尺寸校验、版式、操作回位和反馈方法。Apple HIG 提供原则，本方案的尺寸和门槛由 Mlash 自行确定。[Apple 布局](https://developer.apple.com/design/human-interface-guidelines/layout) · [Apple 排版](https://developer.apple.com/design/human-interface-guidelines/typography) · [Apple 反馈](https://developer.apple.com/design/human-interface-guidelines/feedback/) · [Apple 无障碍](https://developer.apple.com/design/human-interface-guidelines/accessibility)

## 1 全量功能

[全量功能清单](u40-feature-inventory.md)从 Controller 命令、页面和工具窗口、托盘与快捷入口，以及现行能力契约交叉检查用户可完成的任务。[末级任务设计与验收](u40-leaf-design.md)把每组继续拆到命令、偏好或独立可操作视图。每个末级任务有可达入口、可观察结果和复核方法，涉及失败、取消、失效或副作用时也有明确处理。内部定时器、持久化、代理恢复等实现细节映射到用户能观察的状态及后果。

## 2 功能大纲

导航候选包含「连接、配置、诊断」三个日常入口，以及「维护、设置」两个低频入口。入口名直接描述任务。候选方案中的维护承担版本、服务运行资料与数据资产管理。接管策略归设置，临时运行命令归连接或内核所属页。全量任务的拟议主要入口见功能清单。搜索、托盘、错误提示和对象链接均可跳到所属位置。

| 一级 | 二级任务 | 对象边界 |
|---|---|---|
| 连接 | 接管状态、路由模式、节点与策略组、策略组设置、流量摘要 | 当前运行配置及其选路。快速切节点、调模式、测速和开启代理，一屏可达 |
| 配置 | 导入、配置集合、选定配置的来源与更新、版本、节点与组、规则、DNS、拨号链、规则源与节点源、兼容性与运行视图 | 以配置 ID 和版本区分浏览、运行、待应用与上次良好；一个对象一个编辑会话 |
| 诊断 | 流量、连接、网站测试、出口与服务、运行规则与 DNS 查询、日志 | 会话观测及证据。实时采样、静态快照和手动请求各自显示新鲜度 |
| 维护 | 备份与恢复、内核、Geo 数据、应用与版本 | 持久资产和可预检的维护事务。备份、内核包和应用包各自标明实际阶段 |
| 设置 | 外观、启动与桌面、本地网络、接管方式、快捷键、链接导入 | 应用级长期偏好及 Windows 权限配置。即时生效与显式提交有明确提示 |

走查同时比较两种备选。原四分区将诊断和维护分散在数据及设置中，入口少但容易把维护误认为偏好。分成六区并把节点独立可减少复杂运行页的拥挤，但频繁调路由和换节点会跨一级入口。五区作为样板方案，用首次连接、批量更新、找故障、恢复备份、修改 TUN 五条任务逐条验证。每条从无上下文开始，记录首选入口、一级跳转、错误入口是否会造成副作用，以及返回后是否找回原对象。出现系统性误选时重做归属。

| 从零开始的任务 | 预期最短主路径 |
|---|---|
| 首次连接 | 连接空态 → 配置导入 → 使用配置 → 连接 → 确认实际接管 |
| 批量更新并确认仍在运行的版本 | 配置集合 → 多选更新 → 逐项结果 → 目标配置版本 |
| 找一条连接的分流原因 | 诊断 → 连接 → 行详情 → 命中规则/策略组 → 返回所选连接 |
| 从备份恢复一份配置 | 维护 → 备份与恢复 → 预览归档 → 选配置 → 确认 |
| 修改 TUN 选项并确认效果 | 设置 → 接管方式 → TUN 字段 → 保存回读 → 连接状态 |

## 3 UI 布局

主窗左侧上段为连接、配置、诊断，下段为维护、设置。标题显示当前任务或对象，右侧保留与当前任务相关的主要动作。全局接管和告警使用统一状态组件。窄窗收紧侧栏并保留文字和焦点。API 观测只在对应窗口/页可见时启用。

| 空间 | 宽窗样板 | 窄窗或大字样板 |
|---|---|---|
| 连接 | 上部是接管、路由、当前配置和可见的流量摘要。下部策略组、主工具带和节点表占主要高度 | 运行摘要按阅读顺序堆叠，关键开关和实际状态相邻。节点工具带换行，列表单独垂直滚动 |
| 配置集合与对象 | 集合提供单独一行导入和对象列表。详情头固定配置名和版本状态，任务目录承载深层编辑，比较或短详情可并排 | 集合改连续单列。打开对象进入当前分区主内容，目录依次展开，使用明确的对象返回。过期目标回到所属列表 |
| 诊断 | 二级任务选择固定在内容顶部或侧列，表格/日志全宽。连接详情或短测试证据可并列 | 同一任务以正文下钻显示，标题、回退和必要动作固定，详情正文单轴滚动 |
| 维护、设置 | 分类目录加单列内容。可独立完成的短设置用属性行，备份/内核多步骤使用任务主区。表单设可读最大宽度 | 同级目录换为单列进入，返回回到原目录行。表单纵向重排，危险操作与普通动作分行或置于独立区 |
| 浮层与工具窗 | 只承担短选择、短详情、单次文件选择或后果确认，靠近来源；高级导入可独立打开 | 可用空间不足时，同一对象迁入主内容或可滚动工具窗口，保留草稿、错误和原焦点书签 |

以下线框以从上到下的阅读顺序表达层级。方括号内是并列区域，箭头表示替换正文后的下钻。

```text
主窗    [侧栏：连接 / 配置 / 诊断，维护 / 设置] [标题与主要动作 → 正文 → 状态与告警]
连接    连接状态 → [代理开关 / 实际归属] → [路由 / 当前配置] → [策略组 / 节点工具] → 节点列表
配置    [配置 / 导入配置] → 配置集合 → [对象名 / 运行与候选状态] → [任务目录 / 当前任务]
诊断    [诊断 / 当前任务] → 二级任务选择 → [采样状态 / 工具带] → [结果列表 / 所选对象详情]
维护    [维护目录 / 当前资产的状态 → 操作步骤 → 当前步骤结果和提交]
设置    [偏好目录 / 当前分组 → 属性行或编辑表单 → 错误和提交]

窄窗    侧栏保留标签 → 对象或任务替换正文 → 顶部返回原对象 → 单轴滚动正文 → 必要提交动作
大字    同行属性按标签、当前值、操作堆叠 → 主要动作保留独立一行 → 局部说明随字段换行
```

进入末级实现前，按五条代表性任务把线框落实为宽窄样板，逐屏核对标题、信息密度、动作槽与滚动边界。默认首页、键盘快捷键、托盘、协议外部唤起、设置搜索和轻量重开均按兼容映射抵达新位置。保留旧持久化编号含义与业务对象 ID。新旧页面并存期间，同一对象有一个可写入口，确保切换后旧路径仍可解释。

旧编号的落点须可断言。0 进入连接控制区，1 进入配置列表，2 进入连接节点区，3 进入配置的规则入口，4 进入诊断连接，5 进入诊断日志，6 进入设置，7 进入诊断网站测试。旧 3 在无配置时显示可用的导入入口。新配置对象的返回目标随配置 ID 与选择保留。

## 4 UI 功能设计

具体控件、权限、返回规则与独立验收按 [末级任务设计](u40-leaf-design.md)。下面明确跨页共享的状态和事务规则。

### 连接与首次导入

- 连接页无配置时显示「导入配置」。已有配置但尚未使用时显示「选择配置」。两种入口都直达配置页，前者聚焦快速输入，后者定位可用配置。已使用配置时快速读取「代理」状态、路由模式、当前节点和测试当前组操作。
- 代理行保留稳定可见标签，状态紧贴开关，当前节点用独立次级文字。顶栏和托盘采用同一组观测事实，可按可用空间压缩。读屏名称说明此开关控制已允许的接管方式。

| 观测或事务状态 | 可见反馈与下一步 |
|---|---|
| 内核停止或未就绪 | 说明当前内核阶段。已使用配置时保留合适的代理动作，启动中避免重复提交 |
| 内核就绪且确认未接管 | 「代理未开启」，可「开启代理」。与节点连通性分开 |
| 系统代理或 TUN 已接管 | 显示实际接管方式。两种并存时均可读取，未确认的方式单独说明 |
| 外部程序管理或所有权未知 | 「系统代理由其他程序管理」或「系统代理状态未确认」。沿用既有明确接管与恢复条件 |
| 操作进行中或失败 | 就地显示开启、关闭或失败反馈，开关以观测值为准。失败时保留原因及可执行的处理入口 |

- 快速导入采用持久标签「订阅地址或 YAML 文件」，宽时并排输入和动作，窄窗或大字下动作另起一行。选文件和拖放只预填。链接按现有规则遮挡。错误贴近字段并保留输入。成功后选中新卡，用户仍在原任务时把键盘焦点送到新卡的「使用」，切页后完成则在对应配置中提示。
- 高级导入统一标题为「导入配置」，保留订阅、文件、节点链接三类输入。取消、Esc、窗口关闭和 Alt+F4 共用离开判断。用户选择继续编辑时保留输入和焦点。进行中的导入若允许关闭窗口，由可见文案说明任务继续及查看结果的位置。取消草稿和关闭提交中窗口使用各自准确的动作名。

### 配置、详情与设置

- 配置卡维持名称、来源和时间、状态及动作三组信息。列表选择、真实运行版、候选更新和最近更新失败分别表达。常规宽度支持等宽卡片，长内容可换行或按可用空间转单列。操作按钮与卡片点击命中区独立。
- 「查看变化」只浏览当前候选，显示比较对象和当前使用版。「应用更新」显式提交并提示可能中断。网络错误、旧候选或启动失败时给出可执行的下一步，保留实际仍在运行的版本和可重试输入。回滚入口位于配置的版本区，确认内容说明目标及影响。
- 节点详情、连接快照和短差异摘要贴近来源。展开时保留同一对象，关闭后回到触发项。规则、DNS、复杂候选差异、备份恢复和 TUN 使用有清楚标题与返回路径的任务工作区。保留未提交草稿、活动/候选版本边界、显式提交和失败回读。
- 设置按新的偏好目录组织。常用偏好显示当前值并就地改动，运行相关设置显示明确的保存或重启后果，错误贴近字段。设置搜索、跨页和返回保留目标、焦点和滚动。备份预览移到维护，TUN 权限管理归接管方式，两者沿用已有先决条件和明确确认。

### 数据、菜单与托盘

- 流量区区分真实零值、等待采样和采样失败。连接区区分无配置、未就绪、无活动连接、筛选无结果和刷新失败。暂停保留冻结快照及其采样时间，离开观测时执行既有快照清理。连接详情显示打开时的快照时间。断开单条或全部按原确认及回读规则执行。
- 网站测试显示测试对象、正在测、超时或取消，并说明结果依据。日志保留等宽正文、暂停及回到最新，主操作指向脱敏导出。每类空态就近提供一个可执行的下一步。
- 路由菜单、配置更多、节点菜单和托盘按实际动作分组，明确当前项、危险项和键盘路径。弹层首次定位即落在所属屏幕可用区，关闭后恢复触发焦点。轻量重开恢复既有有界书签，重新读取运行状态。

## 5 UI/UX 精修

[视觉与交互详细设计](u40-visual-interaction-design.md)给出品牌、四套配色、控件规格、五区页面及 Shadowrocket 简约规则。以下验收门槛适用于实际 Widgets 实现。

| 项目 | 设计目标及可判定标准 |
|---|---|
| 字阶 | 100% 首轮样板采用页面 24、对象 18、分组 16、正文 14、辅助 12 逻辑像素作为目标。按 Qt 实际字体度量验证中文与数字基线。字号独立提供到 200% 的可读布局，沿用现有偏好字段并同步更新范围校验，覆盖旧设置读取及新值保存重开 |
| 间距与轮廓 | 共享 4/8/12/16/24/32 DIP 间距。字段内部与页面分区各用对应间距。圆角、分隔、焦点和选中样式由共享组件控制。页面标题与内容共用左轴，表单边界统一 |
| 布局稳定 | 同一窗口尺寸、主题、字号和布局模式下，状态变化或视图切换前后，共享工具槽位的锚点漂移 ≤1 DIP。提示或进度出现时固定主体边界或使用就近预留区域。断点重排后重新核对操作顺序 |
| 窄窗与滚动 | 840×560 DIP、100% 应用字号时，连接控制区下至少显示 3 行节点。大字优先完整展示标签和主动作，表单仅纵向滚动，正文与可见滚动条零重叠。允许数据表按其列布局独立横向滚动 |
| 颜色与图标 | 四套语义色覆盖浅、深和两类增强对比。普通文字含有效占位文字达到 4.5∶1，必要状态图形、焦点和控件边界与相邻面达到 3∶1。测实际呈现色对，含 Qt 合成后的有效颜色。品牌和状态均有可辨形状或文字。复核 16/20/24/32/48 px 的应用图标与托盘输出 |
| 输入与动效 | 高频独立图标按钮以至少 32×32 DIP 为鼠标和键盘样板目标，触控场景验证至少 44×44 DIP 的目标区或等效可达入口。密集列表提供可见焦点和独立的详情/测速键盘操作。新增过渡需支持系统减少动态，且最终几何和焦点一致 |

## 测试方法

### 状态与操作用例

复用已有测试套件，补入现有用例无法捕获的失败、取消、竞态或几何断言。用例从用户可见入口驱动。断言同时检查用户可见反馈、选中对象、焦点或滚动，以及允许的 Controller 命令次数和最终状态。使用临时目录、合成 YAML、回环 HTTP 夹具及注入的平台/内核观测。不以截图证明系统状态或命令成功。

| 用例 | 具体操作与通过条件 | 现有入口 |
|---|---|---|
| T01 快速导入 | 从空首页进入。覆盖 URL、本地 YAML、拖放和失败重试。拖入和选文件零导入命令。失败留输入，成功只新增一个配置并选中，当前运行配置和代理写入计数保持原值 | `subscription_cards_ui`、`profile_import_ui` |
| T02 高级导入离开 | 对同一份修改分别用取消、Esc、关闭按钮和 Alt+F4。继续编辑时内容和焦点保留，确认放弃后无写入。已经提交后关闭时，单次操作继续，异步结果归属原配置页 | `subscription_cards_ui`、`ui_components`，原生核对四种关闭路径 |
| T03 首次连接与失败 | 导入 → 使用 → 开启代理。模拟延迟和快速重复点击。一次显式动作最多一次业务提交。失败或回读冲突显示实际值，重试保持对象；外部代理确认取消后写入次数为零 | `home_control_tests`、`navigation_contract_tests`、`feedback_routing_tests` |
| T04 状态一致性 | 注入内核停止/启动/失败/就绪、代理关闭/自有/外部/未知、TUN 确认/待确认。核对首页、顶栏、托盘和可访问状态，无虚假接管或过期响应 | `home_control_tests`、`status_shape_tests`、`tray_quick_menu_ui` |

### 执行入口与证据

Windows 开发机使用已配置的 `windows-mingw-open` 预设。其他已验证工具链按[开发指南](../development/build.md)替换预设。每个切片构建后执行对应定向集合，以下以连接与导入为例。最终从相同源码构建运行 Windows 默认全量测试。原生矩阵使用生产启动入口或原生探针复核，证据分别记录。

```powershell
$preset = 'windows-mingw-open'
./scripts/build.ps1 -Preset $preset
./scripts/test.ps1 -Preset $preset -TestRegex '^(subscription_cards_ui|profile_import_ui|home_control_tests|navigation_contract_tests|feedback_routing_tests|status_shape_tests|tray_quick_menu_ui)$'
./scripts/test.ps1 -Preset $preset
python scripts/check_docs.py
python scripts/check_document_privacy.py
python scripts/check_ui_tokens.py
git diff --check
```

便携交付使用独立名称和新证据目录，从实际分发 ZIP 解压后的可执行文件运行冒烟。按路由逐张核对截图，同时核对设置搜索返回、Schannel、白名单、内嵌图标和 SHA-256。

```powershell
$stamp = Get-Date -Format 'yyyyMMdd-HHmmss'
$outputName = "Mlash-U40-$stamp-portable"
$evidence = "build/u40-$stamp"
./scripts/package.ps1 -Preset $preset -OutputName $outputName
New-Item -ItemType Directory -Path "$evidence/extracted" -Force | Out-Null
Expand-Archive -LiteralPath "dist/$outputName.zip" -DestinationPath "$evidence/extracted"
python scripts/package_payload.py verify --root "$evidence/extracted" --plan scripts/package-files.json
./scripts/ci_smoke.ps1 -PackageDirectory "$evidence/extracted" -EvidenceDirectory "$evidence/smoke"
python scripts/verify-exe-icon.py "$evidence/extracted/Mlash.exe" --report "$evidence/app-icon.json"
python scripts/verify-exe-icon.py "$evidence/extracted/MlashTunService.exe" --report "$evidence/service-icon.json"
Get-FileHash "dist/$outputName.zip" -Algorithm SHA256
```

以归档内含 `Mlash.exe` 的根目录为 `-PackageDirectory`。每条证据记录源码标识、构建预设、EXE 或包哈希、环境、夹具、操作步骤、期望/实测、通过/失败/未验及对应文件。失败先保留复现和日志，修复后按同一场景复测，结果落入[验证报告](../verification-report.md)。截图、日志与合成夹具留在忽略的证据目录，使用脱敏内容。常规测试走隔离替身，真实 WinINet 或 TUN 写入仅使用项目规则允许的受控 VM。
