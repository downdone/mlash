# Mlash 最终 UI 优化稿 · U09-F

状态：**最终设计整合稿，已按 U11 完成本轮原生实施**。本稿确认视觉和交互方向，当前实现契约见 [U11 系统规范](u11-ui-system.md)，实际验证与边界见 [验证报告](../verification-report.md)；原型不是实机验收记录。平台输入、无障碍、性能和部署门禁仍需实际验证。

## 1. 唯一主入口

打开 [最终交互原型](u09-final.html)。该文件内嵌图标、六地区国旗、样式、脚本和合成数据，可独立复制后离线打开，不依赖 npm、服务器、用户配置或运行中的 Mlash。文件顶部的场景/主题/文字大小是**评审工具**，不属于最终产品工具栏。

原型沿用 Shadowrocket 的主要结构与视觉：四项侧栏、居中标题、少量顶栏动作、整组圆角列表、文字列缩进分隔线、蓝色线性图标和行末信息按钮。小象品牌只作轻量识别，不占页面主区域。Windows 保留原生窗口控制，原型不画假的 macOS 三色按钮。

[基础 UI 方案](../ui-u09-shadowrocket.md)、[Verge 吸收评审](u09-verge-review.md) 是详细理由；本稿作为两者整合后的原型范围和实现优先级。旧 [初稿预览](u09-preview.html) 只保留过程参考，不能与最终原型并列作为实施标准。

## 2. 最终页面结构

| 分区 | 默认内容 | 深入任务 |
|---|---|---|
| 首页 | 三行控制组、浏览组/搜索/定位/测速、连续节点列表 | 模式菜单、组搜索、本组测试设置、节点检查器 |
| 配置 | 导入/更新、远程订阅、本地快照 | 配置详情、候选变化、维护/用量、规则草稿、Provider |
| 数据 | 流量 / 连接 / 网站测试 / 日志 | 连接检查器、代理组跳转、规则预填、关闭确认 |
| 设置 | 简单偏好、通用、网络、维护、关于 | 网络编辑、TUN/备份/内核工具入口 |

原型默认深色与 100% 文字，支持浅色和 120% 文字检查。正常宽度为桌面侧栏+内容；窄窗详情变为内容区后续页，返回不改变业务对象。检查器有明确关闭/返回，不能层叠多个对象面板。

## 3. 本轮吸收的便利性微调

- **定位当前直接可见**：被搜索/收藏筛选隐藏时，先确认清除筛选再定位；定位不切节点。
- **排序不盲循环**：更多菜单明确显示默认/名称/延迟及当前勾选。本组测试设置显示 URL；改目标标记旧结果过期。
- **组导航按点击**：常用/最近与搜索优先，不采用指针经过即跳组；自动组只看/测，不手动固化。
- **配置维护就近**：行不膨胀成大卡片；用量/到期/计划/失败在详情集中，下载、比较、应用分开。
- **连接诊断闭环**：目标→规则→路径→状态；转组只浏览，创建规则仅预填草稿，旧配置/代次快照不可给新配置写入。
- **稳定反馈**：最近操作与仍成立的恢复告警分开，固定底部高度；pending 不提前显示成功勾选。

不增加仪表盘、任意布局、常驻长工具排、大量类型徽章、无实现的上传/扫描/Tailscale/模块入口；不把全部 Verge 功能扩展成此次 UI 重做范围。

## 4. 原型可操作范围

### 首页与节点

顶部评审场景支持运行中、未连接、无配置、外部代理、恢复失败。连接演示具名过渡；外部接管需确认；恢复失败保留告警。路由选择独立菜单；连接状态与路由方式不相互冒充。

节点支持搜索、定位、默认/名称/延迟排序、仅收藏、收藏切换、组搜索、独立测试目标、单测/组测与详情。手动选择有 pending 和完成回读示例；自动组点击只读。地区来自内置提示，不作真实地理定位。

### 配置和规则

支持导入类型/必填留稿、配置详情、候选比较、应用成功/失败分支、明确使用其他配置、维护/用量详情、Provider 候选更新和规则草稿。候选窗口可勾选“演示应用失败”；失败后运行版和待更新候选都保持。

规则类型/匹配/策略/位置可编辑，空值拒绝保存；未保存时切分区受保护；连接预填不直接保存。预览中不执行完整 YAML/内核校验，成功只是模拟路径。

### 数据和设置

连接有活动/已离开、搜索、暂停、结构化详情、关闭确认、跳组和规则预填。网站卡片展示目标和独立重测入口，日志保留暂停/导出任务入口。流量是固定合成值，不用装饰曲线伪装真实采样。

设置演示外观/文字、即时开关、网络端口校验与显式保存。TUN、备份/恢复、内核等提供任务说明与部分流程；不安装服务、不运行内核、不生成备份、不写剪贴板或磁盘。

### 明确的原型边界

高级 DNS/Geo/节点/拨号链/快捷键编辑、真实列拖动、系统文件对话框、原生高 DPI 与辅助功能属于后续组件/产品实现验收。对应入口在原型中说明任务，**不声称完整高级编辑器已经设计或实现到每个字段**。系统协议按 [六层设计](u09-system-design.md) 和现有安全契约推进。

## 5. 设计约束到实现的映射

1. 先实现 AppShell、GroupedList、NodeRow、Inspector 四组件样片，验收结构和输入，不直接替换整套产品。
2. 样片比较 Widgets 与有必要时的 QML；[选型评审](u09-technology-review.md) 保持生效。QML 如果采用，优先独立主窗+C++ 核心，需新 ADR 和依赖/部署验证。
3. 再按“功能定义→架构→模块→协议→接口→功能设计”的现有顺序固化每条任务，不把原型 JS 当产品逻辑或复制到 QML。
4. 列表模型有稳定身份与能力字段，UI 只显示投影/发送有限命令；Controller 继续是唯一写入者，跨视图和托盘同源。
5. 保留 source/candidate/active/LKG、写后回读、写前恢复、期望快照与有界取消；UI 换样不增加隐式接管、监听和特权。
6. 新功能入口也要覆盖空/忙/失败/取消/过期/轻量重建，不用正常态截图替代验收。
