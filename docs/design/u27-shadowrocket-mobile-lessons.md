# U27：Shadowrocket 移动端截图的桌面交互启示

2026-11-19。审视用户提供的首页、节点列表和编辑、配置、URL 导入、路由、设置、数据截图。这是**参考图分析**，不是按图新增协议、模块或移动端布局的实现承诺。结合 Mlash 当前首页、配置、数据、设置离屏截图，提炼“用户不需要管太多，东西都能找到”的可执行原则。

## 核心机制

Shadowrocket 的首页把连接、路由、测试放在最先看到的三行，紧接当前配置和节点；它让用户从目标出发，而不要求先理解内核、端口、规则和订阅格式。配置和节点以可识别对象为单位；行的名称承担主动作，右侧 `i` 承担详情，刷新紧贴配置。设置按权限、更新、数据等任务分组，右侧呈现当前值，选中项用勾选，输入未有效时保存不可用。少展示并不等于入口隐蔽：加号、刷新、返回、详情与设置都处在可预期的位置。

## 逐页迁移到 Mlash

| 参考图里的有效做法 | Mlash 桌面端的对应原则 | 不照搬的部分 |
|---|---|---|
| 首页三项高频任务与当前节点列表连续出现 | 首页先连接、选节点和测连通性；当前配置与更新放在相关对象旁。运行内核由软件管理，异常通过可执行的恢复提示呈现 | 大块手机蓝色顶栏、重复展示内部状态 |
| 节点主行、国旗和协议摘要，`i` 单独进详情 | 整行只做选择/展开这一主动作；详情和更多操作放在行尾或就近菜单，回到列表保持筛选与滚动 | 每行都放常驻同权重图标、为了装饰扩大行高 |
| 配置文件带名称、日期、当前标记和就近刷新 | 配置列表是主角，当前使用与待更新状态一眼可辨；刷新靠近卡片，导入靠近列表 | 把远程/本地分割为两个导航体系；只因来源不同增加中间页 |
| 添加/编辑先定类型，必填项在前，技术选项给默认值 | 新增配置/节点从一个明显入口开始；桌面就近展开输入，协议相关高级字段按需展示，校验通过才可提交 | 手机全屏表单、为输入一个 URL 强制打开单独大页面或模态框 |
| 路由模式为“名称＋一句结果＋选中勾” | 常用模式在首页就近选择，说明“流量会怎样走”，把回退等高级设置留在设置里 | 为三四个选项再建多级页面；把用户暴露给原始配置键名 |
| 设置按任务分组，当前值在行尾 | 设置首页保持稳定目录与常驻搜索，点击后在原位置选择或进入单项编辑；危险动作标明对象和后果 | 照搬手机行高、底部导航、把所有技术开关堆到首页 |
| 数据页面按观察/维护目标组织 | 流量、连接、测试、日志保留可预期入口；结果在原列表反馈，详情需要时再打开 | 无关“服务器节点/统计”与危险清理操作混排成同一长列表 |

## 固化为设计检查

每页先写出用户来此要完成的**一件主任务**，再检查：①第一屏能否找到主动作；②对象列表能否直接识别当前、失败和可更新状态；③点击行、行尾按钮、菜单分别执行什么；④返回后是否回到原对象和位置；⑤默认值能否替用户承担技术决策；⑥出错时是否告诉用户下一步，而非内核细节；⑦低频操作能否从相关对象或设置找到。功能发现路径比首页堆满功能更重要。

视觉上沿用桌面适配：浅画布、白内容面、细分隔、品牌蓝主动作与选中、绿色启用开关、灰色关闭开关。保持 Windows/Qt 的侧栏、键鼠和窄窗行为；不复制手机底部导航或高占比顶栏。后续若按此实施，必须先逐页形成入口/返回/空态设计，再做代码和操作链验证。本记录本身不声称 UI 已按这些建议改完。
