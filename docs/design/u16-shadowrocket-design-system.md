# U16：独立 UI 设计系统与 Shadowrocket 风格特化

## 原则复核与职责

Mlash 以用户任务组织首页、配置、数据、设置；首页完成接管和节点选择，配置编辑订阅及规则，数据观察连接与测速，设置处理设备和偏好。Shadowrocket 提供内容优先、少量直接操作、连续分组行和渐进展开的视觉与交互方向，不复制它的 macOS 窗口装饰或与 Mlash 不符的功能。频繁操作在当前上下文内可见，低频维护动作进入详情；状态反馈不推动正文跳位。鼠标、键盘、深浅色和高对比共享相同的信息顺序。

## 分层

1. **信息与任务层**：页面归属、浏览/应用边界、空/载入/失败/候选/运行版状态，由页面契约和 Controller 状态确定；风格模块不得修改。
2. **框架与布局层**：四分区、侧栏、顶栏、正文滚动宿主、分组顺序与主次动作由页面布局组合，使用统一的几何规格，不允许在样式表中暗改控件占位。
3. **组件层**：行、卡片、按钮、菜单、弹层、列表委托各负责自身的绘制及输入状态；使用语义颜色和共享几何、字号，不自行定义一套主题。
4. **视觉特化层**：`UiDesignTokens` 定义颜色、间距/尺寸和字阶的只读契约；`ShadowrocketStyle` 提供明、暗、高对比四套配色、紧凑尺寸/字阶及组件 QSS 模板；`UiTheme` 仅作为运行时 Qt 适配和旧调用点的迁移桥，决定当前系统外观、应用字体、QPalette 和 token 替换。

不是运行时换肤引擎；当前只有一个风格特化。将来若增加风格，需要先证明不同风格对任务层级和组件状态的要求，再增实现，不在页面堆条件分支。语义颜色指背景、侧栏、表面、正文、次要文字、边线、强调、选中、悬停、焦点和结果状态，不能用具体 RGB 名称作为业务判断。

## 本片可观察验收

- `UiTheme` 不再保存明暗/高对比颜色字面量，也不定义独立的布局尺寸和字阶数值；四种外观取值集中在 Shadowrocket 特化中。
- 原页面框架、行高、颜色取值和字体回退顺序保持一致；不会更改代理/TUN 命令及持久化。
- 外观对比度、页面尺寸和主题切换现有测试通过；静态边界检查防止页面新增颜色字面量或反向依赖。
- 实施后记录仍使用兼容桥的范围，逐页原生视觉与读屏复核如果没做则明确未验。

## 后续逐级精修次序

先核对每页任务与分组顺序，再核对侧栏/顶栏/正文宽度与滚动边界，随后统一行和卡片状态，最后调整颜色、线条、圆角、字阶、间距。每次修改一类规格，按明/暗/高对比、100–120% 文字、窄窗和 125–150% DPI 复核；视觉参数不得掩盖结构或状态错误。

## 实施后对照

`src/ui/design/UiDesignTokens.h` 定义只读的颜色、几何与字阶形状；`ShadowrocketStyle.h` 集中明/暗/高对比取值，组件样式模板在独立文件中。侧栏内边距及顶栏两侧动作槽也已由框架几何规格提供。`UiTheme` 不再定义颜色或尺寸字面量，只将当前规格应用到 QPalette、字体与 Widgets 样式。原有页面布局及颜色值保持不变，本片是为后续视觉精修建立单一取值来源，不声称已完成全页视觉重画。外观对比度及页面生命周期自动回归见验证报告；原生人工观感、读屏和不同显示器 DPI 未在本片复核。
