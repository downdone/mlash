# U29：Shadowrocket 截图的设计提炼与桌面转译

2026-11-19。通用的 Shadowrocket 交互原则由 [U27 参考图分析](u27-shadowrocket-mobile-lessons.md)维护。本记录依据同一批手机版截图和随后提供的 Mlash 四张问题截图，专门检查 U29 的设计落差与验收路径。参考的是用户展示的画面和动线，不推断截图之外的功能。U29 已先做了局部代码调整才补这份逐图分析，顺序不符合设计先行要求；用户指出后暂停继续改界面、补齐分析，再按这些判据复审代码与截图。后续任务须在第一行 UI 代码修改前形成这类逐图提炼和可观察标准。

## 逐页观察

| 参考画面 | 首屏焦点 | 下一步在哪里 | 可借鉴的组织方式 |
|---|---|---|---|
| 首页：连接、路由、测试，下面是订阅和节点 | 连接状态与当前节点 | 订阅标题直接展开节点，节点的详情按钮与选择动作分开 | 主任务先出现；对象与其成员保持邻近；常用动作直接可见 |
| 配置：工具入口、当前本地文件 | 当前使用的配置 | 文件行给出名称、时间、选中标记、详情入口 | 配置是对象列表，选择与编辑是两个动作；来源信息成为次要文字 |
| 添加节点与 URL 导入 | 先选类型或填 URL | 必填输入就近出现，保存/下载在同一任务中 | 添加从一个明确入口开始；简单输入用小窗口，完整编辑才用详情页 |
| 节点编辑与全局路由 | 当前对象的字段或互斥选项 | 值在行尾，进阶项再进入下一层 | 详情页只处理一个对象；当前值在目录里可读；选择后无需再展开同一内容 |
| 设置和数据 | 按用途分组的目录 | 状态值与箭头提示去向 | 目录以任务归组，行高、图标、标签和值的轴线稳定，低频功能仍可找到 |

这些截图也有不适合照搬到 Windows 的部分：底部导航是移动设备的屏幕空间选择；高饱和蓝色顶栏、巨大的手机行高与长节点滚动列表照搬到桌面会浪费面积。Mlash 继续用左侧四个稳定入口，但内容区遵循上述信息顺序和动作距离。

## 本轮的可检查标准

沿用 U27 的“主任务先出现、对象入口邻近、低频项仍可找到”原则，U29 在四处界面增加以下判据：

1. 进入数据的流量子页即可读取唯一一组关键指标；子页内不再重复展开相同内容。
2. 配置卡的名称、来源、时间、状态及动作沿固定轴线排列；单份卡片宽度有界，蓝色不铺满卡面。
3. 节点与组编辑先呈可搜索的等高名单；单项编辑和批量维护各有明确入口，加载与失败只占一个内容位置。
4. 首页当前组设置在独立紧凑窗口完成；关闭或换页返回原节点列表，草稿保护继续有效。

## 对四张问题截图的设计判定

| Mlash 问题 | 违反的原则 | 本轮目标 |
|---|---|---|
| 数据 › 流量子页再展开“流量明细”，且上传/下载/连接重复 | 2、4 | 进入流量即见唯一一组指标和趋势，测试另有明确入口 |
| 单份订阅为大色块，内容挤在左上角 | 4、5 | 卡片宽度有界，白色面、清楚的名称/来源/时间/状态/动作轴线；当前仅用窄标记 |
| 节点与组子页外层任务、内层切换、密集名单和大空白 | 2、3、4 | 先显示可搜索的等高对象名单；新增/编辑紧贴名单，少用说明文字；单项编辑再进入编辑器 |
| 首页组设置在节点列表上方整块展开 | 2、6 | 独立紧凑窗口编辑当前组，节点列表尺寸和滚动位置不变；关闭仍回原对象 |

## 验收路径

按真实任务连贯走：打开应用→在首页选节点和组→打开组设置并取消/保存→进入配置并更新/使用→进入节点与组并搜索/编辑/返回→在数据页看流量/测试→切换设置明暗主题及窄窗。每一步核对当前焦点、下一步入口、返回位置、加载/失败状态和视觉轴线。截图只是证据之一，还要用交互测试核对命中区、草稿边界和尺寸变化。
