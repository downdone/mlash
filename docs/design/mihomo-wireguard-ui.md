# Mihomo 与 WireGuard 界面设计

首版已接入 Windows Qt Widgets 主窗与托盘。本页后续设计覆盖实际出口核实、诊断和排版矩阵。接管与回读契约见[双内核设计](mihomo-wireguard-dual-engine.md)。

## 导入 → 识别 → 打开配置

保留一个配置列表、一个导入栏。用户粘贴 URL、选择或拖入文件，导入预览给出名称和识别结果。保存后一律成为普通配置卡。点击卡片打开详情，类型决定可见功能与主动作。

| 输入 | 识别结果 | 打开后第一屏 |
|---|---|---|
| [Interface]／[Peer] 格式的有效文件或粘贴文本 | WireGuard 隧道 | 连接、覆盖网段、接口摘要和 Peer |
| 受支持的订阅、Mihomo YAML 或可转换的节点来源 | Mihomo 代理配置 | 启动代理、本地入口、策略组和节点 |
| 内含 `type: wireguard` 出站的 Mihomo YAML | Mihomo 代理配置 | WireGuard 节点显示在 Mihomo 节点列表，由 Mihomo 策略组选用 |
| 内容不完整、来源未取回或存在识别歧义 | 待识别／格式错误 | 标出阶段、字段与行号，保留原输入；必要时允许用户指定导入类型并重新验证 |

本地文件按内容识别，原生 WireGuard 支持选择、拖入或显式粘贴。URL 继续使用既有 Mihomo 订阅流程。粘贴预览中取消或发现格式错误，可以返回原输入继续编辑。预览、保存和浏览均与启动解耦。设备密钥、PSK、订阅令牌及原始配置遵守现有脱敏契约。

### 配置卡

用同一张紧凑模板呈现两种类型。首行名称及刷新／重读、菜单，第二行「WireGuard 隧道」或「Mihomo 代理」与来源／更新时间，末行只显示有意义的运行态或候选。订阅的 URL 只显示可公开的脱敏部分，详细日期可从详情查看。保留 Daymark 色阶、细边界与稳定排版，类型用可读文字和图标识别。长名可在卡片省略，打开后能看全。导入栏沿用约 48 DIP 高度。

## 打开配置后有哪些功能

| 任务 | 打开 WireGuard 隧道 | 打开 Mihomo 代理配置 |
|---|---|---|
| 启停与选用 | 「连接隧道／断开」。切换同类配置前提示受影响网段 | 「启动代理／停止」。切换同类配置前提示受影响连接 |
| 路径 | 隧道接口、IPv4/IPv6 管理的网段、Endpoint 出口、DNS 设置与实测分别显示 | 本地 HTTP/SOCKS 入口、规则模式、策略组和出站链。物理出口按证据展示 |
| 健康 | Peer 最近握手、隧道收发、指定隧道目标诊断 | 节点测速、连通性测试、代理连接及按规则查看 |
| 配置维护 | 重读来源、编辑、候选差异、回滚，密钥变化只显示摘要 | 订阅刷新、编辑、候选差异、回滚，规则、节点和 Provider 沿用现有能力 |
| 系统接管 | 独立隧道按实际回读写入并恢复受管系统路由。全隧道与断线保护独立验收 | 单独运行时保留已有系统代理和 TUN。并存时以本地代理服务应用，Mihomo TUN 关闭，系统代理不新增或覆盖 |

可浏览的配置详情与实际运行会话分开。未启用配置的网段和入口标记为「配置值」。健康、流量、握手都归当前活动版本，候选不能借用活动会话的数字。详情返回列表保留滚动位置，焦点回原卡片。能力缺失时给出精确原因及可用恢复入口。

## 两条链路怎样共存

- 首页两行「代理」「WireGuard 隧道」。每行显示运行配置、当前状态、短上下文和独立启停。旧用户仅导入 Mihomo 时可沿用原代理区。隧道未导入给一个入口。托盘复用同一状态和独立启停。
- 用户从任一配置详情启动对应链路。另一条已运行时，后台执行共存预检，检查系统路由所有权、网段与 Endpoint、Mihomo 出口与组件。在不涉及替换或接管变化时直接继续；有冲突或必须变更现有接管时才展示确认。取消和失败保留原状态，待清理时保留恢复记录并通过底栏入口处理。
- 两路同时运行时，应用直连且命中受管网段走 WireGuard，应用主动使用本地代理时走 Mihomo，其余直连按 Windows 原选路。界面分开陈述进程是否运行、路由是否生效、Peer 是否握手和物理出口是否有证据。
- WireGuard 断开并成功撤销自己管理的路由后，显示「原有选路已恢复」。已确认独立的 Mihomo 继续可用。Mihomo 停止时只关闭其本地代理，隧道保持原状态。依赖出口的降级按实际观测显示。不可从两条链路都启动推定所有流量都受保护。

## 数据、设置与故障

| 工作区 | 显示与交互 |
|---|---|
| 数据 → 流量 | 「WireGuard 隧道」「Mihomo 代理」「Windows 直连」并列。前两项分别记录 Peer 收发和代理会话，显示采样时刻及范围。直连未采集显示「未统计」。若观察到同一业务先经过 Mihomo 再经 WireGuard，则标明路径并分别保留计数。 |
| 数据 → 连接／测试／日志 | Mihomo 查看连接、规则和测速，WireGuard 查看 Peer、握手和指定目标诊断。按真实能力显示操作，日志可按引擎过滤。重连开始新会话，旧数据标明最后采样时间。 |
| 设置／底栏 | 组件与服务显示协议版本、就绪态和按需授权。持久故障用短文案「隧道待清理」进入可复制的脱敏详情和重试动作。UAC 取消按原位回读状态显示。 |

## 验收方法与完成定义

Qt 接入复用配置列表、卡片和首页控制行。WireGuard 卡沿用名称、来源与时间排版，打开后显示接口、网段、Peer 及独立启停。流量页区分 WireGuard Peer、Mihomo 代理与 Windows 直连，按有效的回读显示状态。

| 范围 | 方法与通过条件 |
|---|---|
| 识别和兼容 | 用有效 CONF、普通 YAML、带 WireGuard 节点的 YAML、订阅、错误扩展名、字段缺失及歧义夹具。每条正确分类或提示，预览及保存前后业务网络状态相同，失败保留输入。 |
| 详情与功能 | 分别从列表打开两张卡，键鼠检查控件和数据归属。隧道用 Peer 与网段，Mihomo 用策略组与节点。返回焦点回原卡。仅有旧 Mihomo 配置时复测既有流程。 |
| 双链路与恢复 | 从两种配置分别启动并独立停止，注入路由冲突、无握手、切网、授权取消和清理失败。已有链路只在明确确认及回读后改变，单路故障不误标独立会话，待清理时阻止重连。 |
| 数据口径 | 用不同大小样本模拟两路计数、串联、未统计、出口未知和重连。按观测点显示，合计不重复，未经验证的路径无确定性标签。 |
| Windows 排版 | 在 1040×720、840×560 DIP、100%／120%／200% 缩放和浅深／高对比下测截图与键盘。选页不移动正文左边界，折叠保留图标，触发区与标签不挤叠，长名称及日期可核对。 |
| 受控 VM | 并发发送内网直连、显式代理和隧道外直连，核对 Windows 路由、实际出口、目的端及计数。断开各自链路并确认恢复。仅在留有对应证据时登记通过。 |

交互原型使用样例配置和模拟状态。Qt 定向回归已核对文件识别、配置卡详情和流量入口。指定目标探测、串联出口的自动判定和完整 Windows 排版矩阵留待后续验收。 [实际验证结果](../verification-report.md#windows-双链路接入与便携预览)

## Qt 交付设计

审查现有构建发现，WireGuard 卡片仍显示「本地文件」，详情把网络和 Peer 拼进只读文本框，首页连接键只跳到整个配置列表，数据页将多个来源混在一段文字，服务页缺少 WireGuard 能力与清理入口。保留竖排侧栏和现有配置卡尺寸，用 Daymark 的语义色、紧凑间距和现有按钮样式组织内容。详情与设置参考 Shadowrocket 的分组信息行，主操作固定在内容布局中，状态用短文字，紧凑窗下长值在可选择的字段中换行。

| 入口 | 末级任务与状态 |
|---|---|
| 配置卡 | WireGuard 类型标识、更新时间、活动状态与候选入口。打开专属详情，返回恢复卡片位置与键盘焦点。Mihomo 卡仍打开节点与组。 |
| 导入与替换 | 文件和粘贴进入脱敏预览。替换允许文件或粘贴，写入时校验预览令牌及原候选代次。保存前可返回草稿，失败仍可返回重试，保存不改变运行路由。 |
| 隧道详情 | 顶部显示配置名称、独立连接动作和阻塞原因。详情按「网络」「Peer」「版本」分开。网络页显示计划值及当前回读，允许输入目标 IP 检查所属前缀。该检查标明口径，避免把配置范围当作实际通信。Peer 页显示等待握手、最近握手和双向累计量。版本页比较候选与上次生效版本的脱敏字段，密钥内容不可见。待应用候选在断开后可显式连接。 |
| 首页与托盘 | 显示两条链路各自状态。一个 WireGuard 配置可直接连接，多个从具名菜单选择。运行、正在操作、清理待确认、受其他接管阻塞时采用同一状态判定。Mihomo 启停仍由自己的命令负责。 |
| 数据工作区 | 流量页分开呈现 Mihomo、WireGuard 与 Windows 直连。采样注明对应引擎与时间，Peer 列表放到详情。连接及测试页继续显示其 Mihomo 数据口径，日志增加仅 WireGuard 筛选。 |
| 设置与故障 | WireGuard 详情可直接打开权限服务任务。服务页显示安装、协议能力和会话清理状态。清理入口调用原权限边界内命令，保留失效原因，更新后重新回读。 |

原型中的串联出口自动判定和指定目标实际发包依赖系统级验证。此交付用明确的出口未知文案及本地网段核对覆盖可验证的界面操作。用 Qt 夹具验证两个类型、键盘进入及返回、旧候选仍运行时重新导入、版本差异、无权限和待清理；输出 1040／840 DIP 浅深原生截图，并区分 Windows 字体偏好和 OS DPI。服务安装、真实 Peer 数据路径和异常恢复另按隔离 VM 验收。

首轮原生截图中，配置类型过长挤到时间的上一行，流量页标题与 Mihomo 空态被另一条链路隔开，单个 Peer 的表格占满页面，深色页签还有一条浅色系统底线。卡片缩短类型标签，流量标题紧随自身数据或空态，Peer 表格按行数留空间，深色页签关闭系统底线。版本动作在同一行排列。

缩短类型后复测卡片，确认状态文字有独立的单行尺寸预算。状态标签按实际字体和完整文字取宽度，不能依赖时间是否换行撑开卡片。
