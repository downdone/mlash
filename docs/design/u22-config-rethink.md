# U22 配置工作台重设计：先脱离现状，再核对约束

状态：**第二版已迁入运行 UI，原生与发布验证另记**。本稿起初把现有路由、控件、页面层级、Qt Widgets 实现全部当作可替换项；完成任务设计后，才逐项核对产品和工程硬约束。[第一版配置工作台原型](u22-config-rethink.html)保留供比较。用户明确“最常用的是订阅列表和更新”后，默认页面改由[第二版订阅优先原型](u22-subscription-first.html)定义；下文第 5 节取代第一版的默认页面和点击语义。

## 1. 问题与目标

当前配置操作是「配置列表 → 整页详情目录 → 点击功能行 → 浮在详情上的检查器 → 编辑器内视角」。用户必须多次寻找入口，详情目录占满页面却没有直接呈现配置内容。检查器还要在宽窗与目录争空间。截图中的侧栏基准是 184 DIP 宽、32 DIP 项高、6 DIP 间距；它更像紧凑工具列表，四个一级目的地缺乏明确的点击面和呼吸感。

本次不以“把目录排整齐”作为目标。任务是：**选一个配置，直接看到它的内容或来源；在同一屏中编辑、应用、更新；始终看得出选中的配置和正在运行的配置是否相同。**

Daymark 源码中 `NavRow` 让整行承担悬停、选择、键盘和右键，`NavSection` 把对象列表放在侧栏分组中；其可借鉴点是**对象就在导航旁，正文直接处理对象**。Mlash 的配置来源恰好是这类对象。首版三物理列样片虽可用，但在单个订阅时新增来源列仍浪费正文宽度，因此本稿选两栏并把来源放进原侧栏。

## 2. 无约束版本：一个配置工作台

### 信息架构

```text
全局导航： 首页 / 配置 / 数据 / 设置
配置页：
  左侧栏：一级导航 + 配置来源（仅在配置分区展示）
          搜索、导入、远程订阅、本地配置；单击只切换浏览对象
  右工作区：对象标题、当前/候选状态、对象级操作
            节点与组 / 规则 / DNS / 拨号链 / 来源与更新
            当前视角的真实内容与就地编辑
```

没有单独的「配置详情目录」「概览跳板」和第二套任务页签。首次进入某个配置，直接显示「节点与组」内容。选另一个配置只替换右侧对象，沿用同一内容视角。切换工作视角不更换一级页面，不需要“返回配置”。从首页/连接深链进入时直接选中对象与目标视角。

### 布局和导航

- 左侧一级导航建议宽 **228–256 DIP**，含应用名和 4 个高度 **48–52 DIP**、相隔 **8 DIP** 的完整点击行。图标 19–20 DIP；字号按当前 100% 文字比例约 13–14 pt，选中项只用一层浅色背景及中等字重。状态/版本不挤进导航底部，仅状态栏保留必要异常。
- 进入配置分区后，**同一侧栏下半段**显示配置来源与唯一导入入口，按远程/本地分组；来源行高约 60 DIP，只展示名称、类型/上次更新和当前使用标识。对象级更多操作在右侧对象标题，而不重复占用来源菜单。
- 右工作区占余下宽度。对象标题行展示名称、来源类型、当前使用/待应用状态；右侧只保留与此对象相关的主动作。下方是一条稳定的内容视角栏，再下方直接是实际节点/规则/DNS 等内容，不能再是链接目录。侧栏已明确所属分区，不再额外放一条重复的“配置”页标题。
- 840 DIP 宽窗保留两栏，侧栏收至 228 DIP；工作区不横向缩放。内容视角可滚动但首尾有可见边界，不能把“来源”藏进没有提示的溢出菜单。若实测小窗/120% 文字不足，再把来源列表改为侧栏折叠段，而不是恢复整页详情层。
- 浮层只给单行选择、菜单和简短确认。复杂编辑占用工作区正文，采用就地表单和固定的保存/取消栏；不叠加半幅检查器。单个节点、规则条目的少量字段可由行旁的轻量编辑层处理。

### 操作合同

| 动作 | 入口与结果 |
|---|---|
| 选配置 | 来源行单击仅改变浏览对象；“当前使用”由运行观测决定，不随选中变化。 |
| 使用配置 | 非当前对象标题的“设为当前”执行 Controller 事务；结果回读后再改变标识。当前对象不重复出现该按钮。 |
| 更新订阅 | 仅远程来源显示“检查更新”；成功产生候选时出现“查看变更 / 应用更新”，不自动覆盖运行版。 |
| 看/编辑内容 | 点击稳定视角直接进入真实内容；编辑入口只在可编辑对象/覆盖字段旁出现。保存失败留在原视角、字段和焦点位置。 |
| 切对象/视角 | 未保存草稿先留在原对象的独立会话；待提交中的写入暂阻切换。显式离开时给出保存/放弃/继续编辑选择，危险动作才确认。 |
| 无配置 | 来源列只有一条导入主动作；右侧显示目的明确的空态，不渲染空视角栏。 |
| 键盘 | 全局导航、来源列、视角栏、正文依次 Tab；箭头在同级来源/视角内移动；Esc 先关闭菜单，再退出当前行编辑，不悄然丢草稿。 |

### 一屏的焦点

配置页默认焦点是**当前浏览配置的实际内容**；来源列负责换对象，标题负责区别“浏览”和“运行”，视角栏负责换内容种类。管理类动作收在对象标题和“来源与更新”，不与内容列表混排。页面只允许一个显著主按钮，随状态在“设为当前”“应用更新”“保存修改”之间改变。

## 3. 再对照硬约束

| 约束 | 对照结论 |
|---|---|
| 原规格要求 URL/文件导入、多配置、切换、更新与安全回滚 | 全部可在来源列和“来源与更新”视角提供；候选/活动/上次良好仍分开，标题必须清楚标注，不能把浏览选中误写成使用状态。 |
| AppController 唯一状态写入，异步网络/进程/文件 | UI 布局无需改变命令所有权。每个编辑视角继续持有有界草稿；提交、回读和错误按既有 Controller 契约。 |
| C++20 + Qt 6 Widgets，不采用 QML/WebView | 分栏可用 QSplitter/QStackedWidget/QAbstractItemView；视角栏与编辑区用 Widgets 实现。该方案没有要求 Quick 特性的动画或渲染。原型 HTML 只作设计评审，不进入产品。 |
| Windows 优先、窄窗/文字缩放 | 840 DIP 宽时侧栏 228 DIP，剩余工作区约 612 DIP；需测 840×560、1040×720、1440×900 和 100/120% 文字。若实际字体放大导致内容不足，再使来源分组折叠。 |
| 原始 YAML、候选、活动和 LKG 不能混同 | 内容视角须标注所看版本；默认查看活动/来源内容，草稿覆盖另列，候选只有明确打开时才显示。保存不得覆盖原始订阅。 |
| 现行 U11/U12/U22 的「列表 → 详情 → 任务/检查器」 | 这是历史 UI 取舍，**不是安全或平台硬约束**。若采用本稿，应以新 ADR 替代相关表现树决策，并同步交互契约/测试；不能继续把旧详情目录留在后台造成双入口。 |
| Shadowrocket 主要风格、Daymark 的直接操作 | 保留内容优先、少层级和就近选择；侧栏与对象级工作区按 Mlash 的订阅概念重组，不照抄任何产品的页面。 |

本稿与原规格中“不编辑规则”的早期 P1 边界不同：项目现行功能已有规则覆盖编辑。原规格保留，已接受的功能扩展不因重排 UI 被删除；实现时须核对现有 ADR 与 Controller 契约。

### 原型复核

已渲染并查看 1440×900 的「节点与组」及 840×700 的 DNS 初始态。前者只有侧栏和内容两大列，配置来源与一级导航共处，右侧直接显示真实组/节点行；后者保留完整导航与来源选择，内容视角、DNS 开关均未被遮挡。原型的对象切换、视角切换、导入菜单和 DNS 草稿是设计模拟，尚非产品命令或真实数据。还需原生 Qt 复现悬停、键盘、120% 文字与保存失败路径后才可把方案标为实施。

## 4. 对照验收与下一步

本节记录第一版内容工作台的验收想法；默认入口和迁移顺序已由第 5 节的订阅优先方案替代。

原型评审先看五条完整链：①导入→出现来源→查看节点；②选备用配置但不改变当前使用；③远程更新→候选→明确应用；④ DNS 编辑失败→切视角→回来仍有草稿；⑤ 窄窗切来源→返回同一视角。观察是否能在每一步说清“我在看谁、改哪里、是否已生效”。对照截图还要检查 4 个一级导航行的命中高度与间距。

本次交付只冻结**提案**，不对运行 UI 动手。完成原型复核后再建取代旧表现树的 ADR、拆迁移切片，首片只替换配置页容器与一级导航尺寸，随后迁移各编辑器并回归草稿/候选/系统写入边界。不得把原型页面计作已实现或已测试。

## 5. 用户反馈修订：订阅列表先于内容编辑

第一版仍把“节点与组”作为打开配置后的默认内容，相当于把低频编辑抬到了高频订阅管理之前。此项被用户纠正。新的主任务次序是：**看有哪些订阅 → 当前使用哪一个 → 单个/全部更新 → 有候选时明确应用**；规则、DNS、节点定义只在用户明确要求时进入。一级导航可以把“配置”直接称作“订阅”，本地 YAML 仍在同一页面的次级分组中。

这轮先比较**动作入口、点击结果和状态边界**，再调整卡片尺寸、字号与间距。页面是否好用要先用“打开即见列表、更新无需进详情、刷新不误切换、候选不冒充生效”四个可观察动作判断；视觉紧凑程度以此为前提。

### Clash 参考的源码证据与取舍

本地 Clash Verge Rev 的 `pages/profiles.tsx` 把链接输入和配置卡片列表放在页首；`profile-item.tsx` 的卡片主体调用 `onSelect(false)`，刷新图标独立调用 `onUpdate(1)` 并阻止卡片点击，同时展示来源、更新时间、流量和有效期。这些是可吸收的**操作分工**。截图中的长菜单把使用、分享、规则/节点/组编辑、脚本、更新、删除全平铺，规则编辑还占据大型模态窗口；这两处不吸收。Mlash 的候选/活动/LKG 分离也不能被 Clash 的直接更新覆盖。

### 第二版默认页

1. **打开“订阅”即见一个卡片列表**，不默认选中某个配置的节点内容，不显示配置详情目录。页首有一行 URL 粘贴与导入，本地文件在右上角。不按远程/本地拆组；有多个可更新来源时显示“更新全部”。
2. **卡片主体单击 = 使用该配置**，已是当前则无写入；边框和“当前使用”同时表达运行身份。刷新图标是独立命中区，只检查这一订阅的更新，绝不触发“使用”。右键/省略号打开同一对象的短菜单。键盘 Enter 使用、独立刷新按钮可 Tab 到达、菜单键定位同一对象。
3. **卡片常驻必要摘要**：名称、订阅来源域名或本地文件名、上次更新、流量/到期（仅来源提供时）。不展示本地文件完整路径，不把带令牌的远程 URL 放入列表；没有真实元数据就不展示假进度。有源文件的本地配置同样可检查更新；无来源的本地快照不显示刷新按钮。更新中只在该卡片显示进度和取消入口；其他卡片仍可浏览。批量更新使用现有有界 Controller 队列，不对 UI 承诺无限并行。
4. **更新结果就地呈现**：无变化只更新检查时间；失败在卡片内保留简短原因与查看详情；产生候选时同时显示“当前使用”和“更新待应用”，卡片下方给“查看”与“应用更新”，明确当前运行版未变。应用后等待 Controller 验证与回读，再移除候选状态。不能把一次下载完成直接标为已生效。
5. **短菜单只放对象入口**：查看配置内容、编辑订阅资料、分享订阅地址（仅远程）和删除配置。更新方式属于“编辑订阅资料”，不单列菜单项；规则、DNS、节点、拨号链集中在“查看配置内容”的次级工作区，不在订阅卡片菜单平铺四五个入口。高级编辑在主内容区完成，保存/取消和草稿保护沿用原契约。
6. **返回链只有一层**：订阅列表 → 所选配置内容 → 返回原列表位置。点击其他一级导航后回来，仍显示订阅列表及滚动位置。详情/编辑页不是新的一级分区；从外部深链进入时返回到原调用页，不能把用户困在配置页。

### 第二版对照约束

| 现行边界 | 处理 |
|---|---|
| 原规格 URL/文件导入、多订阅、切换、更新、安全回滚 | 第二版默认页直接服务这些 P0 任务；来源与更新信息可见，候选需显式应用，回滚留在低频维护入口。 |
| 选中与实际运行状态分离 | 卡片不再引入“浏览选中”假状态；主体点击发起使用命令，只有回读成功才更改“当前使用”。查看内容通过菜单打开，不暗改运行身份。 |
| AppController 串行写入、异步更新与批量命令 | 单卡刷新、批量更新和激活都映射到现有 Controller 命令；UI 根据操作 ID 与 Profile ID 显示各卡状态，禁止双击重复提交。 |
| 原始 YAML、候选、活动、LKG | 更新反馈保留候选与活动并列，候选不自动覆盖运行版本；失败不清除上次良好。 |
| 现行“配置列表→详情目录→检查器” | 属表现树取舍，不是硬约束。采用第二版时应替代其默认入口和长菜单；低频内容工作区可复用业务编辑器，但不能把旧目录留作第二套入口。 |
| Widgets / Windows 优先 | `QAbstractItemView`/委托或轻量卡片、独立按钮命中、`QMenu`、`QStackedWidget` 足以实现；原型 HTML 不进入运行包。 |

第二版原型已渲染默认宽窗、窄窗候选与卡片菜单三态；最初的 8 步操作链在按本地/远程分组、五项菜单的设计上通过。用户随后继续收敛分组与菜单，见下节；原检查结果不再作为最终原型的验收。它不连接 Controller，不能代表运行 UI。正式实现须以真实状态模型重验写入/回读、失败和取消，再做原生视觉与 DPI 复核。

## 6. 同列订阅与菜单层级修订

用户进一步明确：列表不用按远程与本地拆组。两者都是可使用的配置，来源差异只写在卡片的同一信息位：远程显示域名，本地显示文件名。文件名相同但路径不同的情况，在“编辑订阅资料”页辨识；卡片不暴露完整路径或远程私密 URL。来源类型仍保留在模型中，用于决定刷新、分享、文件选择和更新策略，不以两个视觉分区表达。

菜单以**对象、频率、是否需要连续编辑、是否会改变状态**四项判断。卡片中能直接完成的动作不再重复进菜单；超过单步、需要保存/取消或包含敏感信息的动作进入一层独立工作区或受控浮层。一级菜单不放跳往另一层菜单的“编辑配置”总入口。

| 操作 | 所在层级 | 点击结果与理由 |
|---|---|---|
| 使用配置 | 卡片主体 | 高频主动作；已是当前则只反馈，不产生写入。运行身份待 Controller 回读后改变。菜单不重复。 |
| 检查单个来源更新 | 卡片刷新按钮 | 高频独立命中区；远程 URL 和有源文件的本地 YAML 都支持。无外部来源的本地快照不显示。菜单不重复。 |
| 更新全部 | 页眉 | 面向列表的批量动作，只在至少两个可更新来源时显示；可取消后续队列。 |
| 查看变化、应用候选 | 对应卡片的候选条 | 候选属于该对象，查看与应用必须和“当前运行版未变”同屏；不能藏在菜单或下载后自动生效。 |
| 查看配置内容 | 卡片菜单一级 → 内容工作区 | 包含节点与策略组、规则、DNS、拨号链；此处浏览与编辑，返回同一列表位置。进入内容不改变当前使用。 |
| 编辑订阅资料… | 卡片菜单一级 → 资料与更新工作区 | 名称、来源、自动检查、周期、下载/代理方式、更换本地文件集中成一份草稿；保存/取消和失败留草稿。短菜单无法承载字段及校验。 |
| 分享订阅地址… | 仅远程卡片菜单一级 → 受控展示 | 先提示地址可能包含私人令牌，用户再次明确显示二维码；不在菜单直接复制或展开地址。本地文件无此项。 |
| 删除配置… | 卡片菜单末项 → 确认 | 唯一危险项，与其他动作分隔；确认点明配置名称、当前使用时的安全停止后果，取消无副作用。 |
| 重新加载、回滚、兼容性、源/规则编辑 | 内容或资料工作区的相应位置 | 低频维护、版本或多字段操作；不放一级菜单，不再叠加一个“更多维护”菜单。 |
| 上移/下移、打开数据目录 | 列表的排序模式／设置或诊断入口 | 排序是列表级行为；数据目录不是单个卡片的对象动作。二者不占卡片菜单。 |

最终卡片菜单远程最多 4 项、本地最多 3 项。菜单必须固定被点击的配置 ID；右键和省略号调用同一内容，Esc 收起并把焦点还给原按钮。菜单项不可用时按对象能力隐藏，不用灰色条目凑数；编辑中离开按草稿规则确认，更新中仍允许浏览其他卡片。原型只模拟“删除/分享”入口的反馈文案，未展示真实私密数据或执行删除。后续 Qt 实施需把旧列表、详情和抽屉入口收束成这一条操作链，不能并存两套菜单。

## 7. 配置内容页重审：直达内容，单层返回

从卡片菜单进入“查看配置内容”后，上一版原型仍显示泛化的“这里是某配置的工作区”文字，外层又有“配置内容”标题和对象名称，实际内容不可见。候选条的“查看”甚至指向已从视角栏移走的“来源与更新”，导致入口名与落点不符。这两处说明原型只验证了路由存在，未验证落点是否完成用户任务，属于设计缺陷。

新的内容页以**正在查看哪份配置的哪个版本、可在此查看或修改什么、如何回去**为一屏主线：

1. 顶栏以配置名称为页标题；正文最上方只有“返回订阅”、来源域名/文件名和“当前使用/未使用”“已保存版本”状态，不再重复大标题。浏览对象与当前运行对象分开表达；候选不默认混入内容。
2. 菜单“查看配置内容”直接落在“节点与组”的实际列表，而非“概览”“目录”“再点一次进入”。同一内容页中用稳定视角切换节点与组、规则、DNS、拨号链。视角切换只换正文，不生成第二层详情页。
3. 节点与组先给可搜索的组和节点行，行内显示名称及必要协议/成员数；点击条目做就地查看或编辑，复杂字段在正文一侧/同处展开，不覆盖整个窗口。日常切节点继续在首页，这里不悄然改变运行选择。
4. 规则清楚区分可编辑覆盖与来源只读；DNS 默认先显示“沿用订阅”，启用自定义后才展开字段；拨号链无自定义时给一个明确添加入口。各视角的主动作只与该内容有关，不再出现同一对象的重复“更新/使用”按钮。
5. 候选条“查看”进入独立的**变化对比**视角，展示已保存版与候选版及有界变化摘要；“应用更新”仍是唯一写动作，可从卡片或对比页明确触发。候选过期、来源又变或校验失败时拒绝应用并保留旧运行版。
6. 返回订阅列表恢复原卡片位置、滚动与焦点；视角切换保留各自草稿。未保存内容时，返回或切对象先处理草稿；只读查看可以直接返回。对象在后台删除时退回列表并说明原因。窄窗只让内容区滚动，不把返回和对象身份藏进溢出菜单。

验收不只检查“进入了页面”，还检查菜单落点第一屏确有组/节点行；候选查看确有两版本对照；从各视角、未保存草稿和窄窗返回仍定位原卡片；浏览内容没有 Controller 写入。HTML 原型仅示意信息层级与模拟动作，原生 Qt 仍需独立验收。

### Qt 迁移切片

当前运行 UI 的两张 `QListView`、过滤模型、详情目录和右侧检查器由一张配置列表与同区内容工作区替代。列表只持有配置快照和对象 ID；卡片绘制及按钮命中由一个委托负责，不在绘制代码里调用 Controller。用户输入事件按固定 ID 路由至 MainWindow 的既有命令；刷新、菜单、候选查看/应用必须在发出普通行激活前消费事件，避免误切换使用。键盘聚焦行后 Enter 使用、F5 更新、菜单键打开短菜单；候选动作还需可达的键盘入口。

内容工作区默认打开节点与组的真实编辑器，规则、DNS、拨号链为同级页签；资料与更新、候选对比分别从卡片菜单/候选条单独进入。工作区占正文，不再浮在旧详情目录上。旧详情深链转发到内容工作区；返回恢复列表滚动、对象高亮及焦点。更新列表时按 ID 恢复，不能让行重排把动作作用到别的配置。自动回归至少覆盖远程/本地同列、独立更新不激活、候选不自动生效、详情直达、返回原位与菜单类型差异；原生截图再复核窄窗、文字缩放与菜单锚点。

### 规则工作区对照（2026-11-18）

用户提供的 Clash 规则编辑图用于**操作方式**对照，不改变订阅入口的卡片网格。规则编辑首屏采用双区：左侧仅放新规则的类型、内容、目标与“加入前置/追加”两个动作，右侧是可搜索、可选中并就地删除/排序的现有规则；保存和取消固定在工作区底部。来源规则只读/可屏蔽，规则集声明放在同一工作区的独立视角。输入错误只标在对应字段并保留草稿，不用新弹窗；高级 YAML 和规则集定义按需展开。窄窗先保证两区可达和保存区不被遮挡，再决定堆叠或切换形式。验收检查加入前置/追加后列表即见新规则、切换视角保留未保存内容、取消不写入、保存失败草稿仍在，以及候选版本不会被编辑器误当成已运行版本。

### 维护入口补齐（2026-11-18）

卡片菜单维持短菜单。列表级的“排序”工具只作用于当前选中卡片，提供上移和下移，边界处禁用；执行后按配置 ID 保留焦点与滚动。上次良好版回滚置于来源维护工作区，只有确实存在与当前活动版不同的 `lastGood` 时才呈现；按钮说明将切换运行配置，确认后交给 Controller 的安全激活与回读流程。未保存的来源草稿不能被回滚动作悄然覆盖。验收分别检查菜单不膨胀、排序不误作用其他对象、无可回滚版时不出现按钮，以及确认取消时没有写入。

### 原生视觉复核后修订侧栏（2026-11-18）

1.21.0 离屏卡片样片再次暴露导航仍由旧规格给出 184 DIP 宽、32 DIP 高，且 `sidebarItemHeight` 仅定义而未真正用于 `QListWidgetItem`。这是“设计写了但运行路径没调用”的实现遗漏。将共享规格调整为 228 DIP 宽、48 DIP 行高、8 DIP 行距；在构造导航项时显式设置 `sizeHint`，使悬停与选择命中区覆盖整行，而不是只改字体或内边距。宽窗卡片维持两列，最小窗口回落单列。验收读取运行控件的实际宽度、行矩形与间距，并重看窄窗卡片及内容区可达性。

### 侧栏变宽后的节点卡片边界（2026-11-19）

窄窗 840 DIP、文字 120% 下，侧栏增宽后节点卡片的 `QListView` 用最大可用视口宽度推算列数，而不是布局完成后的实际视口宽度。修正网格宽度后回归仍失败，几何诊断显示两张卡片实际排成一列、每张 52 DIP，但视口被限制为 64 DIP。根因是节点区高度上限仍按 `视口宽度 / 220` 预估为两列，与卡片网格实际采用的 300 DIP 列阈值不一致，第二张卡片被高度上限裁掉。网格按实际视口宽度计算，节点区高度上限复用网格的实际列宽和列数；两处必须同源。维持 100%/120% 文字与 840/1040/1440 DIP 的节点列表、卡片可见性回归，不以放宽测试来掩盖裁切。

包内空态截图还显示“排序”独占一整条工具行；零张或一张配置时该操作没有对象关系。排序工具只在至少两张卡片时出现，空态聚焦导入动作，不保留空工具行。

同一截图中的空态另有“导入配置”按钮，与始终可见的地址输入和“导入 / 本地文件”同义。空态只说明缺少配置，操作直接在页面顶部完成；顶端输入保留键盘焦点和明确按钮。回归应从空页检查可聚焦入口、无重复动作及连接页到配置的路径。
