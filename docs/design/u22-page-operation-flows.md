# U22：逐页操作链与返回上下文

状态：事前设计；以实际代码与可观察操作为准，不能以截图相似度代替验收。

## 源码级对照与原则复核

### 设置搜索与目录视觉分叉（2026-11-18 补充设计）

用户复核后的最终选择：**分组设置目录是主视图**，保留行尾值和就近选项菜单；搜索框常驻目录顶部，进入设置即可输入，Ctrl+F 仅聚焦同一输入。取消“搜索设置”入口、展开/关闭搜索条按钮及搜索触发的页面切换。输入只检索，不修改设置或折叠分组；Enter 和结果数菜单定位到目录行，或进入包含目标字段的任务。无查询时不展示结果数；清空后目录保持原滚动位置。搜索条与目录共用窗口宽度，窄窗不横向滚动。多字段任务仍保留明确返回和未保存草稿守卫。此条取代下段早期“点击后展开搜索条”的设计，避免搜索框还要先点击才能出现。

两张实际截图对应同一设置页的目录态与 `openSettingsTask("all")` 编辑态。目录由 `PrototypeUi::group/row` 生成，采用分组标题、行尾值和单值就近菜单；编辑态由 `settingRow` 平铺全部控件。搜索按钮在选择任何结果之前就切到编辑态，`SettingsSearch` 又被放在编辑态顶栏右侧，产生一整块空白、不同字号/行密度、重复信息架构。根因是把“检索”实现为一个完整编辑任务，而不是目录上的临时查找。

设计：设置目录仍为搜索的上下文。点击“搜索设置”或按 Ctrl+F，只在页面内容顶部展开紧凑搜索条；结果菜单锚定结果按钮。输入、Esc 清空和结果选择均不重建目录，不改变设置。选目录项则在目录中定位；选仅存在于编辑控件的项，才进入其所属的启动、网络、内核或维护任务，并把目标行滚入视口。搜索条留在同一位置，便于再次查找；关闭搜索条只清查询与标记，不取消当前任务。切到其他编辑任务前若已有未保存网络草稿，拒绝搜索定位并保留草稿，不自动确认放弃。目录和编辑任务各自保留必要的控件，但不再有“全部设置”这张临时混合页。窄窗时搜索条随内容区缩放，不产生横向滚动；键盘焦点留在输入，结果菜单支持 Esc；返回任务回目录保留目录滚动。验收核对搜索点击后仍在目录、紧凑搜索条顶端、行定位不提交、不同任务跳转、草稿保护与同一窗口位置。

Daymark 的 `Main.qml::navigateSafely` 在切换前处理保存中和脏草稿；`TaskRow.qml` 分开单击速编、双击完整编辑、右键对象命令，`NavRow.qml` 给键盘菜单与焦点状态同等入口；`style/Menu.qml` 在展示前整理可见命令、测量、锚定、限高，并在宿主移动时退出。Mlash 的对象是运行内核、配置、节点和观察数据，不能照搬任务编辑动作，但应沿用 **对象身份固定、主次动作分离、切换前处理草稿、返回来源、菜单从锚点出现** 的方法。

任何 UI 改动先回答：该页要完成哪一件事？主动作会不会写入？动作结束后用户还在原对象和原位置吗？菜单关闭或失败时输入和焦点去哪？危险动作才确认。此轮优先修操作链，不把“多加按钮/改圆角”当作完成。

## 逐页区域与操作契约

| 页面/区域 | 用户主路径 | 当前代码中的断点 | 目标与验收 |
|---|---|---|---|
| 首页·控制区 | 查看当前成员 → 开关接管或切模式 → 原处看观察结果 | 状态/路由分别更新，路由菜单已非阻塞；外部代理接管有安全确认 | 开关读写结果由状态栏和当前行表达；模式菜单唯一勾选、Esc 归还焦点；没有内核时给明确下一步。 |
| 首页·节点区 | 选浏览组 → 搜索/筛选 → 选节点或点延迟 → 看详情/返回 | 列表与卡片点击语义不完全相同；切组可能重置列表滚动，测试与应用都是图标操作 | 明确当前运行成员和浏览组；名称单击遵守组类型，延迟只测速，信息只看详情；换页回来保留组/筛选/滚动。 |
| 配置·列表 | 找远程/本地配置 → 打开详情 → 返回原行 | 同一行同时接 `clicked`、`doubleClicked`、`activated`，多次重建详情；从其他分区返回配置时 `navigate` 强制清空详情 | 单击或键盘激活只开一次；再次打开同一详情不重建输入/滚动；跨分区返回仍在原详情和原行；只有明确“返回配置”才退到列表。 |
| 配置·导入/维护 | 就近选来源 → 输入/预览候选 → 显式应用；右键执行当前对象命令 | `+` 与“导入…”有重复入口；右键动作从执行时全局选中行重新取 ID | 配置页只保留“导入…”行及三来源菜单，首页顶栏 `+` 仍可快速添加；菜单锁定打开时的配置 ID，行重排/刷新也不能作用到别的配置；失败保留来源和草稿。 |
| 配置·详情/编辑 | 读候选/活动状态 → 点规则、DNS、节点等 → 完成后回详情 | 详情由 `showProfileDetails` 无条件重建；离开分区清详情；工作区和详情的返回层级不显式 | 返回链为编辑 → 详情 → 列表；未保存草稿不可被再次点击或切页静默丢弃；对象删除后退回列表。 |
| 数据·四页签 | 选流量/连接/测速/日志 → 筛选/观察/就近处理 | 页签保留，但连接与测试采样随可见性停启；连接右键已按打开时 ID 固定 | 每页签保留过滤/滚动与选中；工具仅在所属页签出现；复制、断开、重测反馈在原处，切页不误操作旧对象。 |
| 数据·规则与连接详情 | 从连接读命中规则 → 跳到规则编辑/组 → 返回连接 | 深链可越过来源状态；规则草稿和连接选中生命周期不同 | 深链显示来源与返回入口；脏规则草稿先处理；返回仍能定位同一连接，若连接消失则说明原因。 |
| 设置·目录/任务 | 找设置项 → 在行上切换单值或进入任务 → 保存/取消 → 回原目录位置 | 目录与任务为双栈；离开设置时可能保留隐藏草稿，`navigate` 缺统一切页守卫；搜索结果仍调用未测量的原生 `QMenu::popup` | 行开关就地生效；多字段任务显式保存/取消；脏草稿切分区须先确认或保留；搜索菜单展示前测量并贴近结果按钮，返回同目录锚点与滚动位置。 |
| 全局导航/菜单 | 侧栏换分区、Esc 退出临时层、窗口隐藏/恢复 | `navigate` 首句直接切 `contentStack_`，对编辑草稿没有统一守卫；部分菜单由 `Show` 事件修位置 | 路由先验证目标和草稿，再更新可见页面；临时菜单跟随锚点生命周期，跨页关闭；拒绝导航时恢复侧栏选中。 |

## 本片施工顺序与边界

1. 配置页修复单击/双击/激活重复事件；对同一详情开关幂等，跨页返回保留配置详情。对象失效时才回列表。滚动、名称编辑中的输入不被重复点击重建。
2. 全局导航对网络设置/规则和已挂载任务草稿保留上下文；返回来源分区恢复原任务和输入。正在提交时阻止切页并恢复侧栏。只有明确取消任务、切换编辑对象或退出才询问放弃，不能因跨页搜索引入额外确认。复用现有 `DialogDraftGuard` 与 Controller 命令，不绕过业务层。
3. 配置右键操作锁定打开时的 ID，刷新/重排后回查该对象是否仍存在。菜单项只有适用时可用；删除保留确认。
4. 其余首页、数据与设置链按表格复核并逐片实施；截图只验外观，操作测试要覆盖返回、重复点击、Esc/焦点、失效对象及脏草稿拒绝导航。

深链在调用 `navigate` 后必须核对目标路由实际到达，才可以继续构建配置详情或编辑任务。提交中被守卫拒绝的路由不能让后续操作落入原分区的工作区。

## 第二片：规则与搜索入口的对象链

源码复核发现规则页的“前往订阅”按规则页签选择旧编号 0 或 1：切到内核规则页时会落在首页，标签与实际目的地不一致。该入口固定前往配置，并在来源配置仍存在时打开其详情；如果导航被提交守卫拒绝，不继续打开详情。连接详情的“定位策略组”在完成路由后也核对首页节点锚点，再改变浏览组。设置搜索中目录锚点仅在设置页确实可达时切换目录栈；正在应用设置时不得把编辑区藏在目录之后。

验收以路由和可见对象为准：两个规则页签的“前往订阅”都落在配置，且来源对象存在时显示同一配置详情；提交中拒绝切页时搜索锚点不会改变目录/任务栈；连接详情无法到达首页时不会偷改浏览组。以上只控制 UI 路由，不改业务状态。

## 第三片：首页节点两种视图的同一对象

列表和卡片是同一批成员的两种呈现。当前 `nodeBookmark()`、进入子组以及视图切换都从行列表读取当前项；在卡片视图中，隐藏行列表的旧选中会覆盖正在看的卡片。设计为统一从**当前可见视图**取成员名，切换呈现时在目标视图中同步选中并滚动，恢复书签时也按当前呈现恢复选中。验收：卡片选中 B 后保存书签得到 B，切回行列表仍选中 B；从卡片进入策略子组要进入 B，不受旧行高亮 A 影响。只有名称有效且为组时才进入。

节点右键只在成员上提供“收藏”，组头与空白处无此对象命令；菜单使用统一的展示前测量与屏幕边界锚定。连接详情中“添加规则…”也使用同一菜单定位方式，避免在窗口边缘与不同 DPI 下先显示方角/跳位再修正。

配置的旧编辑命令虽然已从可见短菜单移出，仍可由动作系统调用；它们也必须按打开时固定的配置 ID 取对象，不能从后来改变的全局高亮重新取值。规则页的显式返回按钮同样在路由真实到达配置后才恢复详情。

本设计不变更内核协议和存储格式。依旧使用 Qt Widgets；复杂编辑留在正文工作区，文件选择使用系统面板。未跑的原生鼠标、缩放和系统写入不算已验收。

## 第一片实施后逐项复核

首页节点区：卡片视图 Enter/双击现在从可见卡片读取成员，行列表从可见行读取成员；二者走同一个手动组写入守卫，自动组只打开详情。列表/卡片切换后的旧高亮不能再指向另一视图中的对象。单卡延迟点击与详情入口保持原有独立命中。

第二、三片复核：首页书签、切换行/卡与进入子组均以当前可见成员为准，目标视图同步选中；节点右键只对有效成员出现收藏命令，连接详情规则菜单和节点菜单都在展示前按锚点定位。规则页不论当前编辑页签都从“前往订阅”回来源配置；连接详情定位组在确认已到达首页节点区后才改浏览组。设置搜索在提交中或隐藏脏任务时不伪装成成功定位。新增隔离回归覆盖卡片 B、子组 B、规则两个页签及脏设置目录搜索。

配置列表：普通单击打开详情，键盘激活可打开详情，Ctrl/Shift 点击保留批量选择；右键在打开时把该行变为唯一对象，并固定其 ID，命令触发前回查该 ID 仍存在。详情重复激活不重建；从首页、数据或设置回配置时保留详情实例、滚动与原列表位置。配置页的顶栏 `+` 不再与“导入…”行重复，首页仍提供快捷添加。更新/应用/删除继续由 Controller 负责，删除确认不变。

全局导航：离开活动任务工作区时，提交中禁止切页并在工作区提示；其余草稿随所属分区保留，返回时恢复工作区、输入和滚动。网络设置任务与规则草稿也保持在原处，只有显式取消/切对象才进入现有放弃确认。设置目录的原有滚动容器未重建。设置搜索的结果菜单改用显示前测量与锚定。数据四页签的采样生命周期、连接右键固定 ID、日志工具带和设置行内单值动作本片未修改。

尚待后续逐页交互验收：真实鼠标/键盘与 150% DPI 的原生检查；节点切组时筛选/滚动的可预测性；连接详情深链回来源连接；配置导入失败与候选版本的多来源人工任务链；设置搜索定位和跨任务返回锚点；系统托盘实际菜单。上述不计入本片自动通过项。

## 第四片事前审计：逐页、逐区域与对象生命周期

这次以 Daymark 源码的 `Main.qml::navigateSafely`、`NavRow.qml`、`TaskRow.qml` 和 `style/Menu.qml` 为操作对照：导航前保留或处理草稿；行本体、次级图标和菜单各有唯一语义；菜单从对象旁展示，测量后再弹出；详情返回原列表位置。下表记录 Mlash 的实际代码路径及本片处理方式，不把外观相似当作交互验收。

| 页面 | 区域与主任务 | 源码审计发现 | 设计处理 / 验收点 |
|---|---|---|---|
| 首页 | 当前连接、代理开关、路由模式 | 当前行标题与状态分开刷新；状态明细多数时候隐藏；外部代理接管有安全确认 | 保留风险确认；主动作只做接管，路由模式用锚定单选菜单；待确认当前行点击含义前不增隐式动作。状态应区分内核运行与系统接管。 |
| 首页 | 连接性测试 | 快测图标与网站测试跳转图标都已连接，但后者被强制隐藏 | 先明确「行本体打开网站测试、尾部图标执行快测」还是整行只快测；未定前不改实际测试范围。 |
| 首页 | 节点浏览 | 搜索、排序、收藏、测试、组内切换、详情同时存在；两视图对象身份已统一 | 名称区域只执行该组允许的选用/进入，延迟只重测，信息只看详情；切组保留过滤和当前对象，空结果给恢复入口。需要实际鼠标与键盘验证。 |
| 配置 | 远程/本地列表 | 单击打开详情，Ctrl/Shift 留给多选；右键固定打开时 ID；再次激活同一详情不重建 | 当前对象与运行对象分别表达。**新断点**：从详情切到另一配置时，已打开的名称编辑会被整页删除，未保存输入静默丢失；先阻止切换，恢复原行并把焦点交还输入。 |
| 配置 | 导入、候选、维护 | 导入来源已就近选择；更新、替换、分享、删除在对象菜单；候选与活动版本分离 | 失败保留来源和输入；应用候选前看差异；删除确认留在危险动作。对文件面板之外的任务弹窗继续按对象流梳理。 |
| 配置 | 详情与规则/DNS/节点/链 | 详情行进入 `TaskWorkspace`，部分编辑仍由 `TaskDialog` 承载；返回链已保留详情实例 | 规则/DNS 等编辑不因切主分区丢草稿；从任务返回详情，再返回列表；对象失效时明确退出并保留反馈。 |
| 数据·流量 | 速率、累计、出口诊断 | 采样只在可见时运行；详细指标折叠；诊断是独立任务 | 概览展示观察时间/采样状态，折叠不改采样；出口诊断返回流量页原位。 |
| 数据·连接 | 活动/结束、搜索、列、详情、断开 | 刷新时按连接 ID 恢复选中与滚动；右键固定 ID；详情是抽屉，但跳组或建规则后没有来源返回锚点 | 观察快照和当前连接分开；断开只作用打开时 ID；深链增加来源返回路径前先确定连接消失时落点。 |
| 数据·测速 | 选节点、全测/单测、结果详情、目标编辑 | 旧实现选节点会清结果；离页停止采样；`WebsiteTargetsDialog` 已由 `presentTaskDialog` 挂载进主窗口 `TaskWorkspace`，只是类型名仍叫 Dialog | 结果明确绑定测试节点；单测反馈留在原卡；目标编辑复核工作区呈现、脏草稿取消和返回原测速页，不重复迁移已有页内功能。 |
| 数据·日志 | 搜索、级别、暂停、复制、导出 | 复制/清空有隐藏的旧按钮；导出同时创建菜单动作与顶栏按钮，菜单动作随后移除 | 工具只保留可见且唯一的入口；复制选中文本和清空视图属于日志操作菜单，导出在顶栏；切页回来保留搜索与滚动。后续清理不参与布局的旧控件。 |
| 设置 | 目录/搜索/单值 | 设置行的单值选择用就近锚定菜单；搜索可回目录锚点；即时值提交 | 搜索结果定位前确认目标可见；目录位置与焦点恢复；单值菜单只显示适用值，Esc 不改设置。 |
| 设置 | 网络草稿/备份/内核/工具 | 网络值显式应用，跨任务可弹弃稿确认；`openSettingsTask("all")` 可绕过不同任务脏草稿检查并重排可见行 | 搜索是临时查找，不得重排仍有脏网络输入的任务；显式取消/应用后才能切任务。备份与内核任务保持独立对象身份。 |
| 全局 | 侧栏、标题、状态栏、托盘 | PageRouter 管一级路由；任务工作区是另一层；状态栏承载运行反馈；托盘菜单另有容量限制 | Esc 只退出最近临时层；被拒绝的导航恢复侧栏高亮；托盘少量高频动作，全部配置和节点回主窗口。 |

本片先修两处确定的数据丢失路径：配置名称草稿切对象，以及设置网络草稿从搜索进入「全部设置」时的绕行。两者均以已有单对象草稿模型处理：拒绝隐式切换并给就地反馈，用户显式保存/取消后再进行。记录测试的输入、原对象、可见页与焦点；不改 AppController 或持久化格式。完成后再逐页继续，不以这两处覆盖全表。

### 集中待答的产品问题

用户确认（2026-11-18）：首页当前节点的名称区域只展示、不响应点击；首页「连通性测试」直接测试**当前策略组所有节点**，测速过程中允许切换当前节点，不跳网站测试页。从连接详情定位策略组后回连接页，恢复原筛选与列表位置，不自动重开详情。网站测速切换测试节点时暂存旧节点结果，切回可看，不立即清空。配置规则/DNS/节点和测速目标编辑逐步统一为页内工作区与一致布局；系统文件选择及危险动作仍需确认。

后续实现边界：组内测速使用已有有界并发/取消命令，测试按钮不锁住当前节点选择；网站结果按节点身份保存有界快照，避免跨节点显示误导，「清空结果」明确清除全部暂存结果。连接返回保留过滤、视图、滚动和选中 ID，ID 消失时只保留位置而不重开旧快照。编辑迁移以对象键、草稿守卫和返回链为先，不将现有模态面板简单嵌入页面后宣称完成。

连接返回切片事前复核：`setConnectionsVisible(false)` 按安全约定清除观察快照，并触发表格模型重建；现有 `updateConnections()` 仅从重建当时的滚动条读取位置，离页位置由此丢失。离开连接页签、切主分区或隐藏窗口之前只保存 UI 书签（滚动值、选中 ID），不保留已失效的连接详情；搜索文本、列偏好和活动/结束选择继续由原控件保存。返回后等新可见快照产生可筛选行时恢复一次书签；ID 已消失则只恢复滚动位置。若筛选结果为空，书签等待后续有行的快照，不将旧连接内容当成当前观察。验收覆盖跨分区与数据页签两种返回，详情关闭且不会自动重开。

日志工具切片事前复核：当前代码同时造出隐藏的「复制选中」「清空视图」按钮和可见菜单动作，导出动作先加进菜单又移除，再作为顶栏按钮复用，导致对象和启用状态不清晰。保留搜索、级别、暂停与按需出现的「回到最新」；「复制选中」「清空视图」「自动换行」「日志目录」只在就近日志菜单中；脱敏导出只有顶栏一个入口，忙碌或退出时禁用。动作直接作用日志文本选择，隐藏控件不再充当中介；Esc 关闭菜单不改变内容。日志抽样生命周期、脱敏协议和系统保存面板保持原契约。

日志清空的失败路径：暂停状态由 UI 保存 `pausedLogs_`，仅调用 Controller 清空可见日志会让旧暂停快照继续显示。清空命令先清这份只读 UI 快照，再清 Controller 视图，刷新空态；不删除磁盘日志，也不悄悄恢复采样。验收覆盖暂停后清空和随后恢复显示。

目标编辑复核：`WebsiteTestsPage` 调用 `presentTaskDialog()`，它沿父链交给 `MainWindow::presentTask()`，最终由 `TaskWorkspace::mount()` 挂入正文；类名为 `WebsiteTargetsDialog` 不代表实际模态窗口。保留这一页内编辑路线，补断言确认编辑器位于可见工作区、取消后返回原测速页。后续把规则/DNS/节点编辑按同一对象键、提交守卫、返回语义逐项验收，不为形式一致性重写已正确的目标编辑器。

网站结果暂存的最小切片：`WebsiteTests` 当前只有一个 `node_` 和一份 `results_`，切节点调用 `clear()` 会把旧结果销毁。增加至多 8 个其他节点的内存快照，按最近使用淘汰；用户在网站测试页选节点时切换视图，不发请求、不改当前代理节点；全测和单测只覆盖该节点对应目标，切回恢复原节点的结果与时间。显式「清空结果」、目标定义变化或内核/配置状态写事务仍清全部快照，保证不同内核配置的结果不混用。UI 下拉只经 Controller 命令更改测试视图，详情抽屉若与新节点不符则关闭。测试覆盖 A 测试、B 测试、切回 A、清空以及 8 个缓存上限。

首页组内测速的最小切片：现有首页按钮运行 `ConnectivityProbe`，只测当前叶子；`testNodes()` 会占用 Controller 的全局 `busy`，导致测速中无法切换成员。托盘组延迟管线已有独立请求/取消和缓存，不占用全局事务。为首页显式整组测速复用其有界请求池，但区分托盘悬停和首页主动操作：只允许**首页启动的**整组测速在 `MemberSelect` 写事务期间继续，其他写事务仍取消；只取消自身回复，不调用全局 `CoreApi::cancelAll()`。首页显示组名与已测/总数，按钮可停止；节点选择仍由 Controller 串行化、回读和保存，测速回复仅更新结果。托盘悬停测速的原取消契约不改变。验收为整组开始 → 即刻切节点 → 当前成员成功回读 → 余下测速仍完成；内核停机或订阅变更则取消。

### UI 交付验收流程修订（设置搜索回归）

本次设置页问题不是单个控件外观错误：目录入口和搜索入口曾分别通往不同组件体系。只看搜索后截图会遗漏进入前的状态；旧、新预览包又都显示同一产品版本，使截图证据与用户运行的包无法直接对应。现有包内冒烟仅检查八张图片数量，独立定时器切页与截图会重叠，实际可把后一个数据页误存成设置页。

以后 UI 切片先列出受影响的**操作路径**，至少覆盖入口、触发前、触发后、取消/返回、再次进入以及草稿/失败状态；列清每一步的可见页面、控件体系、焦点与业务副作用。共享菜单、列表、标题栏或搜索改动要沿所有调用页检查相同组件的状态，而不是以单张优化态截图代表完成。自动测试断言路由和可见对象；包内冒烟串行切页、核对路由再截图，并对照片名与页面身份。截图仅证明对应构建的可见结果，原生人工与真实系统操作另记。

交付预览时记录唯一包名、哈希和实测包路径；同版本的旧预览不得冒称当前候选。只有包内检查和针对性操作链都通过，才可写“已验证此交互”。若扩大套件失败，逐项保留失败，不把定向通过写成全局完成。
