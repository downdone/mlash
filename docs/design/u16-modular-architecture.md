# U16 模块化架构与界面边界

## 功能定义与验收

本轮保持现有用户功能和数据兼容性，重构代码的所有权与依赖方向。验收以原有功能回归、构建、文档检查以及静态边界检查为准；不以本机系统代理写入或长稳运行充当证据。

1. `AppController` 继续是运行状态和持久化意图的唯一写入者。界面事件只调用命令，并从状态快照渲染。
2. 共享的列布局、测速目标和 TUN 选项校验属于不依赖 `app`、`core`、`ui` 的契约模块；存储和配置解析不能反向引入上层。
3. UI 拆成按职责命名的文件：基础控件、配置列表绘制、节点卡片、节点行模型与视图、导航/顶栏。迁移期间允许兼容聚合头，收尾时删除。
4. 每个文件的公开接口只暴露消费者需要的类型；跨页面状态仍由窗口/Controller 管理，不在控件中复制业务真相。

## 六层设计

| 层 | 职责 | 对外契约 |
|---|---|---|
| domain | 无 UI、无 OS 写入的值对象和纯校验 | 显式输入、结果，不持有 QObject |
| storage/profile | 状态文件、版本和源配置 | 候选/活动/已知可用分离；原子提交 |
| platform/core | OS 适配、内核进程与 API | 异步结果和实际状态回读 |
| app | 命令串行、任务代次、快照 | UI 可调用命令与观测状态 |
| ui/components | 单一控件、模型或委托 | 视觉状态、明确的事件信号/回调 |
| ui/pages | 页面布局及生命周期 | 从快照更新，向 Controller 发命令 |

依赖只朝下：UI → app → domain/profile/core/platform/storage；通用纯校验放在 domain。兼容转发头只作迁移桥，收尾后删除，不增加第二份逻辑。

## 协议、事件与状态

- 内核能力接口 `CoreApi` 只描述现有客户端实际使用的配置、版本、代理组、规则、连接和延迟探测等命令。`MihomoClient` 是目前唯一实现，负责特有 REST/JSON 映射；Controller 持有该实现，`CoreManager` 和只读采样会话依赖接口。暂不增加内核插件发现、动态切换或第二种协议的假实现。取消句柄暂沿用 `QNetworkReply*`，后续统一请求句柄时再迁移，不影响当前代次语义。
- 内核 HTTP/JSON 路径由 `MihomoClient` 解释。Controller 使用具名方法；版本、运行配置和代理组集合有类型化 DTO，其他端点仍为有界 `Result`/JSON，不宣称全部静态化。页面不拼接路径。
- `AppController` 的命令结束结果保留 OperationId 和代次，界面只能显示当前任务的结果。
- 页面进入/离开与同页锚点跳转分开理解。页面负责清理自己的采样、草稿和焦点；轻量模式销毁全部页面对象。
- 代理/TUN 的意图、OS 观测、内核就绪和节点健康仍为四种独立状态。恢复日志写入与完整快照匹配规则不改变。

## UI 设计前复核

本轮结构调整不改变 Shadowrocket 方向的信息架构、文字尺寸、间距、主题和页面操作位置。已有首页/配置/数据/设置各页面保持原布局。控件拆分后逐页复核：空态、加载、失败、取消、草稿/候选/运行版，鼠标与键盘，窄窗、DPI、主题，以及隐藏与轻量重建。交互入口和状态写入不因文件拆分改变；如发现需要视觉修改，先补充独立设计和验收点。

## 实施顺序

1. 建立模块边界并拆分 `MainWindowParts.h`，保留兼容聚合头。编译和现有 UI 回归证明行为等价。
2. 把存储/配置使用的纯校验从 `app`/`core` 移入 domain，消除反向依赖，保留原业务规则与回归。
3. 对 Controller、内核协议与页面生命周期继续按垂直功能切片，先固定接口，再迁移消费者，逐片构建与回归。未完成片明确留在项目状态，不宣称整体架构已收口。
4. 以实际调用面提取 `CoreApi`，让 mihomo 作为特化实现；测试进程管理、测速和取消语义，不以抽象层本身当成功能验收。
5. 按[独立 UI 设计系统](u16-shadowrocket-design-system.md)把语义 token、Shadowrocket 取值与 Qt 运行时适配分开；页面任务和分组不因风格抽取而改变。
6. 按[测试架构](u16-test-architecture.md)把最小纯契约目标与隔离集成、Controller 场景及 UI 交互分层，默认系统写入门禁不变。

## 风险边界

头文件拆分可能暴露原先靠偶然包含满足的依赖；逐消费者补显式 include。纯校验迁移不得改变序列化格式、代理/TUN 读写顺序或权限服务协议。本机默认测试不得修改系统代理。

## 收尾迁移设计

兼容转发头仅用于过渡；先把 `app/Types.h`、`app/ConnectionColumns.h` 消费者改为 domain 契约，再删除转发头。UI 页面聚合头按页面替换为所属组件及必要 Qt 头，不能用另一个大聚合头代替。`MainWindow` 作为 Qt 父对象仍拥有页面实例；页面的进入/离开采样由 `PageRouter` 负责，禁止页面自己持有 Controller 写状态。对内核 JSON 只为已稳定且跨多消费者的响应建立 DTO，要求在适配层严格解析并保留现有 Result 错误语义；未覆盖端点明确保留 JSON，不宣称全部静态化。每片按编译、取消/失败和页面轻量重建回归验收。

本轮 DTO 范围固定为内核就绪链的版本与运行配置，以及 Controller 多处使用的代理组集合。适配层验证字段类型，调用方只读取命名字段；内核返回的原始对象仅用于向既有状态快照透传，避免更改 UI 数据格式。缺失/类型错误仍是失败，而不是让默认值伪装为有效观测。页面注册指针改为 Qt 弱引用，主窗口销毁页面后路由器不可再调用它们。公共 Controller 头的依赖缩减以 UI 头不引入完整实现为边界；命令仍由 Controller 实例执行，暂不制造第二状态持有者。

## 实施后复核

已拆出 domain 静态库与 UI 控件/模型/委托文件；主窗口和 Controller 的长实现按职责分到多个编译单元。持久化对测速会话、TUN 运行策略和平台快捷键类的反向包含已消除。Controller 对内核 REST 走具名端点，版本/配置/代理组响应经严格 DTO 解析；`CoreApi` 将 mihomo 具体协议留给适配实现。UI 语义规格、Shadowrocket 取值及组件 QSS 与 Qt 运行时适配分开。旧 `app/Types.h`、`app/ConnectionColumns.h` 和 UI 三个聚合/兼容头已删除，静态边界测试禁止回引。UI 公开头只前置声明 Controller，避免把其宽实现头传递给每个控件。页面仍由 Qt 父对象拥有，`PageRouter` 用弱指针登记并在页面销毁后安全失效。测试按边界标记，纯路由用例从混合 UI 文件抽离。此轮没有改动页面布局、控件外观、文案、默认焦点和操作位置；视觉与键盘路径沿用 U15。Controller 命令面因既有功能仍较宽，未覆盖的内核端点仍使用 JSON；这两项是明确的后续演进边界，不影响本轮所有权与依赖方向验收。实际构建与测试见验证报告。
