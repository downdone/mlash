# U18：并发测速、窗口顶栏与应用在线更新

## 原则审视与功能定义

维持首页选节点、配置管理、数据观察、设置偏好四个任务入口。窗口顶栏仅承担拖动、最小化、最大化/还原和关闭，不再放一份导航或代理状态。系统标题栏仍可在设置中选回；窗口外观不改变内核、代理与 TUN 的生命周期。整组测速保留逐节点结果、进度、取消和错误，采用有界并发异步请求，不为每个节点建立 OS 线程。应用更新只认项目固定发布源与已发布资产，不从订阅或内核更新源接受可执行文件。

Daymark 参考项目当前没有应用内更新器；借用其发布政策中版本/标签一致、不可变发布源、资产与散列核验、失败不覆盖旧版本的原则。Mlash 自身下载和校验路径仍以本项目包白名单与 release manifest 为准。

## 模块、接口与状态

| 功能 | 所有者 | 输入与输出 | 失败/取消 |
|---|---|---|---|
| 整组延迟 | AppController → CoreApi | 去重、最多 500 个成员；固定小型并发窗；逐项 `nodeDelay`、`delayProgress` | 代次隔离旧回包；取消清队列并终止在途请求，不写节点选择 |
| 窗口顶栏 | UI 组件及 Windows 平台适配 | 设置中的「系统/应用内」偏好；本地关闭/拖动/缩放命令 | 无法安全建立自绘窗口时退回系统模式；不改变配置或代理 |
| 在线更新 | AppController 拥有更新会话，网络服务在 app 层 | 固定 GitHub Release 的版本/资源/散列 → 已核验的独立候选；UI 显示当前/新版/下载/失败 | 超时、重定向、体积、散列、版本、取消均停在候选前；运行包保持不变 |

发布顺序：设计 → 实现 → 单元/集成/原生交互 → 包内冒烟与白名单 → 提交/推送 → 标签发布 → 远端资产复核。未执行的平台/系统测试如实记录，预发布不冒称正式发行资格。

## UI 设计

应用内顶栏直接复用现有中央分区页眉与操作槽，右侧加入最小化、最大化/还原和关闭；两侧等宽动作槽维持标题居中，不叠加第二条标题。控件的可见/悬停/键盘焦点沿用现有字阶、颜色与圆角；关闭只在悬停时出现告警底色。原生模式隐藏三项窗口控件。设置目录的「外观」任务内增加窗口顶栏选择，说明切换只重建界面、内核继续运行；键盘和窄窗可达。最大化、恢复、系统拖动与边缘缩放要复核。

更新入口归设置维护，不在首页常驻提示，也不弹启动模态。检查后只显示规范版本、发布说明链接和一项明确下载动作；下载期间状态留在固定区，不挤压正文。下载成功为「已验证候选」，明确提供打开候选包；便携包的替换由用户在退出 Mlash 后完成，不假装在线下载等于已安装。任何下载失败都不能让界面显示已安装。更新不记录 Release 原始 JSON、下载 URL 查询或私密路径到日志。

## 验收

1. 整组测速在测试夹具中证明有界并发数大于旧值 3、少于上限；进度数、单节点重测、取消、旧回复无污染。
2. 系统/应用内标题栏均可设置并恢复；应用内窗口拖动、双击最大化、边缘缩放和三个窗口按钮在 Windows 原生后端可用。状态和正文在两模式不跳位。
3. 更新夹具覆盖新旧版本、错误资产/散列、超时/取消和候选不覆盖运行版；无效响应不提供安装动作。仅以发布资产的签名/散列和固定来源给出候选。
4. Windows 本机构建、定向及发布检查、便携包内冒烟通过；远端发布后复核标签、八项附件及其哈希。没有实际执行的干净机、系统代理/TUN、72 小时稳定性不标通过。
