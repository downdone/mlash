# U25：更明亮的 macOS 式语义配色

2026-11-19。用户指出 U24 后整体偏灰，要求全局提亮并参考 macOS 配色。先核对 Mlash 当前 `Colors`、样式表与明暗页面截图，再依 [Apple 色彩指南](https://developer.apple.com/design/human-interface-guidelines/color) 的语义颜色、界面层级及明暗/增强对比原则设计。这里借用表面层级，不声称复制某个固定 macOS 系统颜色值；Windows 上仍由 Qt Widgets 语义 token 渲染。

## 页面任务与原则审视

首页控制区、配置卡片、数据列表和设置分组都需要先辨认内容与操作。当前浅色 `Window=#FFFFFF`，但 `Surface=#F6F6F8` 让所有内容块偏灰；`Sidebar=#F3F4F6` 与卡片灰度接近，层级靠背景差而非信息主次。全局提亮应覆盖四个主页面、菜单与输入，而不是单独美化卡片。

浅色改为近白窗口画布、纯白内容/菜单表面、浅灰侧栏和轻灰控件。分隔线只用于真实边界，选中状态使用淡蓝面；蓝色只给主要动作、当前状态和键盘焦点，普通文字保持中性色。暗色改为较柔和的深灰层级，不改变用户选择的暗色外观。增强对比套色保持独立。字体、字号、几何、信息密度、导航与业务操作链不在本片改变。

## 状态和验收

主题切换只重绘外观，不更改 Controller 状态、草稿、路由或滚动。空态、加载、失败、候选、当前配置、悬停、焦点以及弹出菜单都继续使用既有语义。100%/120% 字号和常规/窄窗应无颜色断层；正文、次级文字、链接及状态文字对窗口/侧栏/内容面保持至少 4.5:1，高对比边框与焦点保持既有门限。浅色应呈现「白内容面在近白画布上，侧栏稍灰」；深色不能被意外提成亮色。

实施仅调整集中颜色 token；若截图显示某组件继承错误表面，再在该组件样式修正，避免页面私有颜色常量。执行外观与导航/卡片相关测试，生成四主页面明暗截图并检查菜单；结果写入验证报告，未做的原生显示器观感不记为通过。

## 实施后复核

`ShadowrocketStyle::light/dark` 集中调整，页面样式、几何和 Controller 均未修改。浅色截图中的首页控制区、配置双卡、数据表、设置分组均使用纯白内容面与近白画布；侧栏稍灰，导航选中仍清楚。深色四主页面保持暗色，内容面比画布稍亮；托盘菜单和设置下拉沿用同源颜色。100% 与 120% 文字缩放、940×620 和 840×560 的外观回归通过；对比度断言覆盖明暗与增强对比。包内隔离启动的八路由截图同样符合层级。离屏截图不能替代原生显示器或读屏验收；后续若用户认为浅蓝选中面仍过重，应基于真实屏幕截图再微调，不在本片盲目改变状态语义。
