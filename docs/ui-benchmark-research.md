## 一、Clash Verge Rev：宽而浅

### 一句话

**组织复杂度的核心机制是「一页一任务 + 两跳上限 + 行内摘要」，不靠搜索、不靠折叠。**

### 一级导航（源码实证）

8 个扁平页面：首页、代理、订阅、连接、规则、日志、**测试（媒体解锁）**、设置（`src/pages/_navigation-meta.ts`）。左侧竖栏，可折叠、可拖拽重排（需右键「解锁菜单排序」）。

值得注意：**媒体解锁检测占了一个一级导航位**——低频诊断挤占高频导航，是「功能面宽」压缩「简洁」的直接证据。

### 首页（源码实证）

可自选卡片网格，**9 种卡片**，默认开启 8 张（`src/pages/home.tsx`）。卡片各自独立：当前代理、Clash 模式、网络设置、流量统计、网站测试、IP 信息、Clash 信息、系统信息、订阅。

当前代理卡支持组/节点下拉、延迟七档分级、固定节点图钉、测速。

### 设置页结构（源码实证，本轮重点核实）

| 维度 | 事实 |
|---|---|
| 分类 | 4 张卡片（系统 / Clash / Verge 基础 / Verge 高级），2×2 平铺 |
| 顶层行数 | 系统 2（报告计 4 行含嵌套）、Clash 12、基础 10、高级 11 |
| 子对话框 | 11+ 个，合计约 100+ 可调项 |
| 搜索 | **无**（`src/components/setting/` 全目录无 `SearchBox`） |
| 折叠 | **无**（`setting-comp.tsx` 仅 `List` + `ListSubheader` + `ListItem`） |
| 分类页签 | 无（四卡同时展开） |

**这是它最大的可用性缺口。** 找「统一延迟」需要记得它在第二张卡第 4 行。

### 它靠什么不混乱

1. 一页一任务：规则页只读、连接页只观测、设置页只管偏好。
2. **两跳上限**：一行标题 + 当前值/开关 → 对话框。永不展开第三层。
3. **行内摘要**：端口行显示当前端口，内核行显示版本号，不点进去就能看到关键事实。
4. 可配置首页：默认少，用户自己加。
5. 统一页内工具条：搜索（大小写/整词/正则）、过滤、排序、测速，各列表页同构。
6. 双模编辑器：所有结构化编辑都有「可视化 ⇄ 高级 YAML」。

### 它没有用（同样是事实）

- 无全局搜索、无命令面板
- 设置无搜索、无折叠
- 没有把 TUN/DNS 藏起来——反而首页和设置首屏都有

### 已知缺陷（来自其自带 changelog，可视为「确有人报过」）

宽窗口下订阅卡过多导致名称截断（2.5.8 修）；搜索框输入不完整正则崩溃；读屏软件误报侧栏为不可用控件；首页内核启动慢导致布局跳动。

## 二、Shadowrocket：状态先行 + 入口外迁

### 必须先说明的事实

**Shadowrocket 没有原生 macOS 版。** 官方元数据 `description` 为「for iPhone/iPad」，`supportedDevices` 中 Mac 以 `MacDesktop` 出现，属 Apple Silicon 的「Designed for iPad」窗口化运行。因此不存在「macOS 原生界面结构」，只有「iPad 界面 + macOS 菜单栏附加」。

唯一确凿的桌面专属能力（官方更新日志 2.2.92）：

> `feat(macos): add menu bar routing controls and quick server configurations for macOS`

即**菜单栏路由控制 + 菜单栏快捷切换服务器**。

### 简洁的五个机制

| 机制 | 表现 | 置信度 |
|---|---|---|
| 状态先行 | 首屏第一视觉元素是「是否连接」，非功能入口矩阵 | 中 |
| 单主路径 + 就地生效 | 选节点即生效，无「编辑—保存—应用」三段式 | 中（推断） |
| 功能分层而非删除 | 官方功能清单极长（HTTPS 解密、URL Rewrite、脚本、DoH/DoQ、Tailscale），首屏只出现一个动作 | 高（功能多）／中（首屏少） |
| 入口双轨 | 高频动作移到菜单栏，窗口只做配置 | **高** |
| 列表吸收复杂度 | 订阅/节点/规则都是「一行一条 + 行内状态」 | 中 |

**反证**：它在节点/规则很多时同样会变长，但没有用折叠或搜索解决——靠分层与入口迁移。启示是：**先决定什么不该出现在首屏，再考虑折叠**。

### 未找到可靠资料

设置项数量、分组数、键盘快捷键、原生多窗口支持。

## 三、交叉结论

两个产品用了**同一套机制**但侧重不同：

| 机制 | Clash Verge | Shadowrocket |
|---|---|---|
| 一页一任务 | ✅ 8 页严格分工 | ✅ 少量板块 |
| 两跳上限 | ✅ 设置行 → 对话框 | ✅ 列表 → 详情 |
| 行内摘要 | ✅ 端口/版本直接显示 | ✅ 延迟行内显示 |
| 就地生效 | ❌ 显式应用 | ✅ 无草稿 |
| 入口外迁 | 部分（托盘） | ✅ 菜单栏 |
| 搜索/折叠 | ❌ 都没有 | ❌ 都没有 |
| 可配置首页 | ✅ 9 卡任选 | ❌ |

**共同点：两者都**不**靠搜索或折叠解决复杂度，而靠「一页一任务 + 两跳上限 + 首屏裁剪」。**

## 四、对 U06 设计的校正

### 已被印证（不需要改）

- **P0「功能不删、位置重排」** —— 与两者实际做法一致。
- **P1「状态先于导航」** —— Shadowrocket 的核心机制。
- **删除首页六卡** —— Clash Verge 九卡在 840 宽下被自己修过截断，方向一致。
- **四级收纳 L0–L3** —— 与两跳上限同构，但需补精度。

### 需要补进设计的（本轮新增）

| 新增项 | 来源 | 落实位置 |
|---|---|---|
| **两跳上限**：任何设置项从所见页面到完成修改不超过两层 | 两个产品共有 | 新增原则 P12 |
| **行内摘要**：设置行必须显示当前值，而非只显示名称 | Clash Verge 实证 | 5.4 表单行 |
| **就地生效**：偏好与选择类动作不设草稿 | Shadowrocket + ADR 0044 | 已有，需强调 |
| **高频动作外迁**：托盘承担「把动作拿走」，而非第二套导航 | Shadowrocket 菜单栏 | 修正 5.9 托盘定位 |
| **可配置首页**：默认少量，其余可添加 | Clash Verge 实证 | 修正第 2.5 节「删六卡」为「默认收起 + 可选添加」 |
| **双模编辑器标配**：每类结构化编辑都能切 YAML | Clash Verge 实证 + 我们已有 `YamlFormEditor` | 5.4 / 编辑页 |

### 明确不采纳

| 不采纳 | 理由 |
|---|---|
| 设置页无搜索 | 这是 Clash Verge 最大的短板；我们已有 `SettingsSearch`，应保留并扩展到跨页 |
| 首页九卡默认全开 | 对 840×560 是灾难 |
| 媒体解锁占一级导航 | 低频诊断不应占顶级入口 |
| 设置 2×2 平铺不可折叠 | 我们的三分类页签在此点已更优，不回退 |
| 侧栏拖拽重排作为默认交互 | 可发现性陷阱，曾引发读屏缺陷 |
| CSS 注入 / 开发者工具平铺在普通设置 | 属高级/诊断 |
| 无版本管理的轻量配置 | 与我们的候选/运行/上次良好三分契约冲突，**必须比它更严格** |

## 五、对「简洁」的最终定义

综合两产品：

> 简洁不是功能少，也不是界面元素少。简洁是**每一屏只回答一个问题**，且**任何能力最多两跳可达**。首屏裁剪决定观感，两跳上限决定可发现性，两者缺一不可。

Clash Verge 做到了前者的一半（一页一任务）但没做两跳上限的减法（37 行 + 100 子项无检索）；Shadowrocket 做到了两者但功能面窄。**Mlash 的目标是：Clash 的功能广度 + Shadowrocket 的首屏裁剪 + 比两者都好的检索（设置搜索）。**
