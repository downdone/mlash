# R5 施工记录：连接 / 日志 / 规则的十态

> 归属：[界面分层设计](ui-layered-design.md#实施切片) 的 R5 片，规格见 [状态呈现规格](ui-layered-design.md#状态呈现规格)。

## 1. 实施前审计

三页逐态核对（改动前）：连接 4 态齐全、3 态部分、3 态缺失；日志 1 态（暂停）部分、其余 8 态全缺，所有非成功情形都表现为**空白文本面板**；规则两区各有 4–5 态，其中「内核实际规则」把**读取失败**渲染成「暂未读取到匹配的内核规则」——把错误说成了"没有匹配"。

## 2. 实施内容

### 2.1 内核实际规则

`AppController` 增加 `rulesError()` 与 `rulesLoaded()`。页面据此区分五种结论：

| 条件 | 文案 |
|---|---|
| 未就绪 | 内核未就绪 |
| 读取失败 | 读取内核规则失败：<原因>（动作「重试」） |
| 尚未返回 | 正在读取内核规则… |
| 已就绪但为零 | 内核已就绪，当前没有规则 |
| 有数据但被过滤空 | 没有匹配的内核规则 / 请调整检索条件（动作「清除检索」） |

读取失败**不再清空表格**：保留上一次成功的行，并在空态/状态行动作上给重试。

### 2.2 日志页

新增 `logEmptyState` 叠加说明，区分「内核未就绪」「没有匹配的日志」「已暂停」「还没有日志」，不再用空白面板表达非成功状态。

### 2.3 连接页

- 刷新失败时**保留上一份快照**并置 `connectionStale_`，不再 `connectionSession_.invalidate(); connections_={};`。
- `connectionsCurrent()` 排除过期快照；新增 `connectionsStale()`。
- 状态行区分「已暂停 / 正在恢复… / 刷新失败 · 显示上次快照 / 采样失败」。
- 空态文案区分：失败（附"下方保留上次快照"）、未就绪、无匹配、已就绪但无已结束连接、暂停、正在读取、已就绪但无活动连接。

## 3. 验收点与结果

| 验收点 | 结果 |
|---|---|
| 十态在三页各自可区分 | 已实施（外部管理/未确认 不适用：这三页没有外部接管语义） |
| 失败不清空已加载数据 | 已实施（连接、内核实际规则） |
| 时间戳与过期标注 | 连接状态行区分快照时间与失败；日志行前缀自带时间 |
| 新增测试 | `ConnectionViewTests::logAndRuleRegionsDistinguishStates` |
| 完整 ctest | 34 项中 33 通过、0 失败、1 跳过 |

**一处契约变更**：`connectionsCurrent()` 的含义收紧为「最近一次刷新成功」。`ConnectionViewTests` 中原本断言"失败后列表为空"的用例已按新契约改为断言"保留一份快照 + stale 标记"。

**未验**：真实内核下的连接/规则刷新、读屏状态播报。
