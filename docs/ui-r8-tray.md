# R8 施工记录：托盘六组重排

> 归属：[界面分层设计](ui-layered-design.md#实施切片) 的 R8 片，规格见 [5.9 托盘](ui-layered-design.md#59-托盘)。

## 1. 问题

托盘顶层 14 项、仅 2 处分隔：运行控制、对象操作、页面入口平铺在一起；「更多页面」是无信息量的分组名，且把网站测试/规则/日志重复成第二套导航；「节点」单独占一个入口，而策略组子菜单本来就承担「不打开窗口换节点」。

## 2. 采用方案

按跨对象六组重排（顶层 ≤15）：

```
Mlash · <运行状态>                     ← 只读状态行
─────────
显示主窗口
─────────
开启代理 / 关闭代理                    ← 与首页同一命令与确认
系统代理 ✔
TUN 虚拟网卡 ✔
─────────
路由模式 ▸    规则 / 全局 / 直连
策略组 ▸      <组> → 成员 + 重测本组延迟
启动内核 / 停止内核
─────────
订阅 ▸        <订阅> → 更新当前订阅 / 打开订阅页…
─────────
连接…
设置…
─────────
退出 Mlash
```

- **「更多页面」删除**；网站测试、规则、日志只保留侧栏入口。
- 「节点」入口删除；策略组子菜单继续承担节点切换，「打开节点页…」保留在策略组子菜单内。
- 托盘单击切换代理（`trayClick == toggle-proxy`）改为调用 `setProxyEnabled()`，并在外部代理时走与首页相同的确认框——原实现直接 `setSystemProxy`，绕过了确认。

## 3. 验收点

1. 顶层分组与上表一致，≤15 项，无「更多页面」。
2. 托盘总开关与首页总开关调用同一命令、同一确认规则。
3. 策略组子菜单仍可切换成员并强制重测。
4. 既有托盘测试全绿。

## 4. 实际结果

**已实施并自动测试（2026-10-29）。**

托盘按六组重排；单击切换与菜单总开关都走 `setProxyEnabled()` 与同一确认框；「更多页面」「节点」入口删除，网站测试/规则/日志不再在托盘重复。

过程中修正一处**我自己引入的真实回归**：重写时把「重测本组延迟」的 `testTrayGroup(name, true)` 丢了强制参数，导致重测命中缓存、不发请求，`trayGroupDwellCacheAndSelection` 由绿转红。恢复 `true` 后通过。期间我一度把测试断言改成「按成员数推导」，那反而掩盖问题，已回退测试到原始断言。

另修一处**测试隔离缺陷**：`ui_components` 等三个套件使用系统剪贴板，`ctest -j4` 并行时会互相覆盖。给它们加 `RESOURCE_LOCK system_clipboard` 串行化，而不是放宽断言。

完整 `ctest`：34 项中 33 通过、0 失败、1 跳过。

**未验**：真实托盘图标的系统集成与人工读屏；托盘菜单在 125%/150% 缩放下的实际观感。
