# R6 施工记录：工具窗口生命周期

> 归属：[界面分层设计](ui-layered-design.md#实施切片) 的 R6 片，契约见 [工具窗口骨架](ui-layered-design.md#工具窗口骨架)。

## 1. 问题

`DialogDraftGuard` 在 `QEvent::Close` 上无条件询问"关闭会放弃修改，是否继续"。设计契约与之相反：

| 动作 | 行为 |
|---|---|
| 窗口「关闭」 | 放弃未提交编辑并直接关闭，**不询问** |
| 「取消」/Esc | 有改动时**先询问** |

同一窗口不得同时出现「关闭」与「取消」。现状是两者混用同一套询问逻辑。

## 2. 实施内容

`DialogDraftGuard` 的事件过滤改为只拦 **Esc 键** 与 **`QDialogButtonBox` 取消按钮**，`Close` 直接放行（窗口关闭静默丢弃草稿）。新增 `confirmDiscard()` 供"取消"语义使用；`pending_` 为真时忽略取消，由写事务安全结束。

长流程窗口（备份、恢复、Geo、批量更新）关闭窗口**不中止任务**——任务由 `AppController` 持有，窗口销毁不影响。这一点原本即成立，本次用测试固定下来，避免以后被"关窗即取消"的直觉改坏。

标题格式逐窗核对，仅修正一处：`协议关联` 对话框标题 `Mlash链接导入`（缺分隔、且描述的是动作不是对象）改为「链接导入 · 程序关联」。

## 3. 验收点与结果

| 验收点 | 结果 |
|---|---|
| 关窗不询问、取消/Esc 询问 | 已实施，`WorkflowDepthTests` 按新契约改写并通过 |
| 同一窗口不同时出现「关闭」与「取消」 | 复核现有窗口均只保留其一 |
| 长流程关窗不中止任务 | 新增 `BackupTests::closingTheWindowDoesNotAbortTheTask` 固定 |
| 完整 ctest | 34 项中 33 通过、0 失败、1 跳过 |

**未验**：21 个对话框类的标题逐个人工观感复核；真实模态/非模态层级与读屏顺序。
